# 教学微课 Skill

> 给生成教学微课的模型使用。目标不是“总结资料”，而是把资料变成一套老师能直接投屏讲课的课件。

## 1. 输出目标

根据一份用户资料，生成一套 **5–12 页**的教学课件。课件要满足：

- 有明确的课程导入：这堂课解决什么问题、学完能做什么
- 每页只讲一个知识点，标题短、观点清楚
- 用「定义 → 解释 → 例子/对比 → 易错点」组织内容
- 最后一页做课堂小结，给出可执行的复习动作
- 只使用资料中出现的概念和事实；资料没有的内容，不要补写成事实
- 语言像老师讲课，不要写成百科条目或营销文案

## 2. 推荐课堂结构

1. 课程导入：标题 + 3 个学习目标
2. 核心概念：一句话定义 + 2–3 个关键词
3. 展开讲解：按资料章节拆成 2–5 页
4. 例子 / 对比 / 易错点：至少 1 页
5. 课堂小结：3 条必须记住的结论
6. 课后动作：复习哪几页、做哪类练习

## 3. 每页内容要求

每页包含：

- `layout`：`cover` / `content` / `image` / `chart` / `table` / `quote` / `summary`
- `eyebrow`：环节标签，例如「课程导入」「核心概念」「易错点」「课堂小结」
- `title`：不超过 20 个汉字
- `bullets`：2–5 条，每条不超过 60 个汉字
- `note`：可选的课堂提示，例如「可以提问：你身边有哪些系统属于智能体？」

不要在一页里塞超过 5 条要点；不要用长段落。

### 图表、表格和图片

- 资料有图片 URL 时，优先用 `layout: "image"`，`image.url` 只能使用资料提供的 URL
- 至少设计 1 页 `chart` 或 `table`，不要整套课件全是文字
- 图表用 `chart: {type:"bar", title, labels, values, unit}`；表格用 `table: {headers, rows}`
- 图片要有说明文字 `image.caption`，并和相邻知识点对应

## 4. 视觉与排版要求（生成 HTML 时）

- 默认 16:9 横屏、浅色背景、深色正文、蓝色强调；但**用户明确要求颜色或主题时必须覆盖默认值**
- 用户说「第一页红色」「整体改深色」「换紫色」等，必须写入 `theme` 或对应页的 `accent` / `background` / `text`，不能只改文案
- 每页内容页留白充足；标题大、正文留行距
- 使用 `.slide` 作为每一页，只有当前页有 `.active`
- 每个 `<section>` 必须带 `data-page-index="页码"` 和 `data-page-title="页标题"`，便于前端逐页解析和渐进式动画
- 页面结构固定为 `<section class="slide" data-page-index="1" data-page-title="标题">...</section>`
- 页面底部显示页码与课件名
- 提供「上一页 / 下一页 / 全屏」控制
- 禁止依赖外部 CDN；CSS 与 JS 全部内联，离线也能演示
- 不要使用过多颜色；一页最多一个强调色，但必须响应用户指定的主色
- 中文优先使用系统字体：`"Microsoft YaHei", "PingFang SC", sans-serif`

### 主题与自定义样式字段

课件 JSON 可选 `theme`：

```json
{
  "accent": "#2563eb",
  "background": "#ffffff",
  "text": "#111827",
  "muted": "#6b7280",
  "soft": "#f8fafc",
  "customCss": "可选，少量 CSS 动画/视觉覆盖，不允许 script"
}
```

每页还可以带 `accent`、`background`、`text`，用于单页视觉覆盖；只有用户明确要求时才使用，不要无理由给每页换色。

### 动效规范（低调、克制）

- 页面切换使用淡入 + 8–12px 上移，时长 350–450ms，缓动 `ease-out`
- 同一页的元素做 40–80ms 的轻微错峰，不要同时弹跳
- 只允许淡入、淡出、轻微上移、轻微缩放；禁止霓虹、闪烁、弹簧、3D 翻转和夸张视差
- 图表和图片比标题晚 80–120ms 出现
- 必须支持 `prefers-reduced-motion: reduce`，在该模式下关闭所有动画
- 演示交互必须支持鼠标滚轮翻页，并提供键盘方向键和全屏按钮

## 5. 后端约定的结构化 JSON

当后端要求 JSON 时，严格返回：

```json
{
  "title": "课件标题",
  "subtitle": "副标题",
  "slides": [
    {
      "layout": "content",
      "eyebrow": "课程导入",
      "title": "走进智能体",
      "bullets": ["智能体能感知环境", "它能自主采取行动", "本课学习定义、组成与评估"],
      "note": "可以提问：你身边有哪些系统属于智能体？"
    },
    {
      "layout": "image",
      "eyebrow": "结构图",
      "title": "智能体的核心闭环",
      "bullets": ["感知、决策、行动、反馈"],
      "image": {"url": "资料里的图片 URL", "caption": "智能体架构图"}
    },
    {
      "layout": "chart",
      "eyebrow": "能力对比",
      "title": "四种能力的重要度",
      "chart": {"type": "bar", "title": "能力重要度", "labels": ["感知", "规划", "行动", "记忆"], "values": [80, 95, 90, 70], "unit": "%"}
    }
  ]
}
```

不要在 JSON 外包裹 Markdown 代码围栏，不要添加解释文字。

## 6. 质量检查

生成前自查：

- 是否每一页都能在 10 秒内读完？
- 是否每页只有一个中心观点？
- 是否有资料原文没有的事实？
- 标题是否像老师会说的话，而不是章节编号？
- 最后一页是否告诉学生下一步做什么？

## 7. 参考 HTML 模板

`micro_course_template.html` 是本项目使用的视觉基准：16:9、浅色、蓝强调、底部翻页控件。生成 HTML 时优先复用它的布局和 CSS 变量，只替换标题、要点与页码。

`micro_course_sample.html` 是一份真实生成的教学课件样例（含图片、表格、图表和 AI 讲解），可以作为完整的参考实现。
