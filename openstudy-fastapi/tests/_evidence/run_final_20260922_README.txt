## 混流的原因（事实，不美化）
最终那次 gated 跑我用了「采样 + 跑批」的组合命令，**它返回的输出是空的**（工具侧丢了 stdout），
我无法判断这条命令是否已经把套件启起来 → 于是又起了一次。
结果第二次那一次被**单实例锁**挡住（锁就是为这个场景写的）：

- 日志 **第 1-6 行** 属于**没有跑**的那一次：
  `START 16:56:54` / 三条 `[LOCK] …已有一个实例在跑（锁龄 10s）…持有者：pid=25760 started=16:56:45`
  / `EXIT=2` / `END 16:56:55`
  → **exit 2 = 没跑**：不碰 DB、不写产物、不动 sidecar（脚本的约定，见 `acquire_lock`）。
- **第 7 行之后**属于**真正产出产物**的那一次（锁持有者 pid=25760）：
  运行窗口 `16:56:45 → 16:57:23`，`153/153 通过`，`EXIT=0`。
  它的 shell 首行 `START …` 被第二次调用的 `>` 截断覆盖了（所以文件里看不到它的 START），
  而它的 Python 输出因为块缓冲在后面才落盘 —— 这就是两份流交错的原因。
