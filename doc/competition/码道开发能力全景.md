## 0. 一句话定位

**码道不是补全插件，是一个能自己读仓库、改代码、跑命令、写测试、做审查、提交代码的编码智能体。**
我们把它当同事用：人负责"对不对"，它负责"快不快、全不全"。

## 2. 完整流程（8 步，可直接照着走）

> 主线用当前真实分支 `feat/codearts-iteration` 上的 `html_sanitize` 改动。

### 第 1 步 · 接入与选模式
- `/agents` 展示 build / plan / docgen，说明"改代码用 build，只分析用 plan"。
- 确认仓库与分支：`git status -sb`、`git log --oneline -1`。
- **产出**：分支状态截图。

### 第 2 步 · 读懂代码（先读后写）
```
先用 CodeSemanticSearch 找 html_sanitize 的实现与调用方；再用 grep 确认 sanitize_note_html 在哪些路由使用。
```
- 也可 `/codebase-local/index` 建本地索引，再 `/codebase-local/status` 看进度。
- **产出**：定位结果（文件:行号）+ 索引状态。

### 第 3 步 · 规划
```
把这个需求拆成可执行步骤，写进 todo：定位 → 补测试 → 跑测试 → 修复缺陷 → 回归 → 提交。
```
- `todowrite` 生成勾选清单。
- **产出**：任务清单截图。

### 第 4 步 · 写测试（不碰业务代码）
```
使用单元测试技能（developer-test-agent），为 app/utils/html_sanitize.py 生成 pytest 用例，
覆盖 script / on* / javascript: / data: / 正常保留 / 超长输入，并覆盖 nh3 缺失的正则降级分支；
只新增 tests/test_html_sanitize.py，不改业务代码；生成后运行 pytest 贴结果。
```
- **产出**：`tests/test_html_sanitize.py` + `57 passed, 1 xfailed`（发现真实缺陷）。

### 第 5 步 · 分支差异 + 审查
- `/dt/git-branch`：对比 `main` 与 `feat/codearts-iteration`，看变更与 UT 覆盖。
- 再发：
```
只读审查，不要修改文件。基于分支差异按 P0/P1/P2 输出问题，给 file:line 与建议。
重点：正则回溯风险、降级与 nh3 是否一致、测试是否覆盖修复点、未加引号的 src=javascript: 是否漏。
```
- 需要更强安全审查时：`用 security_audit 工具审查当前分支相对 main 的改动`。
- **产出**：分支差异分析 + 审查结论。

### 第 6 步 · 修复缺陷
```
/bugfix
bug 描述：app/utils/html_sanitize.py 的 _JS_URL_RE 里 data:text/html 分支后又要求一个冒号，
导致 data:text/html;base64,... 漏检。修复为覆盖 javascript/vbscript/data，并把对应 xfail 改成正常断言。
```
- 修复后回归：`python3 -m pytest tests/test_html_sanitize.py -q` → `58 passed`。
- **产出**：修复 diff + 58 passed。

### 第 7 步 · 提交
```bash
git add openstudy-fastapi/app/utils/html_sanitize.py openstudy-fastapi/tests/test_html_sanitize.py
git commit -m "fix: 修复降级正则对 data: 协议的漏检"
git push origin feat/codearts-iteration
```
- **产出**：commit + 远程分支链接。

### 第 8 步 · 沉淀
- `/codebase-knowledge/init`：生成代码库知识文档。
- `/experience/enable` + `/experience/reflect/enable`：开启经验收集与复盘。
- `/export`：导出本次会话。
- **产出**：知识文档 + 经验条目 + 会话文件。

## 4. 一个真实案例（PPT P7 用这个）

**主题：一个安全缺陷，从"测试发现"到"审查 → 修复 → 回归"**

| 时间点 | 发生了什么 | 结果 |
|---|---|---|
| T1 | 让码道用 developer-test-agent 写单测 | 新增 `test_html_sanitize.py`，57 passed / 1 xfailed |
| T2 | xfail 暴露真实缺陷 | 降级正则漏检 `data:text/html;base64,...` |
| T3 | `/dt/git-branch` + 只读审查 | 确认缺陷位置 `html_sanitize.py:79` |
| T4 | `/bugfix` 修复 | 协议分支改为 `javascript/vbscript/data` |
| T5 | 回归 | **58 passed** |
| T6 | 提交推送 | commit + `feat/codearts-iteration` |

**一句话讲法**：不是"AI 帮我写代码"，而是"AI 自己写测试、自己发现问题、被审查后自己修好、再自己验证通过"。

## 5. PPT 三页文案建议（说人话，每页 ≤150 字）

**P6 · 怎么用码道**
> 我们把码道当同事，不当魔法。固定六步：需求进对话 → 先读代码 → 拆成计划 → 改完自测 → 审查 → 规范提交。
> 它不只会写，还会读仓库、跑命令、写测试、做审查、提代码。

**P7 · 一个真实案例**
> 一个安全缺陷：AI 先写单测，测出一个真实漏洞；分支差异分析确认位置；修复专家改好；回归 58 项全过。
> 全程会话、命令、提交都可查。

**P8 · 沉淀**
> 每次做完不是结束：代码库知识自动生成，经验自动复盘，常用流程固化成技能，会话可导出。

## 7. TUI 与 IDE 的能力差异（避免讲错）

| 能力 | 在线 TUI（当前） | IDE / Space（AgentTeam） |
|---|---|---|
| code-reviewer + `review.json` | ❌ 没有 | ✅ 有 |
| plan 模式 | ❌ 当前权限禁止进入 | ✅ 可切 |
| 团队模式 / 多 agent 并行 | ❌ 不支持 | ✅ AgentTeam |
| 内置浏览器走查 | ❌ 无浏览器工具 | ✅ 有 |
| PostgreSQL MCP | ❌ 未配置 | ✅ 可加 |
| 单元测试 / 修复 / 分支差异 / 索引 / 经验 | ✅ 有 | ✅ 有 |

> 对外只说**当前环境真实做过的事**；IDE 才有的能力，等真在 IDE 里做了再讲。
