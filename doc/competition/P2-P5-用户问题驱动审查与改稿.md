> 审查对象：`doc/competition/OpenStudy-10页-码道版.pptx`（2026-11-15 17:39 生成，`build_ppt_v4.py`）
> 页码口径：按幻灯片实际页码。当前页序：P2 用户与问题 → P3 资料诊疗室 → P4 知识百科×知识图谱 → P5 规划建议 → P6 资料到题库。

## 0. 一句话结论

**P2 是全篇唯一有真实资料细节的页，但它一次讲了三个痛点；P3–P5 又退回“功能名 + 功能目录 + 指标”；真正回答 P2 的 P6 题库页排在了后面，P9 现场演示也没有演示题库。整份 PPT 现在是“一个人开场，然后产品自己介绍自己”。**

## 一、P2–P5 哪些表述是“假大空/功能目录”（逐条）

### P2 用户与问题（幻灯片第 2 页，`build_ppt_v4.py:259-281`）

> 总体判断：这是全篇最接近真实用户的一页。问题不是“没有用户”，而是**把同一个故障拆成了三个并列痛点**，三张卡片权重相同，评委记不住哪一个才是核心。

1. **「不是资料不够，是资料回不到题上」——假大空（金句式判断，方向对但缺具体对象）。**
   前半句在否定一个用户没说的判断，后半句“回不到题上”没有具体对象。读起来顺，但信息量低。
   → 改成：**「高数 Word 导进题库：公式乱码、图题分家，一晚上一道题没刷成」**。

2. **「以一个理工科备考者为样本」——假大空（研究语言）。**
   “样本”把人变成研究对象，用户不会说“我是一个样本”。
   → 改成：**「小林，理工科备考，高数讲义、真题、错题笔记都在电脑里」**。

3. **「一份带公式和插图的资料，看起来完整，却很难直接变成练习」——假大空（只有判断，没有动作和损失）。**
   “看起来完整”“很难直接”都是判断，没有具体动作、具体损失。
   → 改成：**「周六晚上，他把第三章 Word 导进题库，想先刷二重积分」**。

4. **「一个典型场景」——模板词（功能目录式标签）。**
   四个字没有任何信息，删掉即可。要具体就写“周六 20:10，宿舍”。

5. **「理工科备考者：资料看起来完整，题却做不起来」——假大空（身份 + 判断）。**
   这是“身份 + 判断”，不是“人 + 动作”。“题却做不起来”也太笼统，评委无法在脑子里看到画面。
   → 改成：**「他导入第三章的题：公式一渲染就乱，区域图还留在原文里」**。

6. **三张卡片「01 公式进题库变乱码 / 02 图片和题目分家 / 03 题目找不到知识点」——痛点罗列（三个并列症状，效果等同功能目录）。**
   这是同一个故障的三个后果，不是三个独立痛点；并列之后 P2 失去焦点。尤其 03 是 01+02 的下游结果，不应和它们平起平坐。
   → 改成一条因果链：**Word 公式丢结构 → 区域图与题干分家 → 题对不上知识点 → 这道题刷不了**。P2 只讲“变不成能刷的题”这一件事。

7. **「题目就少了一半信息」——假大空（夸张）。**
   “一半”没有依据；用户的真实感受是“图看不到，题没法做”。
   → 改成：**「区域图看不到，这道二重积分题根本没法下手」**。

8. **「下一次仍然从零开始」——假大空。**
   无法验证，也没有具体损失。
   → 改成：**「错题本里只有题干，翻不回讲义第 3 章第 2 节」**。

9. **「资料存着，学习动作没有发生。」——假大空（咨询金句）。**
   像总结报告，不像当事人；"学习动作"是抽象词。
   → 改成：**「一晚上过去，一道题没刷成。」**

> 可保留：Word 源文件、二重积分公式、区域图、题源 #693 / 第 2294 段——这些是真实证据。P2 要改的是“组织方式”，不是把细节删掉。

### P3 资料诊疗室（幻灯片第 3 页，`build_ppt_v4.py:327-353`）

> 总体判断：数据是真的，但这一页讲的是“系统有四个模块”，不是“用户拿它能决定什么”。

1. **「同一份资料只有一个入口：体检、原文阅读、智能报告都在同一间诊疗室完成。」——功能目录。**
   三个功能名并列；“一个入口”是产品内部效率，不是用户的问题。用户不会为了“一个入口”来用产品。
   → 改成：**「这份资料能不能直接拿来复习？缺的章节会不会白刷？」**

2. **「先看问题，再决定怎么整理」——假大空。**
   正确的废话，任何整理工具都能说。
   → 改成：**「27 章里 25 章没有练习题——先补缺练习最多的 3 章」**。

3. **「四维体检：结构 90 · 图文 100 · 知识 63 · 可学习 48」——功能目录 + 指标自嗨。**
   用户不知道 63/48 代表什么，也不能据此行动。分数可以留，但必须翻译成“能不能刷”。
   → 改成：**「这章有没有题可刷、图能不能看清、知识点覆盖几节」**；分数缩小成证据。

4. **「问题清单：2 项待处理：25 章缺练习 / 10 章内容过薄」——功能目录（“待处理”是系统口径）。**
   信息其实具体，但用系统语言，缺“所以呢”。
   → 改成：**「25 个章节一道练习题都没有，10 个章节只有标题没有内容——这份资料不能直接刷」**。

5. **「章节覆盖：热力图区分讲解、练习与内容过薄」——功能目录。**
   在讲图怎么画，不在讲用户看到什么。
   → 改成：**「哪几章有讲没练，一眼看到」**。

6. **「智能报告：把问题转成整理目标、改进项和下一步」——假大空（三连词）。**
   “目标 / 改进项 / 下一步”是模板词，没有具体内容。
   → 改成：**「报告只说三件事：先补哪章、补什么、补完拿哪几题验证」**。

7. **「综合分 75 · 基本可用」——假大空（评分）。**
   “基本可用”没有标准，75 和“基本可用”的关系也不清楚。
   → 改成：**「75 分：能读，但 25 章没题，不适合直接刷」**。

8. **「原文是事实来源，AI 只做整理和解释」——假大空（原则句）。**
   正确，但用户不关心；这是技术页的内容。
   → 删除，或移到 P7 技术页。

9. **「体检 → 读原文 → 智能报告：一个入口完成，不用在三个功能间来回找。」——功能目录。**
   把三个模块串成流程，仍然是功能视角；“来回找”是产品自己的问题。
   → 改成：**「先看体检报告，点问题直接跳到那一章原文」**。

10. **「综合分、问题清单和章节热力图，最终都落到可执行的整理动作。」——假大空。**
    “可执行的整理动作”什么也没说。
   → 改成：**「今天先补第 3 章的 10 道题，明天再补第 5 章」**。

### P4 知识百科 × 知识图谱（幻灯片第 4 页，`build_ppt_v4.py:356-379`）

> 总体判断：这一页全是“图谱怎么设计”，没有“用户拿它找什么”。

1. **「知识百科 × 知识图谱：节点有类型，来源有落点」——内部视角 / 功能目录。**
   “节点 / 类型 / 落点”是图论和实现词；用户只问“这题考哪、原文在哪”。
   → 改成：**「这道题考的是哪一节？原文在第几段？」**

2. **「主题页按概念/方法/综合分色；点开节点，来源、相关题目和原文都能继续追。」——功能目录。**
   颜色分类、点击、三类结果，全是功能点，没有用户动作。
   → 改成：**「做错一道二重积分，点一下「二重积分」，就能看到定义、相关题和讲义原文」**。

3. **「主题详情：1 条来源 · 8 个出链 · 19 个反链」——内部指标。**
   “出链 / 反链”用户不懂，数量也不代表用户价值。
   → 改成：**「这个知识点在 1 份资料里出现，连着 8 个相关概念、19 条关联」**。

4. **「五类来源：题库 / 资料 / 网页 / 笔记 / 图片 → 归并成知识主题」——功能目录 / 架构图。**
   五类来源是系统数据源清单，不是用户问题；“归并”是内部动作。
   → 改成：**「不管题、讲义、网页还是笔记，只要提到「二重积分」，都会出现在同一个主题下」**。

5. **「知识百科：主题页有来源、版本、出链与反链；点来源回到原文。」——功能目录。**
   版本 / 出链 / 反链堆术语，用户无法感知。
   → 改成：**「主题页能看：这个概念从哪来、哪道题考过、原文在哪一段」**。

6. **「知识图谱：首层只画知识主题；详情里展开来源、相关题目和相邻关系。」——内部视角。**
   “首层只画……”是设计说明，不是用户收益。
   → 改成：**「先看概念之间的关系，点开一个概念再看具体题目和原文」**。

7. **「知识百科」「知识图谱」作为两个并列产品模块——功能目录。**
   两个功能名并列，暗示“两个东西”；用户只需要一个“从题目找知识点”的入口，图谱只是视图。
   → 合并成一页：**「题目 → 知识点 → 原文」**，图谱作为“看关系”的视图出现。

### P5 规划建议（幻灯片第 5 页，`build_ppt_v4.py:382-406`）

> 总体判断：这一页最像“产品说明书”，四个小标题全部是功能名，用户的问题没有出现。

1. **「规划建议：把下一步拆成每天能做的动作」——假大空。**
   “规划建议 / 下一步 / 动作”都是抽象词；没有时间、科目、题量。
   → 改成：**「接下来 7 天，每天先看哪段、做哪 5 题」**。

2. **「不是让模型凭空写计划：先看资料和题库证据，再按天拆成精读、练习、复习。」——假大空（防御式）。**
   “不是让模型……”是产品自辩；“证据”是术语；“精读 / 练习 / 复习”是方法清单。
   → 改成：**「计划按你实际做错的题和资料缺口排，不用你填模板」**。

3. **「真实界面：概率论 7 天学习处方，按天拆到精读 / 练习 / 复习」——功能目录（“学习处方”是产品命名）。**
   用户说的是“计划”，不是“处方”；“精读 / 练习 / 复习”仍是分类。
   → 改成：**「真实界面：概率论 7 天计划，每天 30 分钟，先看哪段、再做哪几题」**。

4. **「建议从哪里来」——内部视角。**
   系统在解释自己的逻辑，不是用户的问题。
   → 改成：**「这份计划为什么这样排？」**

5. **「证据起点：从资料体检和题库薄弱点出发」——功能目录 / 术语。**
   “证据起点”是架构词；用户只关心“是不是按我的错题排的”。
   → 改成：**「先看你哪几章没做题、哪几个知识点错得多」**。

6. **「按天拆解：把薄弱章节拆成精读、练习、复习」——功能目录。**
   描述功能如何工作，不给用户可执行的一天。
   → 改成：**「每天 30 分钟：10 分钟看原文、15 分钟做题、5 分钟回看错题」**。

7. **「可回看：每项都能查看原文、回到练习」——功能目录。**
   “可回看”是功能名；用户要的是“点一下就能回到那段”。
   → 改成：**「点每一项，直接回到对应原文和题目」**。

8. **「不是任务清单：不强制打卡，只给下一步建议」——假大空（否定式定位）。**
   用户不关心你是不是任务清单；否定不能建立价值。
   → 改成：**「今天没做完，第二天从没掌握的那道题接着来」**。

9. **「建议不是任务清单；每条都能回到资料与题目。」——假大空（重复口号）。**
   同义反复，没有信息增量。
   → 改成：**「明晚 8 点打开，先做第 3 章 5 道二重积分题」**。

## 二、P2 应该只讲哪一个核心痛点

### 3 个候选与打分

> 评分口径：1–5 分；“普遍性”按**目标画像内**（长期整理资料、题库、笔记的理工科备考者）计算，不按全人群计算。

| 候选 | 一句话痛点 | 真实感 | 可演示性 | 普遍性 | 合计 |
|---|---|---|---|---|---|
| A 收藏型 | 网页、文档、图片收藏了一堆，做题或复习时找不到对应知识点和原文 | 5 | 2 | 5 | 12/15 |
| B 格式断裂型 | 高数 Word 里的公式和区域图，导入题库后公式丢结构、图片和题分家，题刷不了 | 5 | 5 | 4 | **14/15** |
| C 溯源断裂型 | 题做完了，却不知道它对应哪一节、哪段原文，错题回不到资料 | 4 | 4 | 5 | 13/15 |

**结论：P2 只讲 B。**

理由：
- **B 最有画面**：左边是 Word 里的公式和区域图，右边是题库/刷题页；评委 10 秒就能看懂“哪里坏了、修好了没有”。
- **B 最像这个用户的真事**：理工科的高数、线代、概率论资料天然带公式和图，这不是凭空造的需求。
- **B 能带出后面所有页**：公式和图片不丢 → 题目有题源 → 题目挂知识点 → 知识点连图谱 → 图谱给复习计划。P3–P6 是同一条链。
- **A 太泛**：如果 P2 讲“收藏了找不到”，会立刻被归类为“又一个 RAG / 知识库”，而且“找不到”很难在 30 秒内演出来。
- **C 太靠后**：它是 B 解决之后才会出现的下一个问题，适合放 P4/P5 做“顺藤摸瓜找原文”，不适合当 P2 的主痛点。

**关键改法：公式乱码、图题分家、知识点找不到不是三个痛点，而是同一个故障的三个后果。P2 用“一条因果链 + 一张对比图”，不要用三张并列卡片。**

P2 的统一说法：**「一份高数 Word，导进题库就散了：公式乱码、图题分家、题对不上知识点——刷不了，也回不到原文。」** 这是一件事的完整链条，不是三件事。

## 三、P2 最终用户画像文案

> 1 句身份 + 1 句真实动作 + 1 句损失；不含“赋能 / 闭环 / 资产化 / 证据链”。

**身份：** 我是理工科备考者，长期收集网页、文档、图片，也自己整理题库和错题笔记。

**真实动作：** 上周六晚上，我把《高数·综合练习（第三章）》Word 导进题库，想先把二重积分刷一遍。

**损失：** 公式全变成乱码，区域图还留在原文里，题目也对不上知识点——一晚上过去，一道题没刷成。

> PPT 标题可用：**「高数 Word 导进题库：公式乱码、图题分家，一晚上一道题没刷成」**。
> 额外提醒：全篇也别再用“知识资产 / 一站式 / 全链路 / 资料即题库”这类词；它们和“赋能/闭环”是同一类。

## 五、10 页以内的用户故事主线（不是功能清单）

> 一句话主线：**一个理工科备考者周六晚上想刷高数第三章；从一份导不进的 Word 开始，先把它变成能刷的题，再顺着题找回知识点和原文，最后知道接下来七天补哪几章。**

## 六、P2 可直接替换的页面文案（排版建议）

```
标题：高数 Word 导进题库，一晚上一道题没刷成
副标题：理工科备考者小林，周六晚上想刷第三章二重积分。

左侧：Word 原文件截图（公式 + 区域图）
右侧：一条横向因果链（不是三张卡片）
  公式丢结构  →  区域图与题干分家  →  题对不上知识点  →  这道题刷不了

底部一句：不是资料不够，是这份资料变不成能刷的题。
```

要点：**一页只留一个痛点、一个主人公、一个失败动作、一个损失。** 公式、图片、知识点都只作为“这条链上的证据”，不再各自单独成卡片。
