# P1 批次 2 任务提示词（剩余 P1）

- 目标日期：2026-11-03
- 范围：优先处理用户可见/数据可信的 P1，不一次性动全部 P2，避免回归面失控。
- 验收：每项真实 API/页面回归；`npm run build:prod` 通过；自动 review 后输出“已修复 / 剩余”。

## 目标提示词

### A. 我的学习
1. `/front/myQuestion` 根路径必须有明确落点（优先恢复上次子页，失败回退 `myBank`），不能白屏。
2. `myStats` 的 5 个统计请求不能因为一个失败导致整页空白：改用 allSettled/逐项容错，单接口失败时显示可用数据并有提示。
3. 错题统计区分“待消灭错题（active）”与“累计错题（含已掌握）”，页面上明确标注口径，避免同一页面出现互相矛盾的 75/90/125 三组数字无解释。

### B. 消息中心
1. `SysNotice.create_time` 模型加 `server_default=func.now()`；评论/回复/@ 通知写入时显式写当前时间；历史 NULL 时间回填。
2. 系统通知和分享通知未读数提供聚合接口（至少 `/system/notice/totalUnread`），前端顶栏红点统一用聚合值。
3. 分享通知删除/清空前必须 `ElMessageBox.confirm`；拉取失败显示错误，不静默假空态。
4. 通知列表按 `create_time DESC NULLS LAST` 排序。

### C. 学习分享
1. `GET /notes/note/public/{id}` 补作者昵称/头像，不再恒“匿名用户”。
2. `GET /notes/note/public/list` 只返回 `status='published'`，草稿不进入公开列表。
3. 详情页只保留一次浏览计数（移除前端重复 `recordClick`，保留服务端详情自增）；避免同一打开 +2。
4. `POST /notes/comment/create` 复用 `_get_note_checked`，私有笔记非作者不可评论。
5. `POST /favoriteNote/favoriteNote` 校验笔记存在/可见，唯一键冲突返回 400；收藏列表补 authorName/isFavorited。
6. 编辑发布必须发送 `status='published'`（新建发布路径），不再落成 draft。

### D. 后台管理
1. `/system/dashboard/stats`、`/recent` 加 `require_admin`。
2. `/ai/agent/configs` 保持登录用户自己的智能体（不误加 admin），但统一 `{code,msg,data}` 信封；前端适配 `data.agents`。
3. 不处理监控后端缺失/20+ 死路由（留作 P2 批次），在结果中明确标注。

## Review 提示词

- 读取 `P1批次2修复记录.md` 与 `git diff`；
- 对 A–D 跑真实 API/页面最小回归；
- 检查是否引入 P0 回归（会话、点赞、公告、RAG、个人隐私）；
- 输出 verdict、剩余 P1/P2、未验证项。
