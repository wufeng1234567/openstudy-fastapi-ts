# 闭环检测 - 题库练习

- 检查日期：2026-11-02
- 检查范围：`/front/questionPractice`（公开题库广场）→ 题库详情 → `/:bankId/practice/:moduleType`（顺序 / 随机 / 错题 / 模拟）
- 检查方式：两个子代理独立检查 + 主代理真实 API/数据库/页面复核
  - 后端子代理 A：`hy4-preview-f`
  - 前端子代理 B：`glm-5.3-flash`
- 主代理复核结论：**有条件通过（无 P0；P1 成绩持久化与判分可信度未闭环）**

## 一、结论摘要

题库练习的主链路可以真实走通：

- 题库广场能加载公开题库（实测 17 个公开题库）；
- 题库详情能显示题量/错题/收藏/斩题/笔记统计，并进入四种练习模式；
- 顺序练习能加载 10 题，选项作答、正确答案/解析展示、答题卡计数均正常（实测选中第 1 题 B 后显示“已答 1/10”及解析）；
- `POST /questionPractice/report` 真实写入 `user_practice_log`，答错会 upsert `user_question_error`；
- 学习统计 `totalPracticeCount` 随上报增加，删除测试流水后能回落；
- 私有题库对其他用户返回 403；收藏/斩题的重复提交有幂等提示。

但本轮不能判“完全闭环”：

1. **练习成绩没有服务端会话/成绩记录**：只有逐题流水，结算页是前端内存态；刷新/换设备后无法回看本次总分、逐题结果、用时。
2. **判分完全在前端**：题目接口把 `answer` / `analysis` 明文下发给未作答页面，`/questionPractice/report` 直接采信客户端 `isCorrect`，答案可看、正确率可伪造。
3. **简答题按字符串全等判分**：用户答“惯性定律的另一种说法”基本必判错并写入错题本，正确率与错题本会被污染。

因此该模块的定位是：**单次练习可用，练习结果与学习数据闭环不足**。

## 四、P1 问题

### P1-1：练习结果没有服务端持久化，刷新/换设备即丢

**现象**

- 后端模型只有 `question_bank`、`question_main`、`question_sub`、`user_bank_favorite`、`user_question_favorite`、`user_question_error`、`user_question_marked`、`user_practice_log`，**没有练习会话/成绩表**。
- `POST /questionPractice/report` 只写逐题流水（`questions.py:1132-1234`），返回 `{isCorrect, errorId}`，没有 total/score/sessionId。
- 前端结算状态 `showExamResult` 是组件 `ref`（`PracticeComponent.vue:763`）；`watch` 明确在结果态不写草稿（`:3122-3123`），刷新后结算层消失；mock 历史也只在 localStorage（`MockExamHistory.vue:111` 的注释自述）。

**用户影响**

- 练习提交后刷新页面，成绩/正确率/逐题解析全部丢失；换电脑或清缓存后历史成绩全无。
- 可以看错题本，但无法回答“我上次这套题得了多少分 / 哪类题一直错 / 我的成绩趋势”。

**建议**

- 新增 `user_practice_session`：`user_id / bank_id / module_type / start_time / end_time / total / correct / score / status`；
- 前端结算时 POST 一次，`questionPractice/report` 可附 `session_id`；
- 详情页/学习统计按 session 读取；mock 历史也迁到服务端。

### P1-2：答案随题下发、前端判分、后端不校验 `isCorrect`

**现象**

- `format_question()`（`questions.py:122-154`）在普通题目列表/练习接口中返回 `answer`、`questionAnswer`、`analysis`。
- `useQuestionPractice.ts:2093-2109` 用前端 `q.correctAnswer` 判分，然后 `reportPractice({isCorrect})`。
- `report_practice`（`questions.py:1132-1234`）只按 `payload.isCorrect` 写 `is_correct`，不按题目答案重算。
- 后端子代理实测：`GET /questionMain/questionMain/all?bankId=1300` 返回明文 answer；向 `/questionPractice/report` 提交错误 `isCorrect=true` 也被计入正确数。

**用户影响**

- 用户按 F12/抓包即可看到整套答案与解析，练习失去意义；
- 任意客户端都能刷“全对”，统计正确率/学习报告不可信；
- 这也是学习统计口径被污染的根因之一。

**建议**

- 练习加载新增 `withAnswer=false`（或独立 `practice/questions` 接口），只返回题干/选项；提交后再返回解析；
- `report` 服务端对客观题按 questionType 重新判分，主观题标记 `pending`；
- 模拟考试/正式考试必须走服务端判分。

### P1-3：简答题按字符串全等判分，几乎必然判错并污染错题本

- `useQuestionPractice.ts:2098-2099` 对 `fillblank`/`essay` 使用：
  `String(ans).trim().toLowerCase() === String(ca).trim().toLowerCase()`
- 简答题参考答案是自然语言，用户几乎不可能逐字相同；实际测试“惯性定律的另一种说法”被判错（errorId=460）。
- 后果：简答题正确率被严重低估，错题本被灌水，用户看到“我全错”。
- 建议：`essay` 不自动判分，显示“参考答案/待自评”，不写错题本；`fillblank` 可按空格/标点归一化后判分。

### P1-4：模拟考试结果不进入练习流水/错题本（代码审查）

- `PracticeComponent.vue:2238-2308` 的 `handleMockSubmit` 只做本地判分、`store.addMockExamRecord()`、`ExamSummary`，没有调用 `reportPractice`。
- 因此模拟考中的错题不会进入 `user_question_error`，正确率/练习次数也不会进入 `userStats`（除非另有未发现的后端接口）。
- 若产品口径是“模拟考试独立于日常练习”，可接受；否则应补交卷上报。当前至少会与用户“我做了模拟考但学习统计不变”的预期冲突，建议明确文案或补接口。

## 五、P2 问题

### P2-1：删除题库不级联 `user_practice_log`，孤儿流水永久计入统计

- `questions.py:801-865` 的 `delete_banks` 级联删除 QuestionSub/收藏/错题/斩题/笔记/分享/题目/题库，**没有删除 `UserPracticeLog`**。
- 后端子代理实测删除临时题库 1300 后，仍有 19 条 `user_practice_log` 残留；统计按 `user_id` 聚合，会把已删除题库的练习继续计入趋势/正确率。
- 建议：删除题库/删除题目时补 `delete(UserPracticeLog).where(question_id.in_(question_ids))`（日志表注释说“刻意不加 FK”，但清理策略仍应明确）。

### P2-2：`recordStudyTime` 统计口径失真 + 重复叠加

- `questions.py:1087-1129` 对传入的全部 `questionIds` 无条件 `review_count + 1`、`last_review_time = now`，不论是否真的作答；
- `useQuestionPractice.ts:1765` 传的是题库全部题目 id；同一次进入还可能再调用 `/favoriteBank/recordStudy/{bank_id}`，导致 `study_count` 一次进入 +2（后端实测）。
- 建议：只在实际作答时累加 `review_count`；`study_count` 只在一个入口累加。

### P2-3：阅读/完形题的 `answeredCount` 把空对象当已答

- `PracticeComponent.vue:1328`：`answeredCount = answers.filter(a => a !== null).length`。
- 阅读/完形初始 `answers` 为 `{}`（`useQuestionPractice.ts:929`），空对象不等于 null，会被计入已答；答题卡“已答 X/Y”“剩 N 题”和交卷未答提示会偏大。
- 建议：与 `buildDraftSnapshot` 的 `hasAnswer` 口径统一：对象需 `Object.keys(...).length > 0`，数组需 `length > 0`。

### P2-4：重复改单选答案会重复上报流水

- `PracticeComponent.vue:1489-1492` 每次重选单选/判断都调 `handleAnswerSubmission`，`reportQuestionPractice` 无 per-question 去重；前端只有 100ms `submissionLock`（`useQuestionPractice.ts:2007-2012`）。
- 后果：用户改几次答案就多几条学习记录，正确率/练习次数虚增；后端并发重复提交实测 10 次全部落库，无幂等。
- 建议：同一题同一波去重，或服务端按 `(user_id, question_id, submit_token)` 唯一约束。

### P2-5：`reportPractice` 失败静默，学习数据缺报无提示

- `useQuestionPractice.ts:117-140` 的 `catch` 完全吞掉异常；网络失败/后端 500 时用户仍看到正常作答，但流水丢失。
- 建议：失败时轻提示并提供一次重试；后端记录可观测指标。

### P2-6：题库练习入口会被 `lastVisited` 重定向到旧练习页

- `questionPractice/index.vue:32-57` 进入模块会按 `frontPageCache.lastVisited` 重定向；`practice.vue:53-56` 离开时把 `lastVisited` 设置为当前 `bankId`，导致用户从侧栏点“题库练习”时直接回到旧题库详情/练习，而不是题库列表。
- 前端子代理实测：SPA 存活时从 hash 进入 `#/front/questionPractice`，数秒后被 replace 到 `#/front/questionPractice/1299/practice/sequential`；冷加载不复现。
- 建议：`lastVisited` 只记录列表级位置，或进入练习前给可取消提示。

### P2-7：草稿键可能出现 `NaN/null`

- 前端子代理实测 localStorage 存在 `os_practice_draft_105_NaN_sequential`、`os_practice_draft_105_0_null` 垃圾键；`bankId` 未就绪时 draftSaver 已开始写入，`goBack` 时也可能为 null。
- 建议：只有 `Number.isFinite(Number(bankId))` 且 `>0` 时才允许创建草稿键；清理历史垃圾键。

### P2-8：统计口径不一致

- `overview.totalErrors` 用 `status=1 AND is_mastered=0`（79），`errorAnalysis.totalErrors` 用全量（94）；同一“错题数”两个数字。
- `overview.byQuestionType` 通过 JOIN `user_question_favorite` 统计，是“收藏题型”而不是“练习题型”，与实际练习分布无关。
- 建议：统一为 `user_practice_log JOIN question_main` 口径，并在页面标注“错题总数/未掌握错题”等不同含义。

### P2-9：资源不存在返回 code=500

- `questionBank/questionBank/{id}` 不存在和 `questionPractice/report` 题目不存在都使用 `error()` 默认 code=500（`questions.py:635 / 1155`），前端无法区分业务“不存在”与服务器故障。
- 建议：资源不存在统一 404 或明确业务码。
