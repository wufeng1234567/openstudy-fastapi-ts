## 一、结论摘要

后台基础数据可用：

- 管理员 admin/123456 登录成功；`/getInfo` 返回 roles `["admin"]`、perms `["*:*:*"]`；`/getRouters` 返回完整动态后台菜单；
- `GET /system/dashboard/stats` 返回真实数据：4 用户、18 题库、738 题、33 笔记；`/system/dashboard/recent` 返回最近活动；
- 管理员可读 `/system/user/list`（4）、`/system/role/list`（3）、`/system/menu/list`（148）、`/system/dept/list`（10）、`/system/dict/type/list`（7）、`/system/config/list`（19）、`/system/comment/list`（10）、`/system/ai/config/list`（5）、`/carousel/carousel/list`（5）；
- 普通用户 user1 访问 `/system/user/list` 返回 code 403，`require_admin` 生效。

但后台存在两个 P0 越权：

1. **`/rag/config` 无管理员鉴权**：任何登录用户可读且可修改全局向量化后端/模型/API Key；实测 user1 `GET /rag/config` 返回 200 完整配置。
2. **公告写接口无管理员鉴权**：`notices.py` create/update/delete 仅需登录；普通用户可发布/删除全站公告（详见消息中心报告 P0-1）。
3. **AI 配置接口无管理员鉴权且泄敏**：`ai_config.py` 11 个端点零 `require_admin`；user1 `GET /system/ai/config/list` 返回 5 条（含 `apiKey`、`baseUrl`、管理员 `webPhone`），`DELETE /system/ai/config/999999` 返回 200，可删系统默认模型。
4. **监控后端大面积缺失**：`/monitor/**` 只有 ratelimit 8 个端点；在线/定时任务/日志/服务/缓存页面会落 `catch_all` 返回 200 空列表，呈现“无数据”假闭环。
5. `/system/dashboard/stats` 普通用户可读全局统计（P1 信息暴露）；`/ai/agent/configs` 无守卫且响应不是标准信封（P1）。

## 三、P0

### P0-1：公告写接口无管理员鉴权

- `notices.py:370-390` create、`:393-420` update、`:423-433` delete 均只用 `get_current_user`；普通用户可发布/删除全站公告。
- 后端子代理实测 user1 `POST /system/notice?notice_title=audit_p0_probe...` 返回 `code=200`、`data.notice_id=81`，DB `sys_notice` 出现 `81|audit_p0_probe|user1`（已由管理员删除）；user1 `DELETE /system/notice/999999` 也返回 200。
- 详见 [闭环检测-消息中心.md](闭环检测-消息中心.md) P0-1；后台管理页面的“通知公告”同样受影响。
- 建议：三个写接口加 `require_admin`；前台删除只走 `/front/*`。

### P0-2：AI 配置接口无管理员鉴权，泄露 apiKey/管理员手机号，可删系统配置

- `ai_config.py` 11 个端点零 `require_admin`；仅自实现 `_is_admin` 用于脱敏，未用于放行。
- user1 `GET /system/ai/config/list` → `code=200`，5 条配置含 `apiKey`、`baseUrl`、`webPhone:"19959256351"`、内部地址 `http://127.0.0.1:9200/v1` 等；user1 `DELETE /system/ai/config/999999` → `code=200`（删除通道对普通用户敞开）。
- 影响：模型密钥/端点/管理员手机号泄露；可删除系统默认模型导致全站 AI 功能不可用。P0 越权/泄敏。
- 建议：写接口全部 `require_admin`；读接口管理员全量脱敏、普通用户仅自身 `source=user`；删除自行放宽的 `_is_admin`，统一 `core/security.py` 口径。

### P0-3：`/rag/config` 无管理员鉴权，普通用户可改全局向量化配置

- `openstudy-fastapi/app/api/v1/rag.py:1240-1255` 的 `GET /rag/config`、`:1258-1333` 的 `PUT /rag/config` 只依赖 `get_current_user`，没有 `require_admin`。
- 实测 user1 `GET /rag/config` → `code=200`，返回 `config.rag.embedding.backend=local`、模型 `BAAI/bge-m3`、chunkSize/topK/rrfK/cloudApiKey 等完整配置；user1 `PUT /rag/config {"chunkSize":500}` 返回 200（已恢复原值）。
- 用户影响：任意登录用户可切换全局 embedding 后端/模型、修改 chunk 参数、覆盖/清空云端 API Key，导致全站检索失真/不可用或配置被篡改；属于 P0 越权写。
- 建议：GET/PUT 加 `Depends(require_admin)`；云端 Key 只返回掩码；操作审计。

## 四、P1

### P1-1：后台统计接口对普通用户开放

- `dashboard.py:19-24` 的 `GET /system/dashboard/stats` 只依赖 `get_current_user`；实测 user1 返回 `code=200`，可见全站用户数/题库数/题目数/笔记数及分类统计；`/system/dashboard/recent` 同样 200。
- 影响：普通用户可读取后台运营数据（虽非 PII，但属于信息暴露）；建议加 `require_admin`，或只返回当前用户维度。

### P1-2：智能体配置接口泄露且响应信封不合规

- user1 `GET /ai/agent/configs` → HTTP 200，响应体直接 `{"agents":[...]}`，无 `code/msg/data` 标准信封；内容含全部 personaPrompt。建议加 `require_admin` 并统一 `success()` 包装。

### P1-3：监控模块后端缺失，catch_all 造成假成功

- OpenAPI 398 条路由中 `/monitor/**` 只有 ratelimit 8 个端点；在线用户/定时任务/登录日志/操作日志/服务监控/缓存监控等后端不存在。
- `main.py:273` 只注册 `rate_limit_admin.router`；`catch_all.py:23-32` 对未匹配路径按关键词返回 200 空列表/`{"count":0}`，前端会显示“无数据”而非报错。
- 建议：核对前端 monitor 页面 URL，补齐后端或下掉页面；至少对 `/system/**`、`/monitor/**` 未知路径返回 404。

### P1-4：后台分组 CRUD 未实跑，写闭环覆盖不足

- 列表接口已验证（用户/角色/菜单/部门/字典/参数/评论/轮播/AI 配置），但新增/编辑/删除/角色分配/字典数据/参数保存/评论审核等写闭环未实跑（前端按收口指令停止）；若有写接口缺 admin 或前端 403 未处理，应升级 P0/P1。后端子代理已确认 `system.py` 等 19 个端点有 `require_admin`，但未逐项验证写操作落库。

### P1-5：20+ 后台 views 页面无路由/无菜单，深链 404

- 前端实测：`#/system/role`、`#/system/dict`、`#/monitor/online`、`#/carousel`、`#/notice-mgr` 均渲染 404；`/getRouters` 只返回“系统管理(user/config/notice)+监控(ratelimit)”两组，`src/store/modules/permission.ts` 无本地兜底路由。
- `src/views` 下角色/菜单/部门/字典、在线用户/定时任务/服务/缓存/Druid/登录日志/操作日志、轮播/敏感词/留言/公告管理等 20+ 组件成为死代码；`permission.ts` 的 ADMIN_PATH_PREFIXES 还包含 /wordBooks、/words、/dictation 等 17 个无路由前缀。
- 影响：后台功能面显示不全；管理员无法通过 UI 进入这些管理页；后续维护容易误以为功能存在。
- 建议：确认裁剪意图——保留则补菜单种子/动态路由；不保留则删除死页面与无效前缀。

### P1-6（待复测）：未登录访问 /index/home 疑似未跳登录

- 前端子代理清 cookie 后直敲 `#/index/home`，仍渲染后台首页框架（`permission.ts:232-242` 应跳 `/login?redirect=...`）；可能是 CDP clearBrowserCookies 未生效的假阳性，但不能排除。
- 若人工无痕窗口复现，则为 P0 后台壳暴露；建议人工复测并检查 js-cookie/守卫执行顺序。
