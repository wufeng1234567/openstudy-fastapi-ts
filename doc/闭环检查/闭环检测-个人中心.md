## 一、结论摘要

个人中心页面可以打开：

- `/front/profile` 显示本人昵称、用户名、邮箱占位、头像、我的笔记/收藏/模型入口；
- 我的笔记列表真实（当前 10 条第一页，共 12 条，分页 2 页）；
- `GET /system/user/profile` 返回昵称/邮箱/手机/性别/头像；`GET /system/user/front/106` 返回他人公开资料；
- 头像上传、修改密码、编辑资料弹窗 UI 存在。

但已确认核心编辑链路有问题：

1. **他人主页接口泄露手机号/邮箱**：`GET /system/user/front/1` 对 user1 返回 admin 的 `email=ry@163.com`、`phonenumber=15888888888`、`status`，任意登录用户可遍历 id 获取全站 PII。
2. **`front/{id}` 的“用户不存在”分支漏 import `error`**：访问 `/front/2`、`/front/999999` 返回 `code=500` + `NameError: name 'error' is not defined`。
3. **编辑资料前端发 JSON body，后端 `update_profile` 只接收 Query 参数**：`PUT /system/user/profile` 用 JSON `nickName=audit_test_nick` 返回 200，但再次 GET 昵称仍是“演示用户1”；换成 Query 参数才会真正更新。用户点“保存”会收到“修改成功”，实际什么都没改。
4. **`update_profile`/`updatePwd` 零校验**：空昵称、非法手机/邮箱、超长字段均可写入；超长昵称会 500 并回显 SQL 堆栈；密码可改成 1 位且密码经 URL query 明文传输。
5. 其他：头像只校验扩展名不校验内容，旧头像不清理，改密后旧 token 不失效；业务错误统一 code=500。

## 三、P0 问题

### P0-1：`/system/user/front/{id}` 泄露全站用户手机号/邮箱

- `app/api/v1/user_front.py:40-48` 返回 `email/phonenumber/status`；仅需登录，无本人/管理员限制。
- 后端子代理实测：user1 token 请求 `GET /system/user/front/1` → `{"userId":1,"userName":"admin","nickName":"系统管理员","email":"ry@163.com","phonenumber":"15888888888","sex":"1","status":"0"}`。
- 用户影响：任意登录用户可遍历自增 userId 抓取全站用户手机号/邮箱，属于 PII 泄露/合规风险；前端他人主页 `profile/index.vue:16` 也会直接显示该 email。
- 建议：前台接口只返回 `userId/userName/nickName/avatar/sex` 等公共字段（与 `users.py:149-154` 的 frontList 对齐）；手机/邮箱只允许本人或管理员读取。

### P0-2：`front/{id}` 的“用户不存在”分支 100% 500（漏 import）

- `user_front.py:10` 只导入 `success, paginate`，但 `:38` 调用 `error(...)`；`GET /front/2`、`/front/999999` 均返回 `{"code":500,"msg":"服务器内部错误: NameError: name 'error' is not defined"}`。
- 影响：他人主页对不存在/已注销用户必崩，前端显示系统内部错误而不是“用户不存在”。
- 建议：补 `from app.core.response import error`；不存在用户返回 404 业务码。

## 四、P1 问题

### P1-1：编辑资料前端 JSON body 被后端忽略，用户看到“修改成功”但数据不变

- `src/api/system/user.ts:82-88` 的 `updateUserProfile(data)` 用 `data: data`（JSON body）PUT `/system/user/profile`。
- 后端 `users.py:380-407` 的 `update_profile` 参数全部是 `Query`：`nickName/email/phonenumber/sex`，没有 `request.body`/Pydantic body。
- 实测：用 user1 JSON body `{"nickName":"audit_test_nick",...}` PUT 返回 `code=200`，随后 GET 昵称仍为“演示用户1”；改用 Query 参数 `?nickName=audit_prof_test...` 才变成 `audit_prof_test`（已恢复原值）。
- 用户影响：编辑资料点击“保存”永远提示成功，但资料不变；刷新后改动全部丢失。
- 建议：后端改为接收 Pydantic body（或前端改 Query），并补一条真实编辑断言；两端字段名统一。

### P1-2：资料/密码字段缺少服务端校验，超长值 500 且泄漏 SQL

- `users.py:381-407` 直接 Query 赋值，无 max_length/regex/enum；后端子代理实测：
  - `?nickName=<60个A>` → code=500，msg 含完整 `UPDATE sys_user SET nick_name=$1...` 与 asyncpg 堆栈；
  - `?phonenumber=12345678901234567890` → 同类 500；
  - `?email=notanemail`/`?sex=9`/`?nickName=` → 200 接受（脏数据）。
- `update_password` 只校验旧密码，`newPassword=1` 实测可登录；密码通过 URL query 明文传输。
- 建议：新增 `ProfileUpdate`/`PasswordUpdate` Pydantic schema，昵称 1-30、手机 11 位、邮箱正则、sex 枚举、密码 ≥6 且不等于旧密码；密码改 body；全局异常不回显 SQL。

### P1-3：业务错误统一 code=500

- `update_password` 旧密码错误返回 `code=500`（`response.py:18` 默认 code=500）；“用户不存在”等业务错误同样被前端当成服务器异常。
- 建议：业务失败显式 `code=400`；只有未捕获异常才用 500。

### P1-4：编辑弹窗手机/邮箱必填与存量空数据冲突，普通用户无法保存

- `userInfo.vue:38-42` 的 rules 要求 `phonenumber`、`email` 必填；演示账号 user1 两者为空（`GET /system/user/profile` 返回 `email=""、phonenumber=""`）。
- 前端实测：打开编辑资料不改任何字段直接点保存 → 提示“手机号码不能为空/邮箱地址不能为空”，无法保存；用户也没有 UI 入口清空回空值。
- 建议：非空才校验格式；或补齐存量数据/允许空值；这属于 P1 易用性阻断（叠加 P1-1 body 契约，实际编辑完全不可用）。

## 五、P2 问题

### P2-1：头像上传/旧文件/改密 token

- 头像 `file_util.py` 只按扩展名校验；实测将 `evil.txt` 改名 `evil.png` 可上传成功并写入 avatar；旧头像不清理，重复换头像累积孤儿文件。
- 改密后已有 Redis token 未清，旧 token 仍在；被盗号时改密无法踢掉攻击者会话。
- `save_upload_file` 超限 400 返回 `{"detail":...}` 而非 `{code,msg}` 信封；建议统一。

### P2-2：头像/密码/我的收藏/模型未完整验证

- 头像上传 `uploadAvatar` 走 FormData，后端 `save_upload_file`；未测类型/大小/旧头像清理。
- 修改密码成功后的当前 token/重新登录语义未测；无 `requiresLogin` 的 `front/profile` 路由需要确认游客行为。
- “我的收藏”复用 MyFavoriteNote； “我的模型”使用 AiModelManager，均未走真实数据。

### P2-2b：他人主页分类过滤错位 / 假分页 / 头像失败态

- `profile/index.vue` 的 `fetchCategories` 使用 `state.user.id || userStore.id`，但 `front/{id}` 返回字段是 `userId`（无 `id`），他人页分类标签实际用访问者自己的分类过滤他人公开笔记。
- 笔记 `pageSize=999` 全量拉取后前端 slice，total 不随分类筛选变化（假分页）。
- 头像 `beforeUpload` 仅校验 image 类型、无大小上限，`uploadImg` 无 `.catch`，失败无提示/弹窗卡住；改密成功仅关弹窗、不退出登录。
- 建议：改用 `state.user.userId`；后端分页；头像加大小/失败处理；改密后强制重登。

### P2-3：我的笔记全量加载 `pageSize=999`、前端分页

- `profile/index.vue:276/275` 使用 `pageSize:999` 拉全量后前端切片；笔记多时首屏/内存压力。
- 建议改用后端分页。
