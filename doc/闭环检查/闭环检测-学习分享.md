## 一、结论摘要

学习分享的阅读与写作主链路可以走通：

- 公开列表 29 篇笔记，分页、搜索、标签、分区、排序接口均正常；tags=20、sections=8、ranking=10；
- 详情页能显示标题、正文、标签、评论、上下篇、收藏状态；
- 写笔记 API 可创建/删除；临时笔记创建后个人笔记 12→13，删除后回 12；
- 收藏笔记列表 2 篇，评论预览/回复数据可读。

但当前模块不能判定完整闭环：

1. **点赞功能不存在**：前端没有任何点赞按钮/API，后端 OpenAPI 也没有 like 路由；`POST /notes/note/like` 等任意路径被 `catch_all` 兜成 `200 操作成功 data:null`。热榜却展示“点赞 N”，热度公式包含点赞×3，属于“看得见、点不了、假成功”。
2. **详情作者恒为“匿名用户”**：`get_public_note` 未把 authorName/avatar 传给 `format_note`，同一篇笔记列表显示“演示用户2”、详情显示“匿名用户”。
3. **公开列表混入草稿**：列表只过滤 `is_public=1`，不过滤 `status=published`；新笔记“发布”接口实际仍写 `status=draft`。后端实测 note_id=39（admin, draft, is_public=1）出现在 29 条公开列表中。
4. **浏览计数可刷 + 双计**：详情 GET 自增一次，前端再 POST `/public/click` 一次；`record_click` 无登录、无幂等，未登录连点 10 次 +10。
5. **评论越权写**：`POST /notes/comment/create` 只检查笔记存在，不检查可见性；user1 可给 user2 的私有笔记写评论并触发通知。
6. **收藏写链路 500**：收藏不存在的笔记触发外键 500；并发收藏同一笔记 4/5 次返回唯一键 500；前端双击/弱网重试必现红色错误。

## 三、P0 问题

### P0-1：点赞功能不存在，且被 catch_all 假装成功

- 前端 `src` 全量 grep 无点赞 API/按钮；后端 OpenAPI 无任何 like 路由；`notes.py` 只在 `format_note():57` 读取 `like_count`，没有写入实现。
- 参考 `list.vue:560` 的热榜 tooltip 会展示“点赞 N”，`note_ranking` 的热度公式为 `view_count + like_count*3 + comment_count*5`。
- 实测 `POST /notes/note/like`、`/notes/note/public/like/89`、`/notes/like`、`/noteLike/noteLike` 均返回 `HTTP 200 {"code":200,"msg":"操作成功","data":null}`，实际没有写入任何点赞记录（来自 `catch_all.py:13-32` 的兜底）。
- 用户影响：用户能看到点赞数但没有按钮/动作；如果外部客户端尝试点赞，会收到假成功，误以为操作生效；热榜的点赞项永远是演示数据常量。
- 建议：补 `user_note_like` 表和 `POST/DELETE /notes/note/{id}/like`，事务内增减 `like_count` 并做唯一键；同时 catch_all 不再兜非 GET 写接口。

### P0-2：`catch_all` 对未知写接口统一假 200（系统性）

- `catch_all.py:13-32` 对任何未匹配路径返回 `success(None)` 或空分页；本模块的点赞就是直接受害者。
- 影响：前端调用不存在/拼错的接口时，用户看到“操作成功”，数据却没有变化；任何后续路由漏注册都会变成静默 bug。
- 建议：非 GET 的未知路径返回 404/405；`/notes/*` 等已实现前缀直接 404；保留 catch_all 只处理历史 GET 兼容。

## 四、P1 问题

### P1-1：详情页作者名恒为空，显示“匿名用户”

- `notes.py:629` 的 `get_public_note` 调用 `format_note(note, linked_banks, is_favorited=is_favorited)`，没有 `author_name/author_avatar`；`notes.py:660` 的 `get_note` 同样缺失。
- 前端 `detail.vue:55` 回落 `noteData.authorName || '匿名用户'`；实测笔记 89 列表作者为“演示用户2”，详情响应 `authorName=""`、页面显示“匿名用户”（截图 `_scratch_v3/audit_notes_shots/02-detail-other.png`）。
- 影响：作者身份/主页跳转/信任链断裂；分享内容无法归属作者。
- 建议：详情接口查 `SysUser` 并传 `author_name/author_avatar`；前端详情不再用匿名兜底掩盖。

### P1-2：公开列表/热榜/标签混入 `status=draft` 草稿

- `list_public_notes`（`notes.py:296`）只过滤 `is_public=1, del_flag='0'`，无 `status='published'`；`note_ranking`（`:477-480`）和 `public_note_tags`（`:443-445`）同样。
- 后端实测 note_id=39（admin，`status=draft`，`is_public=1`）出现在公开列表 29 条中，按 content_length 排第 1。
- `editor.vue` 发布新笔记不传 `status`，`create_note` 默认 `status="draft"`（`notes.py:674`）；我们的临时公开笔记测试得到 `status=draft` 但仍出现在公开列表（本次测试数据已删除）。
- 影响：未发布/草稿内容可能被公开；用户对“发布/草稿”的预期失效，存在隐私风险。
- 建议：发布路径显式 `status='published'`；公开列表/热榜/标签统一加 `status='published'`；`is_public=1` 的 draft 禁止公开。

### P1-3：浏览计数未鉴权、无幂等、前后端双计

- `notes.py:607-608` 详情 GET 每次 `view_count += 1`；`notes.py:632-645 record_click` 没有 `get_current_user` 依赖，且没有去重。
- 前端 `detail.vue:516-524` 详情加载后再 `recordClick(noteId)`（`detail.vue:522`），一次访问 +2；后端实测未登录连点 10 次 +10（389→399）。
- 影响：热榜/浏览量可被脚本刷高；同一用户刷新页面重复计数，排行不可信。
- 建议：只保留一处自增（推荐 GET 内），删除前端 `recordClick`；或把点击做成带用户/时间窗幂等的独立事件；未登录拒绝或限流。

### P1-4：评论创建不校验笔记可见性（可评论他人私有笔记）

- `notes.py:1125-1150 create_comment` 只查 `Note.note_id == noteId, del_flag='0'`，不检查 `is_public`/作者；实测 user1 对 user2 的私有笔记 472 评论成功（comment id=135），而 GET 该笔记返回 403。
- 影响：私有内容可被他人评论/触发作者通知，越权写；评论内容本身还可能暴露私有笔记存在。
- 建议：创建评论前复用 `_get_note_checked`/`_can_view_note`；非作者只能评论公开且已发布笔记。

### P1-5：收藏写链路存在 500（不存在/并发）

- `notes.py:1458-1480` 的收藏接口先查后插，未预检笔记存在；收藏 `noteId=999999` 触发 `ForeignKeyViolationError` 500；并发 5 次同一笔记 4/5 次 `UniqueViolationError` 500。
- 影响：用户双击收藏或弱网重试会看到红色系统错误；前端无法区分“已收藏”与“服务器故障”。
- 建议：收藏前预检笔记；捕获唯一键冲突返回 400 “已收藏”；外键不存在返回 404。

### P1-6：编辑已有笔记离开无未保存提示，Ctrl+S 新笔记不能存草稿

- `editor.vue:523-527` 的 `goBack` 编辑态不写草稿（`:477`），改动直接丢失；新笔记态 Ctrl+S 只提示“请先发布笔记”（`:731`）。
- 建议：编辑态 dirty 标记 + `onBeforeRouteLeave`/`beforeunload` 确认；新笔记 Ctrl+S 走 `saveNoteDraft`。

### P1-7：收藏笔记列表缺 `authorName` / `isFavorited`，我的笔记列表 `isFavorited` 恒 false

- `notes.py:1451` 的收藏列表 `format_note` 未传 author 和 `is_favorited`；实测 `favoriteNote/list` 返回 `authorName=""`、`isFavorited=false`，但用户明明已收藏。
- `notes.py:257` 的 `notes/note/list` 也未计算 `isFavorited`。
- 影响：收藏列表丢失作者信息，收藏态显示错误。
- 建议：两个列表都批量计算 `authorName/authorAvatar/isFavorited`。

### P1-8：存储型 XSS 风险（后端零清洗）

- 后端笔记正文/评论接受并原样落库 `<script>`/`onerror` 内容（后端实测可写入；前端 Tiptap/markdown 渲染目前有潜在过滤器，但评论 `v-html` 依赖 `renderMentionsHtml` 转义，仍需后端兜底）。
- 影响：一旦某个渲染路径漏掉 DOMPurify，将形成存储型 XSS；即使前端安全，评论/正文也应做基本长度/敏感词/HTML 清洗。
- 建议：富文本存储前使用白名单清洗；保留原始 Markdown 与安全 HTML 分离；评论强制纯文本转义。

## 五、P2 问题

### P2-1：评论空内容可提交、无长度限制

- `create_comment` 接受 `content=""`（实测 id=134 成功），无 trim/长度；建议 `content.strip()` 非空 + 最大长度；错误返回 400。

### P2-2：删除父评论导致子回复成孤儿但仍占计数

- 删父评论 136 后 `replies(parentId=136)` 仍返回 1 条；`comment_count` 只减 1（5→4），与列表回复数不一致。
- 建议：明确级联删除或保留子回复并标明“父评论已删除”，同时统一计数。

### P2-3：排行榜 today/week/month 恒空，无空态文案

- 由于演示库近 30 天无新公开笔记，`today/week/month` 均空；页面有周榜空态但月/年也可能空，需确认；`note_ranking` 无 `status` 过滤（同 P1-2）。
- 建议：补 status 过滤和空态说明。

### P2-4：标签模糊匹配误伤（Java 命中 JavaScript）

- `notes.py:334-335` 使用 `ilike(f"%{tag}%")`；实测 tags=Java,Python → total=11，包含 JavaScript 等前缀文本。
- 建议：按逗号拆分精确匹配，或使用标签关系表。

### P2-5：列表请求无竞态保护 / 发布后关联保存误报 / 详情重试缺失

- `list.vue:494 fetchNotes` 无请求序号；快速搜索时旧响应可能覆盖新结果。
- `editor.vue:805-807` 先清 `editingNoteId` 再保存关联，关联失败会误报“发布失败”但笔记已发布，重试会重复发帖。
- `detail.vue:47-52` 详情错误态只有“返回列表”，无重试；`CommentSection.vue:163` 评论预览失败静默为空。
- 建议：列表请求序号、关联保存独立错误提示、详情/评论重试按钮。

### P2-6：其他

- `notes/comment/list`、`note_ranking`、`publicSection/list` 不需要登录即可读；评论列表会暴露评论内容，需确认公开范围。
- 游客不能浏览“公开笔记”（路由守卫重定向登录），与“公开分享”语义需产品确认。
- `get_public_note` 详情每次 GET 自增浏览，已包含在 P1-3。
