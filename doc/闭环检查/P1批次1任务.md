# P1 批次 1 任务提示词（安全 / 数据风险）

- 目标日期：2026-11-03
- 目标：修复 P1 中最影响安全/数据完整性的三组问题，不扩散到其他 P2。
- 验收：真实 API + 前端构建 + 代码审查；每项必须有“修复前现象 / 修复点 / 修复后验证 / 剩余风险”。

## 任务目标提示词

请作为 OpenStudy 修复工程师，按以下顺序完成 P1 批次 1：

### A. 个人中心：编辑资料契约与校验

1. 后端 `PUT /system/user/profile` 必须接收 JSON body（camelCase `nickName/email/phonenumber/sex`），不再只依赖 Query；前端 `updateUserProfile` 的现有 JSON 契约必须真正落库。
2. 服务端校验：昵称非空且 ≤30；邮箱有值才校验格式；手机号有值才校验 11 位；性别仅 0/1/2；空字符串允许清空可清空字段。
3. 前端编辑弹窗：手机/邮箱为空时不再强制必填；非空才校验格式；保存失败必须留在弹窗并显示服务端文案。
4. 修改密码：改为 JSON body，校验旧密码、新密码 6–20 位、不能与旧密码相同；前端改用 JSON body。
5. 不改动演示账号数据；必须用临时值修改并恢复。

### B. 英语学习：词书越权与导出、due 计数

1. `GET /words/practice/new-words?bookId=`、`GET /words/practice/mastery?bookId=`、`POST /words/practice/submit` 的 `bookId` 必须校验归属：只能本人或系统预置词书；否则 404/403，不能返回他人私有词书内容。
2. `POST /words/words/export`、`POST /wordBooks/wordBooks/export` 必须按当前用户过滤：只导出自己的 + 系统预置词书；传他人 bookId 返回 404/403。
3. `GET /words/practice/due?bookId=` 的 `count` 与 `items` 必须使用同一 `bookId` 条件（修复 count=20/returned=0）。
4. 前端不破坏现有词库/听写/阅读调用；真实 API 验证 user2 对 user1 词书全部拒绝，user1 正常。

### C. 题库搭建：编辑数据保护与保存保护

1. `loadEditData` 请求失败时不得先把 `builder.questions` 清空；设置 `editLoadError`，保存按钮逻辑必须拒绝保存并提示。
2. `removeQuestion` 必须二次确认；取消不能删题。
3. `handleSave` 的 `basicFormRef.validate().catch` 必须真正中止；空题干/选项/答案校验失败也必须中止。
4. 编辑保存时先更新/新增题目，全部成功后才删除被移除的旧题；读取原有题目失败必须中止保存；新建题库逐题写入失败时尽力删除刚创建的空壳题库。
5. 修复 `update_question` 状态变更后题库 `total_questions` 不重算的问题。
6. 前端 `npm run build:prod` 通过；真实 API 验证创建/编辑/删除题目与题库计数正常。

## Review 提示词

修复完成后，请以“审查者”身份独立检查：

- 读取 `P1批次1修复记录.md` 和 `git diff`；
- 对每个目标跑最小 API 回归（user1/user2 双账号、越权、边界输入）；
- 检查是否引入 P0 回归（尤其个人资料/公告/会话鉴权、导出、题库保存）；
- 检查前端是否有保存按钮竞态、错误提示、未 await 的异步操作；
- 输出“通过 / 有条件通过 / 不通过”，并把未覆盖风险写入剩余清单。

## 验收口径

- 通过：所有目标 API 回归通过，前端构建通过，无新增 P0。
- 有条件通过：目标主链路通过，但存在非阻断边界问题；必须列出。
- 不通过：任一目标出现数据丢失、越权、保存假成功或构建失败。
