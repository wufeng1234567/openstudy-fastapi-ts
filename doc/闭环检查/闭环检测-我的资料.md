## 一、结论摘要

我的资料页和资料链路可以真实走通：

- 页面显示 12 个资料夹、34 份资料、5.1 MB，默认资料夹下有文档列表、搜索、AI 检索、上传、分享、整理记录入口；
- 真实 API：创建 `audit_资料夹验证` → 上传文本 `audit_资料测试.md` → 状态 1→5、1 个 chunk、`vectorized:true` → 搜索命中原文 → 删除资料夹并清理，全链路通过；
- 后端子代理另验证：知识库 CRUD、上传（uploadText + curl multipart）、文档列表/正文/大纲/版本/微课状态、search/ask 引用、分享领取物理副本、跨用户隔离（12 项 404）均通过；审计数据已清理。

主要问题：

1. **知识库 `docCount/chunkCount` 上传后滞后**：上传后立即查 KB 仍显示 0 篇，直到向量化完成才变 1；若解析失败（status=4）则永久为 0，`kbShare` 会把有文档的库误判为空库。
2. **检索相关性信号失效**：无关查询仍返回片段且 `lowConfidence:false`，`/rag/ask` 可能出现 `found:true` 但正文说“没有找到”，引用与结论矛盾。
3. **catch_all 对未知路径假成功**（全局问题）：写错路径的删除/改名/分享会返回 200“操作成功”，实际没执行。
4. **删除不清理物理图片/文件及关联记录**：磁盘与微课/整理记录会留下孤儿。
5. **上传轮询期间重复全量刷新**：`pollUploadedDocuments` 每轮 `await load()`，单次上传可触发 `/rag/workspace/overview` 9 次；大库多文档时请求放大、列表闪烁。
6. **同名文件重复上传无提示**：实测同名文件 ×2 均入库，演示默认夹已存在 6 份同名 `01_智能体基础概念.md`。

## 三、P0 / P1

无 P0（未发现越权成功、数据串改或丢失）。

### P1-1：知识库 docCount/chunkCount 上传后滞后，失败时永久为 0

- 真实测试：`POST /rag/document/uploadText` 后立即 `GET /rag/knowledgeBase/635` → `docCount=0`；`GET /rag/document/list/635` 已有 1 篇；轮询 status=5 后 KB 才变 `docCount=1, chunkCount=1`。
- 根因：`rag_write_service.py:727-781` 的 `create_document` 不调用 `_refresh_kb_counts`（`:586-607`）；只有 `replace_chunks`（`:807`）和 `delete_document`（`:581`）刷新。若解析失败（status=4）永远不会到 replace_chunks，计数永久 0。
- 用户影响：资料夹显示“0 篇”但右侧有文档；总览统计失真；`kbShare.py:169` 用 `not kb.doc_count` 判空库，会把有文档的库误拦为“空知识库无法分享”。
- 建议：`create_document` 末尾和 `mark_document_failed` 后都调用 `_refresh_kb_counts`。

### P1-2：catch_all 对未知 API 返回 200 假成功（系统性）

- `catch_all.py:13-32` 对任何未匹配路径返回 `success(None)` / 空分页；后端子代理实测 `/api/v1/user/login`、`/api/v1/auth/login`、`/user/login`、`/api/v1/login`、`/v1/user/login` 全部 `200 {"code":200,"data":null}`，只有真正 `/login` 返回 token。
- 本模块的写错路径改名/删除/分享会显示“操作成功”但数据不变；`rag.py:226-228` 注释也承认过同类坑。
- 建议：非 GET 未匹配请求返回 404/405，保留 `Accept:text/html` 的前端路由放行。

### P1-3：检索/问答相关性信号失效，无关查询也返回片段

- `hybrid_search.py:299-308` 的 `has_keyword_agreement` 仅判断 `keyword_score is not None`；jieba 对“资料/的”等常见词几乎必命中，向量检索又有相似度地板，导致 `hits` 恒非空。
- 后端子代理实测：只有 1 篇审计文档的库中，问完全不相关的“量子色动力学/弦论”仍返回同一片段，且 `lowConfidence:false`；`/rag/ask` 无关问题返回 `found:true` + 1 条 citation，正文却说“在当前资料中没有找到”，自相矛盾。
- 用户影响：AI 搜索显示“找到引用”但内容无关；问答引用与结论冲突，置信度提示不可信。
- 建议：加停用词/最低 keyword_score 阈值；模型判无相关内容时 `found=false, citations=[]`。

## 四、P2 问题

### P1-4：上传轮询每轮全量 load / 超时静默

- 前端实测：一次上传的轮询阶段 `/rag/workspace/overview` 被请求 **9 次**（`index.vue:2531-2559` 的 `pollUploadedDocuments` 每轮 `await load()`）。
- 大资料库 + 多文档时，全量 overview 返回全部 KB/文档/图片元数据，轮询成本高；列表会被反复覆盖刷新。
- 轮询只认 status=4/5，其余最多约 90 轮×1.2s≈110s；超时后 `uploadTip` 被清空，卡片仍停在“解析中”，没有“仍在后台解析/稍后刷新/重新解析”的提示。
- 建议：轮询只调 `getDocumentStatus`，完成或节流后再 load 一次；退出时若有 pending，明确提示并保留 statusText。

### P1-5：同名文件重复上传无提示

- 前端实测：同名文件 ×2 都上传成功，没有“覆盖/保留/取消”提示；演示默认资料夹已有 6 份同名 `01_智能体基础概念.md`，AI 检索会返回重复段落。
- 建议：上传前按当前 KB + 文件名检测重复，给“覆盖/保留副本/取消”；或后端返回 duplicate 标记。

### P2-1：删除文档/知识库不清理物理图片/原文件及关联记录

- `rag_write_service.py:562-583`（delete_document）只删 chunk/doc/plan/log，未调用 `file_util.delete_file`，`image_map` 与原文件仍留在磁盘；`delete_knowledge_base`（`:246-278`）也不清理原文件。
- 建议：删除时按 `file_path`/`image_map` 清物理文件；至少提供后台清理任务。

### P2-2：删除知识库产生幽灵记录

- `delete_knowledge_base` 物理删文档，但未清理 `MaterialOrganizePlan` / `MaterialOrganizeLog` / `RagMicroCourse` / `RagQaRecord`；对比 `delete_document` 会清理整理计划/日志，知识库级删除不完整。
- 建议：按 docIds 级联清理关联记录，或在历史列表过滤已删文档。

### P2-3：HTTP 状态码恒 200，错误只在 body.code

- 未登录 401、越权 404、参数错 400、撤销 410 都以 HTTP 200 返回；前端必须读 `code`，与 catch_all 叠加会放大“假成功”。
- 建议：业务错误透出 HTTP 4xx；前端统一读 code，但服务端也应按语义返回。

### P2-4：上传先整文件读进内存再判 5MB

- `rag.py:61-80` 的 `_read_upload_files` 先 `await upload.read()` 再判断大小，6MB 文件也会占内存；建议流式/预判 Content-Length。

### P2-7：上传扩展名预检 / 拖拽提示 / 解剖错误态

- `index.vue:2371-2395` 只依赖 input accept，未用 `isSupportedKbFile` 预检；系统对话框选“所有文件”时要等后端 400，单文件提示取决于 `res.msg`。
- 拖拽上传在 `busy` 或无选中资料夹时直接 return，无提示（`:2366`）。
- `DocumentAnatomyDialog.vue:428-444` 非 200 时正文为空、无错误说明，弹窗一片空白。
- `microCourse.vue:252-258` 无 docId 直访直接 return，页面空白；`index.vue:295` 生成微课入口未禁用未解析完成（status≠5）的文档。
- 这些是体验问题，建议补错误态/禁用态与明确提示。

### P2-6：领取分享弹窗空输入无反馈

- 前端实测：领取弹窗空输入点“领取资料夹副本”没有错误提示（`19-receive-error.png`）；可能是按钮禁用但无视觉反馈。建议补必填校验文案/禁用态提示；领取副本真实可见性未实测。
- 相关：上传没有逐文件/百分比进度（仅文字 tip），大文件体验略糙；console 有 21 条 warning（ElementPlus `type=text` 弃用、Tiptap 重复扩展、ECharts 空容器、FavoriteButton targetId Undefined），无 error。

### P2-5：分享 doc 分支的归属校验与撤销语义

- `kbShare.py:157-168` 传 docId 时用 doc.kb_id 覆盖后查询 KB 只按 id+del_flag，未补 `kb.user_id == user_id`（doc 已校验，实际不可利用）；撤销只置 status，已领取副本保留，`my` 可出现 `status:invalid` 与 `copyStatus:available` 并存。
- 建议：补 KB 归属条件；在界面明确“撤销只影响后续领取，副本保留”。
