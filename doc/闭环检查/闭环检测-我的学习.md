  - 前端子代理 B：`glm-5.3-flash`

## 一、结论摘要

“我的学习”四个子模块的数据和后端接口基本真实可用：

- 题库管理：user1 有 5 个自己的题库，题库收藏 6 个；题库卡片、分组、分享/删除入口正常；
- 题目管理：题目收藏 8、我的错题 75、我的斩题 10；tab 数字与接口 total 一致；
- 笔记管理：我的笔记 12 篇，收藏的笔记 2 篇；新建临时笔记后列表 12→13，删除后回到 12；
- 学习统计：`overview`、`bySubject`、`trend`、`errorAnalysis`、`growth`、`learning-loop`、`weekly-report`、`exam-banks`、`diagnose` 均返回 `code=200` 真实数据；学习周报有 82 次练习，学习闭环有 3 个今日任务，考试计划可生成 59 天计划；页面截图显示总览、趋势、科目分布、错题诊断、学情诊断、学习闭环全部渲染。

当前主要问题不是数据不真实，而是**`/front/myQuestion` 根路径直接访问会白屏**、**同一统计指标存在多套口径**（例如错题总数 75 / 90 / 125），以及**统计页的多个子面板在接口失败时静默显示“无数据”**，容易让用户误判。未发现主链路 P0。

## 三、P0 / P1

无 P0。

### P1-3：`/front/myQuestion` 根路径直接访问白屏

- 前端子代理浏览器实测：登录后打开 `/#/front/myQuestion`，5 秒后 URL 仍停在根路径，内容区完全空白，只有顶栏“我的学习”（截图 `_scratch_v3/audit_shots/06_root.png`）。
- 根因：`myQuestion/index.vue:33-55` 的 `redirectToLastVisited()` 在 keep-alive 挂载时序下没有完成 `router.push`，且路由层没有兜底 `redirect`；侧栏子入口正常，所以从侧栏点击子项不会触发，但书签/历史/外链会看到白屏。
- 建议：在 `router/index.ts` 给 `/front/myQuestion` 增加 `redirect: '/front/myQuestion/myBank'`，或在 `redirectToLastVisited` 失败时 `router.replace('/front/myQuestion/myBank')`。

以下统计口径与错误反馈问题也按 P1 关注：

### P1-1：错题指标存在 75 / 90 / 125 三套口径

- `GET /userStats/overview` 的 `totalErrors=75`（`status=1 AND is_mastered=0`，见 `user_stats.py:61-68`）；
- `GET /userStats/errorAnalysis` 的 `totalErrors=90`（全量错题，含已掌握，见 `user_stats.py:297` 起）；
- `GET /userStats/learning-loop` 的 `errorBattle.total=125`（`study_diagnosis_service.diagnose` 的 ever_wrong，包含历史做题但不在 `user_question_error` 的题）。
- 页面同时出现“待消灭错题 75”“掌握进度 15 / 90”“错题歼灭战 ... 117 待攻克”，用户会认为数字互相矛盾。
- 建议：在接口/UI 层明确命名（“未掌握错题 / 错题总量 / 曾经做错过的题”），或统一为同一口径；至少在页面 tooltip 说明。

### P1-2：学习统计任一子接口失败会导致整页统计空白，且错误被隐藏

- `myStats/index.vue:765-795` 用 `Promise.all([getOverview, getBySubject, getTrend, getErrorAnalysis, getGrowth])`，任一请求失败就进入 catch；已成功的响应不会应用，`loading=false` 后可能显示 `isEmpty` 空态“还没有学习记录”。
- `WeeklyReportPanel.vue:186-197`、`LearningLoopPanel.vue:231-243`、`DiagnosisPanel.vue:439-450` 的 catch 只 `console.warn`/置空，用户看到的是“无数据”而不是“统计加载失败”。
- 影响：网络短暂异常/单接口故障会被误读为“我没有学习数据”，降低可信度。
- 建议：各接口独立容错，保留已加载部分；失败时显示可重试的错误条。

## 四、P2 问题

### P2-1：`overview.byQuestionType` 统计的是“收藏题型”而不是“练习题型”

- `user_stats.py:113-128` 的 `type_query` 从 `UserQuestionFavorite` JOIN `QuestionMain`，不是从 `user_practice_log` JOIN；实际只返回单选题 8 条（收藏题型），与用户实际练习的 6 类题型不一致。
- 页面目前未直接展示该字段，但后续做题型分布图会得到错误数据。
- 建议：改为 `UserPracticeLog JOIN QuestionMain`，按 `is_correct` 可同时算正确率。

### P2-2：学习闭环/错题歼灭战的“已歼灭 8”与“已掌握错题 15”不一致

- 同一页上方 `学习总览` 的“已掌握错题”为 15（`user_question_error.is_mastered=1`），下方“错题歼灭战”显示 8 已歼灭、125 总量；两处都用了“掌握/歼灭”语义，但数据源不同。
- 建议：统一为同一服务计算结果，或在 UI 文案中明确“已歼灭（曾经错过的题）”与“已掌握错题（含所有错题）”。

### P2-3：`myStats` 页面把收藏题库数当成“科目分布”的上限

- 页面标题写“按收藏题库”，数据来自 `bySubject` 的 `UserBankFavorite`；如果用户没有收藏题库但实际练习过，科目分布会为空，不能反映真实练习分布。
- 建议：增加“按练习记录”的统计口径，或把标题改为“我的收藏题库分布”。

### P2-4：`userStats` 子页面多个 catch 静默降级

- `WeeklyReportPanel`、`LearningLoopPanel`、`DiagnosisPanel` 的错误都只 console.warn，用户看不到失败原因；与 P1-2 同源，单独列出便于修复。
- 建议：统一错误态组件 + 重试按钮。

### P2-5：题库管理/题目管理/笔记管理空态与重定向细节

- `/front/myQuestion` 会根据 `lastVisited` 直接跳上次子页（`myQuestion/index.vue:33-51`）；用户从侧栏点“我的学习”时可能不落在题库管理首页，而是上次的统计/笔记页。
- 各分组为 `v-show` 常驻，首次进入会并发请求三个列表；数据量小时无感，大列表时需要懒加载/分页优化。
- 旧页面 `myFavoriteBank/myNotes/myFavoriteNote/myMarked/myMistakes/myShares` 仍保留但已重定向/被复用；若路由未清理，后续可能出现双入口维护成本。

### P2-6：题库管理空题库点击静默 / 批量删除确认框出现 Markdown 原文 / 全量拉取无分页

- `myBank/index.vue:814-820` 的 `handleViewDetail` 对 `totalQuestions=0` 直接 `return`，点击空题库卡片没有任何提示；应提示“空题库，先去添加题目”。
- 批量删除确认文案含 `**无法恢复**` 字面量（`myBank/index.vue:979`），Element Plus 的消息框不渲染 Markdown，用户会看到星号。
- `listMyQuestionBank()` / `listFavoriteBank()` 全量拉取后前端搜索/过滤（`myBank/index.vue:795-862`），题库多时会卡；建议后端分页或虚拟滚动。

### P2-7：笔记管理首屏重复请求 + ECharts 隐藏容器警告

- 前端子代理实测：`noteManage` 首屏 `noteCategory/all`、`questionBank/my`、`notes/note/list`、`favoriteNote/list` 各请求 2 次（v-show 常驻 + keep-alive `onActivated` 双拉）。
- keep-alive 下 `myStats` 图表在 `display:none` 时初始化，每次全站导航产生 6 条 ECharts “Can't get DOM width or height” 警告，掩盖真实错误。
- 建议：`onActivated` 加“已加载过”判断；ECharts 初始化/`resize` 前检查 `clientWidth/clientHeight > 0`。

### P2-9：`overview.totalQuestions` 实际是“收藏题目数”，不是题库题目总数

- `user_stats.py:130-141` 的 `totalQuestions` 来自 `UserQuestionFavorite`；user1 值为 8，而其 5 个题库题目总数约 335。`bySubject.questionCount` 同样多为 0。
- 页面“收藏题目 8”文案是对的，但字段名会让 API 调用方误以为“题库总题数”；建议重命名 `favoriteQuestions`，或补一个真实题库题数。

### P2-10：资源不存在返回 `code=500` 而不是 404

- `/questionError/questionError/1`、`/questionMarked/questionMarked/1`、`/favoriteQuestion/favoriteQuestion/1`、`/notes/note/1`、`PUT /notes/note` 都返回 `code=500` + “记录不存在”。
- 用户会看到“系统异常”而不是“记录不存在/无权访问”；建议统一 404 业务码。

### P2-11：`/userStats/exam-plan` / `/practice-progress` 的裸调用 422

- OpenAPI 中 `exam_date`、`since_ms` 为必填；不带参数直接调用 422。UI 的 `ExamPlanPanel` 会传 `exam_date`，`getPracticeProgress` 会传 `sinceMs`，正常路径可用；但空计划/直接调用没有友好空态对象。
- 建议：无计划时返回 `hasPlan:false` 空态；`since_ms` 给默认近 30 天。

### P2-12：`/userStats/reviewSheet` 返回 docx 二进制

- 该接口实际返回 `.docx` 字节流（zip/`word/document.xml`），不是 JSON；前端 `DiagnosisPanel.vue:184-220` 已按 blob 下载处理。
- 建议在 OpenAPI/接口注释明确 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`，避免调用方误按 JSON 解析。

### P2-8：`notes/note/list?userId=他人` 返回 403，但部分 `questionBank/my`/`favoriteBank/all` 忽略 userId 参数

- user2 调 `/questionBank/my?userId=105` 实际返回 user2 自己的 1 个题库，而不是 403；`/favoriteBank/all?userId=105` 同样返回 user2 自己的数据。
- 这没有泄露数据（用了登录态），但“传了 userId 却被静默忽略”会让调用方误以为得到了指定用户数据；建议统一参数策略（忽略时在响应/文档明确，或直接拒绝）。
