# 闭环检测 - 英语学习

- 检查日期：2026-11-02
- 检查范围：`/front/english/{ocr,vocabulary,listening,reading}`（拍照识词 / 我的词库 / 单词听写 / 阅读练习）
- 检查方式：两个子代理独立检查 + 主代理真实 API/数据库/页面复核
  - 后端子代理 A：`hy4-preview-f`
  - 前端子代理 B：`glm-5.3-flash`
- 主代理复核结论：**有条件通过（页面与基础数据可用；词书越权读取/导出、统计/记录口径为 P1）**

## 一、结论摘要

英语学习四个入口页均可打开：

- 我的词库页显示 3 个词书（四级高频词汇 20 词、考研高频词 10 词、四级核心词 12 词）；
- 单词听写页有词库选择、纯听力/打字输入/自动听写、范围/顺序/内容/语速设置；
- 阅读练习页有主题输入、题量选择、生成一篇入口；
- `/words/practice/overview`、`stats`、`last`、`due` 等返回真实数据；本次真实创建并删除临时词书（136）成功。

但词书相关 API 存在明确越权读/导出风险：

1. `GET /words/practice/mastery?bookId=...` 和 `GET /words/practice/new-words?bookId=...` 不校验词书归属；user2 直接读到了 user1 词书 135 的 20 个单词/释义/音标。
2. `POST /words/words/export?bookId=...` 和 `POST /wordBooks/wordBooks/export` 不按用户过滤；user2 可导出 user1 词书单词/全部词书（HTTP 200 xlsx）。
3. `POST /words/practice/submit` 未校验 `bookId` 归属，用户可把练习记录挂到他人词书；不影响他人 state，但数据归属混乱。
4. `words/practice` 的“due/mastery/new-words”统计与词书/学习状态存在口径需要核对：`due?bookId=128` 的 count=20、returned=0（count 未按 bookId 过滤）；部分错误返回 code=500。

## 四、P1 问题

### P1-1：`mastery` / `new-words` 未校验词书归属，跨用户读取单词

- `english_practice.py:607-685` 的 `new_words` 和 `_book_mastery` 只按 `bookId` 查 `Word`，没有 `book.user_id == 当前用户` 或系统预置判断。
- 实测 user2 请求：
  - `GET /words/practice/mastery?bookId=135` → `{mastered:0, learning:0, new:20, total:20}`；
  - `GET /words/practice/new-words?bookId=135&limit=5` → 返回 user1 词书 135 的 `abandon/absorb/abstract...`（词/释义/音标）。
- 而 `GET /wordBooks/wordBooks/135` 对 user2 返回 500「词书不存在」，说明访问控制存在但这两个接口绕过了。
- 用户影响：任何人知道词书 id 即可读取别人的生词本内容和掌握度；隐私泄露。
- 建议：在 `new_words` 与 `_book_mastery`（或路由层）先调用 `_get_owned_book`/允许系统预置；非本人/预置返回 403/404。

### P1-2：单词/词书导出接口不做用户过滤

- `words.py:478-515` 的 `export_words`：`select(Word)` 只按可选 `bookId` 过滤，不校验词书归属；`words.py:518-547` 的 `export_word_books` 直接 `select(WordBook)` 导出**全部用户**词书。
- 实测 user2 `POST /words/words/export?bookId=135` 和 `POST /wordBooks/wordBooks/export` 均返回 HTTP 200、xlsx 字节流（6788/5643 bytes）。
- 用户影响：词书内容/词书名/描述可被任意登录用户批量导出；应只导出自己的+系统预置词书。
- 建议：导出前复用 `_get_owned_book` / allowed_ids，或按 `user_id == uid OR user_id IS NULL` 过滤。

### P1-3：`POST /words/practice/submit` 不校验 bookId 归属/存在性

- `english_practice.py:284-330` 直接接受任意 `bookId` 写 `EnglishPracticeLog`；后端子代理实测 `bookId=99999` 仍返回 200 并落库（id=21，title 回落“单词听写”），同一请求重复提交会生成多条记录（id=18/20）。
- 用户可把练习记录挂到别人的/不存在的词书下；`_book_mastery` 还会读该词书，造成统计/归属混乱；双击/重试会稀释正确率。
- 建议：`bookId` 非空时校验属于当前用户或系统预置；增加 `clientSessionId` 幂等键。

### P1-4：`due?bookId=` 的 count 未按词书过滤

- `english_practice.py:740-748` 的 count 查询只用了 `cond`（uid+到期），没有加 `Word.book_id == bookId`；items 查询有 bookId 条件。
- 实测 `GET /words/practice/due?bookId=128&limit=5` → `count=20, returned=0`；`bookId=135` → `count=20, returned=5`。词库详情 128（12 词）显示“今天该复习 20 个”，点进去却是空列表。
- 建议：count 与 items 共用带 bookId 的条件；从词书详情进入听写时 scope=due 的行为与显示数字一致。

## 五、P2 问题

### P1-5：OCR「马上听写这些词」丢失 bookId/scope，闭环最后一步脱节

- `ocr/index.vue:561-564` 的 `goListeningNow` 只跳 `/front/english/listening`，不带 `bookId`/`scope`；听写页会默认选“第一本有词的”，不一定是刚导入的词库。
- 用户刚识别、导入后点“马上听写”可能练到别的词书，识别→入库→练习的闭环断在最后一步。
- 建议：跳转带 `?bookId=<donePanel.bookId>&scope=recent`（听写页已有 pendingBookId 消费能力）。

### P2-1：词书详情/单词列表对他人 id 返回 code=500 而不是 403

- `_get_owned_book` 的 `error("词书不存在")` 使用默认 code=500；user2 访问 `wordBooks/135` 得 500。前端可能弹“系统异常”，应返回 404/403。
- 同理 `words/words/list?bookId=135` 对 user2 返回 500。

### P2-2：`new-words`/`mastery`/`due` 参数与统计口径需核对

- `mastery` 与 `new-words` 在没有 `bookId` 时 422（必填）；页面/智能体调用时必须始终带；建议接口给出明确空态或默认词书。
- `mastery` 的 `learning` 统计含所有有 state 的词，`new` 用总词数减；与词书列表 `wordCount` 可能不一致，需核对。
- `due` 的 `items` 包含 `stage:0` 但 `dueDate` 已到期的词；页面需确保显示。

### P2-2：`submit` 幂等/`topWrong`/重复词等统计问题

- `submit` 无幂等键，同一 body 连发两次生成 id=18/20 两条记录，`stats.sessions` 2→3；bookId 不存在也落库（见 P1-3）。
- `stats.topWrong` 同 count 时按单词字母序，最近本次错词（如 deadline）会被旧词挤掉；建议同 count 按最近时间排序或单独返回“本次错词”。
- 同一词书可重复添加同形词（wordId 568/569），`_update_learning_state` 用 `setdefault` 只把第一条记入记忆曲线，另一条永远算“没学过”；建议 `(book_id, lower(word))` 唯一约束或导入去重。
- 词书详情 `dueCount` 与词书规模不一致（同 P1-4）；`due?bookId=128` 显示 20 但 returned 0。
- OCR `/ocr/recognize` 无大小/类型/超时校验，非图片异常泄漏内部路径（`cannot identify image file...`）；建议 10MB/白名单/统一文案/识别结果留痕。

### P2-3：OCR/阅读 AI 依赖未实测

- OCR 使用 `/ai/assistant/stream` scene=ocr 多模态、阅读使用 `/ai/generate/reading/stream`；真实模型/图片成本未跑，失败/超时/坏 JSON 路径需补测。
- OCR 页面有图片/文档双路径、词库内联创建、批量添加；代码层完整。

### P2-4：听写刷新不恢复、OCR 单卡词库与批量不一致

- 听写页刷新后回到选库页，`getLastPractice` 未被调用；用户无法从上次错词继续（只能统计回看）。
- OCR 识别结果每卡有独立词库下拉，但 `addAllWords` 只用全局 `selectedBookId`，单卡选库会被忽略；建议按 `word.bookId` 分组或批量时禁用单卡下拉。
- `reading` 子路由 meta 未加 `requiresLogin`（其他三个子页有），未登录深链可能裸渲染，建议对齐。
- 统计页 keep-alive 下 ECharts 空容器产生 6 条 warning（无 error）。

### P2-5：阅读练习无独立后端文章/题目接口

- OpenAPI 中没有阅读文章/题目/解析的独立端点；阅读页疑似由前端 AI 生成，题目数据仅前端内置，后端只验证 `/words/practice/submit(mode=reading)` 存储路径。
- 建议：若产品要求阅读记录/题目可回看，应补服务端文章/题目快照；至少明确阅读结果只存分数不存原文。
