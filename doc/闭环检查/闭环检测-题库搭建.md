# 闭环检测 - 题库搭建

- 检查日期：2026-11-02
- 检查范围：`/front/studio/create?type=public`（题库搭建 / 手动题目搭建）及题库、题目创建接口
- 检查方式：两个子代理独立检查 + 主代理真实 API/数据库/页面复核
  - 后端子代理 A：`hy4-preview-f`
  - 前端子代理 B：`glm-5.3-flash`
- 主代理复核结论：**有条件通过（主链路可用；编辑页数据丢失/删题无确认/保存非原子/停用题统计不重算为 P1）**

## 一、结论摘要

题库搭建页能正常打开：

- `/front/studio/create?type=public` 显示题库名称、科目、封面、描述、题目搭建、发布设置、发布按钮；
- 手动创建题库 + 单选题 API 闭环通过：创建临时题库 1304 → 题目 3771 → `totalQuestions=1` → 题库题目列表 1 条 → 删除题库后数据库无残留；
- 后端子代理另测 6 种题型（单选/多选/判断/填空/简答/组合题含子题）全部创建成功，题库 0→6 题量统计与 DB 一致，列表/搜索/batchInfo 可查，练习可见性通过，删除级联清理干净；
- 公开/私密切换、空题库发布确认、题目编辑/删除、AI 生成面板、图片/文档素材入口在代码中存在。

目前最值得关注的是：**编辑已有题库时，`loadEditData` 在题目加载失败后会保留空 `questions`，用户点击保存会把原有题目全部删除**；**删除题目没有确认框，误删后保存即真删**；**空题干/空选项没有前端校验，保存会因后端 422 整体失败**；**新建题库和题目不是同一事务，部分题目失败会留下半成品，重试还会重复新增**。

## 三、P0/P1/P2

### P1-1：编辑已有题库加载失败后，保存会删除原题库全部题目

- `create/index.vue:396-462` 的 `loadEditData` 一进来 `builderRef.value.questions = []`，随后调用 `getQuestionBank` / `listQuestionMainAll`；任一失败只 `ElMessage.error('加载数据失败')`，`questionsLoading=false`，**没有禁用保存**。
- 用户此时点“发布题库/保存修改”，`handleSave` 以空 `currentQuestions` 继续；若第二次 `listQuestionMainAll` 成功，`existingQuestions` 为原题，`toDelete` 会包含全部旧题，逐题删除。
- 影响：一次网络抖动/接口失败可造成题库题目全部丢失。
- 建议：加载失败设置 `editLoaded=false` 并禁用保存；或重新拉取失败时直接中止保存；保存前必须确认 `questionsLoaded`。

### P1-1b：删除题目无确认，误删后保存即真删

- `QuestionBuilder.vue:2371-2377` 的 `removeQuestion` 直接 `splice`，没有 `ElMessageBox.confirm` 或撤销提示。
- 编辑已有题库（`?bankId=`）时，用户点题目卡片红色删除按钮 → 题目从本地列表消失 → 再点“保存修改”，`create/index.vue:620-621` 的 diff 会把该题从数据库物理删除。
- 用户影响：误触成本高，且删除无法恢复。
- 建议：删除前确认，或删除后 toast 提供“撤销”；编辑已有题库保存前再次列出将删除的题号。

### P1-2：空题干/空选项未校验，保存整体失败

- `QuestionBuilder.vue:2328-2348` 新建题目默认 `title=''`、选项 `['选项A','选项B']`；`create/index.vue:480-523` 的 `validateAnswers` 只校验答案，不校验题干/选项。
- 用户拖入一个题型、未填题干就发布：前端校验通过，`POST /questionMain` 因 `questionText min_length=1` 返回 422，`handleSave` 只显示“保存失败”，用户不知道是哪一题。
- 建议：保存前逐题校验题干非空、单选/多选至少 2 个非空选项、分值范围；错误定位到题目序号。

### P1-3：新建题库 + 逐题添加不是同一事务，部分失败留下半成品

- `create/index.vue:657-677` 先 `createQuestionBankWithReturn`，再 `for` 逐题 `addQuestionMain`；任一题失败就抛到 catch，但已创建的题库/已添加的题不会回滚。
- 用户重试会创建第二个同名题库；题库列表出现半成品，题量不完整。
- 建议：后端批量创建题目接口（单事务）或前端失败时提示“题库已创建但题目未全部保存”并给出继续编辑入口；不要静默留下。

### P1-4：`basicFormRef.validate()` 的 catch 里 `return` 不会中断 `handleSave`

- `create/index.vue:539-542`：
  `await basicFormRef.value?.validate().catch(() => { ElMessage.warning(...); return })`
  的 `return` 只退出 catch 回调，`handleSave` 会继续执行。当前前面有手工检查名称/科目兜底，所以未即时暴露，一旦放开校验规则即成真 bug。
- 建议：改为 `const ok = await basicFormRef.value?.validate().catch(() => false); if (!ok) return`。

### P1-5：保存是逐题串行请求，失败无回滚、重试会重复新增

- `create/index.vue:621-654` 编辑模式逐题 `update/add/delete`；中途失败时已成功的题目已落库，前端没有标记成功项。
- 用户重试保存时，上一轮 `toAdd` 中已有部分落库且本地无 `backendId` 的题会再次新增，产生重复题目。
- 建议：后端提供批量保存事务；或失败后强制重新拉取题库题目并提示“部分已保存”。

### P1-6：题目停用后题库 `total_questions` 不重算（统计虚高）

- 后端子代理实测：题库 1305 有 6 题，`PUT /questionMain/questionMain` 把题目 3772 的 `status` 改为 `"1"`（停用）后，题库 `totalQuestions` 仍为 6，按 `COUNT(status='0')` 应为 5。
- 根因：`questions.py:1364-1366` 只在 `new_bank_id != old_bank_id` 时调用 `_recalc_bank_total`，没有在 status 变更时重算。
- 影响：题库列表/练习页题量虚高；停用题仍被计入；用户会以为题目没删掉。
- 建议：`update_question` 中只要 status 或 bank_id 发生变化，就无条件 `await _recalc_bank_total(db, question.bank_id)`。

### P2-1：`/questionBank/questionBank/my` 全量无分页
- `questions.py:605` 的 `my_banks()` 无 pageNum/pageSize/bankName，题库多时首屏全量；前端“载入已有题库”下拉会很长。

### P2-2：题目列表全量加载 + 编辑页 N 次请求
- `create/index.vue:415` 使用 `listQuestionMainAll` 全量；`QuestionBuilder` 切题/全屏编辑可能重复加载；大题库首屏与内存压力。

### P2-3：离开未保存提示缺失
- `create/index.vue` 有 `saveFormCache`（Pinia）但无 `onBeforeRouteLeave` 确认；编辑题目/题库后直接离开会丢改动。

### P2-4：AI 生成失败/空结果缺少服务端持久化
- AI 生成结果仅保存在 `QuestionBuilder` 本地预览，未导入保存前离开会丢失；生成失败只 toast，未保留原始 JSON/重试入口（代码走查）。
- 本次未实测 AI 生成链路（模型成本/时间），需下一轮补测无模型、超时、坏 JSON、生成失败是否留脏题。

### P2-5：同名题库、非数字删除 ID、批量删除策略

- `questions.py:644/684` 创建题库无同名校验；后端子代理实测同名题库可重复创建（id 1305→1307）。
- `questions.py:817/1386` 删除接口 `int(x)` 未捕获，`DELETE /questionBank/questionBank/abc` 会 500；建议改用 `_parse_id_list` 返回 400。
- `delete_banks`/`delete_questions` 遇到混合他人 id 会整体 403（安全但提示笼统）；建议前端提示具体无权限项。
- 未登录请求返回 HTTP 200 + body `code=401`，前端必须读业务码；建议统一 HTTP 状态语义。
