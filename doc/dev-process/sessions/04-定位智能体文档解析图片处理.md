# 调查报告：智能体侧上传文档（Word/PDF/MD）解析链路与图片处理

## 0. 总体结论（先给答案）

用户的反馈**准确**。智能体（Agent）侧对文档插图的处理停留在 **"提了、落了、能回插到题目，但没喂给模型看"** 这一步：

| 环节 | 智能体链路（`/ai/agent/stream`） | 题库 AI 搭建链路（`/ai/assistant/stream` scene=question-bank） |
|---|---|---|
| 文档解析 | 后端 `parse_file` 抽文字 + 插图 | 前端 `parseFileBlocks` 调后端同一 `parse_file` |
| 文档插图列表 | `doc_images`（**落盘成 URL**） | `imageList`（前端，base64 data URL） |
| 文档插图喂给 LLM | **否**（只喂给题目回插 + 提示词告知数量） | **否**（文档图也不进 `visionImages`） |
| 用户直接上传的图片喂给 LLM | 是（`req.images` → `image_url` block） | 是（`visionImages` → `images` → ImageBlock） |
| 插图回插到题目 | 是（`【图N】` → `<img>`，用落盘 URL） | 是（`replaceImageMarkers`，用落盘 URL） |

**关键差异不在"喂不喂文档图"（两边都没喂），而在于**：题库搭建在前端把文档拆成"[文本块 + 【图N】标记]"，模型能"看见文字里的图片位置标记"；而 Agent 侧虽然也生成了带 `【图N】` 标记的 `marked` 文本，但**这个 marked 文本并没有进入 `file_text`**——Agent 送给模型的是 `_attachment_plain_text(parsed)`，即 **`textContent` 纯文本（不含任何【图N】标记）**。因此模型既看不到文档图，也不知道图片在文档中的位置，自然"只能解析 Word 文本内容"。
