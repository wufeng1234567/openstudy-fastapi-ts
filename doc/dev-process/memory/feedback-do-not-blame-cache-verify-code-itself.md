**排障"改了代码但用户页面没效果"类问题时，禁止用"缓存/旧构建/环境差异"结案或反复挂起；必须落盘实证到底是代码问题还是别的。用户会直接质疑并反感这种归因。**

**Why:** 2026-10-11 用户原话"有没有可能 只是单纯你的代码问题 不是什么更新问题呢？"——Agent 此前多轮把"表格仍不渲染"归给"用户跑的是旧构建/缓存/环境差异"，用户不接受这种解释，要求直接验证代码本身。Agent 随后拉 vite dev server 编译产物实锤"代码/缓存无问题"，才把怀疑点正当收敛到浏览器运行时。

**How to apply:** 遇"改了前端用户页面没变化"时，先用**硬证据**定性——vite dev 模式下（用户跑 `npm run dev`）**拉 dev server 返回给浏览器的编译产物**，确认是否含最新修复；含=代码已生效→怀疑点转真实浏览器运行时（取 F12 Console 真实报错）；不含=确属构建/缓存。**先自证、再收窄**，不要用"你再重启/重建试试"把问题推回给用户。相关：`feedback-verify-code-not-memory-before-plan`（排斥臆测、要求先读代码核实现状）。
