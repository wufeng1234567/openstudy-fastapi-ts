**每完成一项功能/改动后，直接提交（写好提交说明），不要再问用户是否提交。此授权也覆盖"生成设计/方案文档"——不要先问要不要生成，直接产出落档。**

**2026-10-10 再次强调并扩大授权范围：批准实施方案后，"检查完毕直接干活就行，不需要我审批计划，不需要问我计划"——即授权/方向一旦确认，后续不必再提交计划待批，直接实施到底。** 与"做完即提交"一致：只在**方案本身待定/方向未定**时才需确认，方案拍板后一路做到提交。

**Why:** 2026-10-09 用户明确指示："添加完毕功能 记得提交写好说明 不需要每次都问我 每次做完就提交记录就行"。同日再次强调"生成文档不需要问我 直接干活就行"。2026-10-10 又强调"不需要我审批计划 不需要问我计划"。用户希望减少来回确认的摩擦。
**How to apply:** 本仓库完成一个可交付的改动单元后，主动按既定流程提交（用 worktree 隔离脏工作区——见 feedback-git-worktree-isolation），并撰写清晰的提交说明；只在涉及高风险/不可逆操作（如强推、删除大量文件、推送公开仓、需要凭据）时才停下确认。定向 `git add` 本次改动文件，不要 `git add -A` 带上历史遗留脏改动。

**提交前流程（用户已确认模式）：** 完成改动并验证通过后，先跑一遍相关回归探针 + `app.main` 导入，再进入提交链路——`先 fetch → 建 worktree`（用 git worktree 隔离脏工作区），把本次改动文件拷入新工作区提交推送，不触碰原脏工作区。
