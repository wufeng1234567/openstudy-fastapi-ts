用户要求：**在讨论功能是否已实现、或提改法之前，先实际读代码核实现状**，不要凭记忆/推测下结论；且用户会显式区分「先梳理」与「开始写代码」两个阶段。

**Why:** 用户多次经历"记忆/方案与代码实际状态不符"（如 Agent 侧工具链路、草稿功能其实已存在），并以"以代码为准、记忆是历史可能过期"为共识；2026-10-11 提出 Word 图片解析需求时也明确说「**先不写代码 给我仔细梳理这个功能**」。
**How to apply:** 收到"看下实现了没有/梳理一下"类请求时，先并行读相关源码（含对照参考模块）核实真实行为，再输出梳理结论；不要跳过核实直接给方案，也不要在"梳理"阶段顺手改代码；若发现用户描述与代码不符，坦率指出并以代码为准。
