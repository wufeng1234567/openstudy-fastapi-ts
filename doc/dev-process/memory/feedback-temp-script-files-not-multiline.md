---
name: 临时脚本用文件而非内联多行
description: 本环境（Windows/CodeArts CLI）内联多行脚本（python -c 多行）语法常失败，应落成临时 .py 文件再执行，用完删除
type: feedback
from: Agent
---

**规则：** 需要执行多行脚本（如查 DB、跑临时逻辑、前端校验）时，**写成临时脚本文件**再运行，不要用 `python -c "多行..."` 或 `node -e "多行..."`（含 heredoc 拼命令）的内联形式。用完删除临时文件。

**Why:** 2026-10-09 排查 `tools` 列类型时，内联多行脚本反复语法报错（换行/引号在 Windows 命令行下被破坏），改用临时脚本文件（如 `_chk.py`）后一次成功。2026-10-10 又实证：用 heredoc + `node` 组合做前端校验同样失败，改 `write` 工具写 `.cjs` 脚本再跑一次通过。

**同类坑：把多个 git 操作（如「删 worktree + fetch」或「建 worktree + 拷入文件」）拼成一条命令也会被 Sandbox 拦（2026-10-11 再次踩中）。须拆成单步逐条执行。**

**同类坑 2：断言"代码里不该出现某关键词"时，别用「源码文本包含某字符串」这种粗断言**——注释/文档字符串会误伤（2026-10-11 实证：`_probe_middleware_stream.py` 的 MW-09 断言"源码不含 `BaseHTTPMiddleware`"被判红，仅因该文件文档串里用它做了"为何不用它"的说明）。**正解=只匹配真实形态**：是否存在对应 `import`、是否出现 `X(` 调用 / `X)` 继承，或直接用 `ast` 解析 import。

**例外（2026-10-11 实证）：本条只针对"多行逻辑脚本"。若是「向文件末尾追加一小段固定内容」这种单层操作，`cat >> file <<'EOF' ... EOF` 的 heredoc **在本环境可正常写入且中文为 UTF-8**（实测追加中文段落无 GBK 乱码），可照用；追加后仍建议核查末尾中文显示与编译。**

**How to apply:** 在 win/cmd 环境做一次性排查/校验时直接创建临时脚本文件（`.py`/`.cjs`/`.js`），勿尝试 heredoc 拼多行命令；也勿把多个 git 操作拼成一条命令，拆单步跑。注意临时验证脚本不要误入库（本仓库约定 `tests/_probe_*.py` 才刻意保留入库）。**临时校验脚本用完即删，下次可能已不存在——需重新写一份再用（2026-10-10 实证：`openstudy-vue3-ts\_v.cjs` 校验脚本本轮已不在，须重写）。**

**临时脚本应落在该仓库测试目录（如 `openstudy-fastapi\tests\`），用完删除（2026-10-11 实证：路由顺序探针 `tests\_probe_route_order.py` 写完即删）。**
