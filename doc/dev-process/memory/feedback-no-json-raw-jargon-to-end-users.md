**面向 C 端用户的展示与措辞：不得出现原始 JSON / 特殊格式协议文本；措辞必须"说人话"，去掉只有程序员看得懂的技术性说明。**

**Why:** 2026-10-11 用户原话「专家输出的内容 是带格式文本的不好看 需要优化掉 **不能给用户看那些json格式或者特殊格式**」；此前（2026-10-10）也要求「直接说它可以干嘛」「不要敲代码程序员看的词」。这是**教育/学习类 C 端产品**（非开发者工具）定位的持续取向——同类决策还有删掉底部状态条（轮/步/llm 毫秒）。
**2026-10-11 追加细则（UI 优化四项中的两条，同源）：** ① **子代理的输出内容不得携带 markdown 格式字符**（如 `*` 星号等），须去格式化后再展示；② **协议/工具名的英文原样文本要给用户看中文**（如 `delegate 完成`、`delegate_task · delegate` 这类英文标识不能直接露出，须映射为对应中文，落点在 `AgentToolResult/index.vue` 的 `TOOL_LABELS`/`ACTION_LABELS` 映射表；此外 `AgentToolDetail/index.vue` 的 `FIELD_LABELS` 也要补 `subAgent`/`subAgentName`/`result`/`steps` 中文，否则原始英文键名既露英文又因超宽与值相碰）。

**2026-10-11 追加实现取向（Agent 拍板）：** 去 markdown/协议噪声**优先在生成/消费源头清洗**，而非渲染层——例：子代理 `delegate_done` 的 `summary`（结论）在 `useAgentChat` 消费时就用 `stripMarkdown` 剥掉 `*` 等标记，这样"结论"插值与"展开详情"两处都干净（一次性去噪，避免多个渲染点重复处理）。
**2026-10-11 追加取舍原则（隐藏优先于翻译，Agent 拍板）：** 当某条技术信息（如 `delegate_task` 委派工具卡片，会露出"请专家帮忙/派发"）**属于内部实现细节**时，**优先"隐藏/不外露"而非"翻译成中文"**——用户看到了就觉得不对。本题的 delegate 工具卡片在单/多专家两种场景都隐藏（落点 `useAgentChat.ts` 的 `tool_start`/`tool_result` case 过滤），中文映射表（`TOOL_LABELS`/`ACTION_LABELS`）仅作兜底；单专家场景由此做到"无协同卡 + 无派发痕迹 = 纯当前助手自己完成"。
**2026-10-11 追加细则（子代理结论里的 markdown 表格也要去掉）：** 子代理的结论还会出现 **markdown 表格**（`| 指标 | 数值 |`、`|---|` 分隔行），用户原话「这类 md 表格格式 符号 同样也要说明不要这种符号」。落点=`useAgentChat.ts` 的 `stripMarkdown` 补 `stripMarkdownTables`：①**网格分隔行**（`|---|:--:|` 一类）整行删除；②**表格数据行**（`| a | b |`）去首尾 `|`、单元格 trim 后连接（两列用 `：` 连成 `累计作答次数：227` 最自然，列数 >2 用 ` · `）——目标是转成可读行而非留一堆 `|`。用户给的样例数据：`累计作答次数 227 / 正确率 58.6% / 错题数 26 / 已掌握错题数 2 / 收藏题目数 8 / 斩题标记数 5 / 收藏笔记数 1 / 题库学习次数 18`。

**2026-10-11 `stripMarkdownTables` 实测结论（用样例数据跑通，转换效果完全正确）：** ① 分隔行 `|---|---|` 整行删除；② 两列表转 `指标：数值`（表头与数据都转对）；③ 三列表转 `科目 · 错题数 · 正确率`（` · ` 分隔）；④ **单个竖线不误伤**（如 `TCP | UDP` 保持原样，不当作表格行）。另有实测踩坑：**提取表格行时不要用正则**，正则里的 `\\{` 易被误当转义组——改用字符串查找（`startsWith('|')`/`includes('|')` 一类）判定与切分更稳。

**2026-10-11 覆盖范围核对结论（用户诉求「子代理的结论会出现 md 表格」）：** 已确认全部 summary 产出路径均经清洗——① experts 卡片"结论"走 `row.summary`；② 专家卡片"交给它的任务"走 `row.task`；③ `AgentToolResult` 主行 summary 虽可能带表格，但 delegate 工具卡本身已隐藏（不显示）；④「深度思考」（`AgentReasoning`）与「主助手正文」走 md 渲染器（`renderAgentMarkdown`），表格能正常渲染、**不去格式化**。清洗调用点共 3 处（`pushExpertStart` 的 task、`fillExpertDone` 两处 summary）。**后端 `delegate_done` 的 summary 不再二次清洗**——前端消费点即清洗源头，无需双保险。

**How to apply:** 任何要展示给终端用户的组件（工具结果卡片、专家卡片"结论"、错误提示、设置面板文案）都必须保证呈现的是**人类可读的通俗描述**；出现原始 JSON、`<|DSML|>`、`{"tool":...}` 之类协议文本时，要么在**生成源头拦截**（如子代理协议文本回灌纠正），要么在渲染层做去技术化处理。措辞层面统一用业务语言（如"专家帮你看题/建题库"），不暴露工具名、函数名、字段名。
