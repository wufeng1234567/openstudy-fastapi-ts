**排障/写代码时不要再反复征求"计划/方案"的同意——直接干；但遇到"两条链路、两种修复方案完全不同"的关键技术分叉时，问一句方向是正确且被接受的。**

**Why:** 2026-10-11 Agent 在排查子代理问题中途想先确认链路（普通 API vs ds-free），自述"用户说不用问计划，但这是关键技术分叉，问一句方向能避免整轮白干"——用户随后**确实回答了链路问题**（答：普通 API + Function Calling），没有不满。说明用户反感的是**琐碎的方案确认**，不是**能防止跑偏的关键澄清**。

**How to apply:**
- 不要为步骤化计划、实现细节、显而易见的下一步去征求同意——直接执行（呼应 feedback-auto-commit-with-message：完成即提交）。
- 但当**存在两条互斥路径且修复方案完全不同**（如此次 ds-free 链路 vs 普通 API 链路）、盲目动手会整轮白干时，**先问一句方向**——这类澄清是值得的。
- 判定标准：问「会不会让你少走一整轮弯路」——会，就问；不会，就干。
