2026-10-11 用户对智能体/专家命名与设置面板下拉给出明确产品决策（原话：「明显多余了」「有没有更优秀的整合方案」「名字不够融合，又是智能体又是专家，要区分吗？还是给用户自由度自由命名？」）。

**定案（Agent 综合判断，用户已知情接受）：**
1. **命名统一**：**面向用户的层面统一叫「专家」**（不再"智能体/专家"混用）；「智能体设置」里的东西也叫专家。
2. **删除设置面板智能体下拉里的「官方智能体」分组**——理由：已有"专家开关"，"自动路由"已是默认且最优路径，下拉里的"选官方专家"与"专家开关"语义重复、多余。
3. **保留「我的智能体」入口**：用户自定义智能体（如"数学老师"）仍需一个**显式选择入口**（它不参与官方专家的开关/自动路由），故下拉只保留「自动」+「我的智能体」两块。
4. **下拉整行隐藏**：当只剩"自动"一项（`myAgents` 为空）时该行完全没意义 → 整行 `v-if="myAgents.length"` 隐藏。

**Why:** 用户侧不该同时看到"智能体"和"专家"两套叫法，也不该有两处语义重叠的"选专家"入口（下拉 vs 专家开关）；官方专家由「专家开关 + 自动路由」统管更简洁，用户自定义智能体是另一类事物才需要显式选。
**How to apply:** 后续 UI 文案、设置面板、提示词涉及用户可见命名时统一用「专家」；改 `chat.vue` 智能体下拉时不要恢复"官方智能体"分组；用户自定义智能体保留独立下拉入口（勿与官方专家开关合并）。

**2026-10-11 延伸（命名去英文/去技术味到工具层）：** 用户进一步要求把界面上**残留的英文/协议标识也中文化**——如 `delegate 完成`、`delegate_task · delegate` 等工具名与 action 名要显示成对应中文（落点 `AgentToolResult/index.vue` 的 `TOOL_LABELS`/`ACTION_LABELS`）。即"统一用中文业务语言"的边界已从提示词/设置面板扩展到工具结果卡片。

**2026-10-11 中文映射的具体落点（本轮定案的具体字段，供实施遵循）：** `AgentToolResult/index.vue` 的 `TOOL_LABELS` 补 `delegate_task: '派发专家'`、`ACTION_LABELS` 补 `delegate: '委派'`；`AgentToolDetail/index.vue` 的 `FIELD_LABELS` 补 `subAgent`/`subAgentName`/`result`/`steps`（子代理返回字段原本无中文映射 → 显示原始英文键名，且 `subAgentName` 12 字符超 `.td-key` 的 68px 宽 → 与值相碰，补映射后标签变短即解）。

**连带清理（同批，`chat.vue`）：** 删除"官方智能体"分组后 `agentRoles` 成为**死变量**（只在声明 + `loadAgents` 里赋值、无任何消费）→ 依本仓库惯例（删前先 grep 确认无引用）删除 `agentRoles` 声明与其在 `loadAgents` 中的赋值，并连带去掉仅供它用的 `listAgentRoles()` 调用（减少一次请求）；`AgentRoleMeta` 类型 import 若随之无用也一并清理。
