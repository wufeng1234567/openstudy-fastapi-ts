# 核心链路：从一份资料到一套能刷的题

> **文件位置**：`doc/CORE-FLOW.md`
> 这是 OpenStudy 的主干能力，也是产品对外介绍的第一卖点。

---

## 一句话

> **上传一份 Word / PDF / Markdown → 系统自动解析 → 变成你的题库 → 直接开刷。**

---

## 四步拆解

```
① 上传资料          ② 自动解析            ③ 导入系统            ④ 开刷
Word / PDF / MD  →  拆段落·认公式·抠图片  →  变成题库·标注出处  →  四种模式练习
带公式、带图片        转成可检索的知识块        按原文出题           自动判分、进错题本
```

### ① 上传资料

用户在三个地方都能上传：

| 入口 | 位置 | 用途 |
|---|---|---|
| 智能对话 | 输入框下方「附件」按钮 | 边聊边传，让 AI 直接读这份资料 |
| 题库搭建 | 「AI 智能出题」弹窗 → 参考素材 | 指定用哪份资料出题 |
| 知识库 | 左侧抽屉 → 上传文档 | 长期沉淀，后续随时检索 |

**支持格式**：`.doc` / `.docx` / `.pdf` / `.md` / `.txt`

**代码位置**：
- 前端上传组件：`openstudy-vue3-ts/src/components/ChatFileUploader/index.vue`
- 后端上传接口：`openstudy-fastapi/app/api/v1/document.py`、`app/api/v1/rag.py`

---

### ② 自动解析

这一步是整个产品的地基。传统方案在这里断掉，后面就全废了。

**解析器做了什么**（`openstudy-fastapi/app/services/file_parser.py`）：

| 能力 | 说明 |
|---|---|
| **拆结构** | 按标题 / 段落分块，保留章节层级，不是硬切字数 |
| **认公式** | Word 原生公式（OMML）与 LaTeX 都识别，前端用 KaTeX 渲染 |
| **抠图片** | Word 内嵌图、PDF 里的图，按位置归属到对应段落，正文留 `【图N】` 标记 |
| **格式兜底** | 老版 `.doc` 自动调 Word 转 `.docx`；改名的文件按魔数识别，不只看后缀 |
| **编码兜底** | TXT 自动探测 GBK / UTF-8，不乱码 |

**为什么难**：教材类文档往往是「图 + 公式 + 表格」混排。
只抽纯文本 → 公式变乱码、图全丢；直接丢给大模型 → 超出上下文、图片对不上位置。
我们的做法是**图文一起进**：正文里的 `【图N】` 标记会和图片一起入库，出题时再按标记插回去。

**支持的格式声明**：
```python
# openstudy-fastapi/app/api/v1/document.py
"formats": ["pdf", "doc", "docx", "txt", "md"]
```

### ③ 导入系统

解析完的文档进知识库，走完整流水线：

| 环节 | 实现 | 代码 |
|---|---|---|
| 分块 | jieba 中文分词，按语义切 | `services/rag/chunker.py` |
| 向量化 | bge-m3，1024 维 | `services/rag/embedding.py` |
| 存储 | pgvector `vector(1024)` | `models/rag.py` |
| 索引 | HNSW 向量索引 + GIN 全文索引 | `deploy/db-init/01_*.sql` |
| 检索 | 双路召回 + RRF 融合 | `services/rag/hybrid_search.py` |

**检索为什么用两路**：
- 向量路擅长「意思相近」——搜「求导」能找到「微分」
- 关键词路擅长「精确命中」——搜「拉格朗日中值定理」不能漏

两路结果按**排名**合并（RRF，k=60），不拍脑袋定权重。

**出题时会发生什么**：
1. 用户说「用这份资料出 10 道单选题」
2. Agent 调 `knowledge_search` 检索相关段落
3. 把检索到的原文 + 图片一起喂给多模态模型
4. 模型返回题目 JSON，每道题带 `source`（出自哪一段）
5. 题目落库，前端渲染公式和图片

---

### ④ 开刷

题库建好后有四种练习模式：

| 模式 | 说明 | 特点 |
|---|---|---|
| 顺序练习 | 按章节顺序逐题练 | 适合系统学习 |
| 随机练习 | 随机抽题 | 一次抽定，不刷新 |
| 错题练习 | 只练答错过的题 | 支持「只刷错题」筛选 |
| 模拟考试 | 自定义组卷、限时、交卷判分 | 有历史记录，可「再考一次」 |

**判分规则**：
- 单选：选中即判
- 多选 / 判断 / 填空：需要点「确认」
- 简答：AI 辅助判分

**刷完之后**：
- 答错的题自动进**错题本**
- 可以**收藏**、**斩题**（标记已掌握）
- **学习统计**给出正确率、趋势、薄弱知识点 TOP5、难度分布

---

## 这条链路解决了什么

| 原来的痛点 | 现在 |
|---|---|
| 手动录 20 道题约 1 小时 | 上传即出题，分钟级 |
| 公式变乱码、图片丢失 | 公式渲染 + 图片按位置插入 |
| 出的题不知道哪来的 | 每道题标注出处段落 |
| 错题散落各处 | 自动进错题本，统计到知识点 |
| 不知道下一步练什么 | 薄弱点 TOP5 + 难度分布 |

---

## 30 秒讲清楚这条链路

> "我们的核心链路是四步：**上传、解析、入库、开刷**。
> 用户上传一份带公式和图片的 Word，系统先自动解析——不是简单抽文字，是把公式认出来、图片抠出来、按段落归好位；
> 然后进知识库做向量化，建两套索引；
> 接着 AI 从原文里取材出题，每道题标注出处；
> 最后用户直接开刷，四种模式，答完自动判分、进错题本、更新学习统计。
> **这条链路走完，一份资料就变成了一个能用的题库。**"

## 已知边界（如实说）

| 边界 | 影响 | 计划 |
|---|---|---|
| 扫描版 PDF（无文字层）抽不出正文 | 只能拿到目录骨架 | 30 天内接入 OCR |
| 图片不参与向量化 | 不能「以图搜图」 | 90 天内上多模态向量 |
| 单文档最多喂 8 张图给模型 | 图特别多的文档会截断 | 按相关度挑图 |
| `.md` 里的外链图片不下载 | 只保留链接 | 后续支持 |
