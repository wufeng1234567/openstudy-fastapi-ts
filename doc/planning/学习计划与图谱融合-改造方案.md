# 学习计划 × 知识图谱融合 · 改造方案

> 日期：2026-11-08  
> 性质：**只读方案 / 待审批**。本文件不修改任何业务代码；审批通过后才进入实施。  
> 范围：`openstudy-fastapi` + `openstudy-vue3-ts`。  
> 一句话：**把「学习计划」和「知识图谱」合并成一个只给建议、能反复调整、能看见系统如何思考的学习规划工作台。**

---

## 0. 一页结论

### 0.1 我们要做的不是“更好的任务清单”

旧版的问题是方向错了：它把系统对用户的理解，包装成了一张张“读《导数》”“开始今天第一项”“去练这个题库”的任务卡。用户不需要被安排，用户需要的是**建议、依据、替代方案**。因此本轮做的是：

1. **删掉任务**：删除 `读《xx》` 卡片、checkbox、开始/去做/完成按钮、`days[].tasks[].status`、`progress`、`todayTasks`。
2. **合并界面**：学习统计页只剩一个「学习计划」工作台。左边是统一图谱，右边是建议，下面是历史；不再有第二个“知识图谱”面板与它并列。
3. **统一图谱**：`topic / bank / document / note / image / web` 六类节点，全部来自真实表；没有真实关系就不画边。
4. **建议可改**：`StudyAdvice` 是可反复修改的建议书，不是一次性计划；支持快捷调整和自然语言调整，每次调整产生新版本。
5. **动画真实**：动画播放的是后端真实图遍历 `trace`，不是前端随机特效；LLM 只在这条真实轨迹和锁定事实上写解释，不凭空造节点。
6. **历史可管**：新增一张 `study_plan_snapshot` 快照表，支持列表/重命名/置顶/删除/查看后继续；不存任务完成态。
7. **对话可生成**：`study_plan` 新增 `advise` action，智能对话页与悬浮助手复用同一张 `StudyPlanGenerativeCard` 和同一套动画。
8. **资料诊疗室同步重构**：资料体检保留；原文阅读支持全屏；第三页「学习处方」删除，改为「智能报告」，直接给出这份资料的更新目标与改进建议。

### 0.2 已定约束（不作为可选项）

- **只给建议**：全站计划面不出现任务卡、checkbox、开始/去做/完成按钮；`StudyAdvice` 不含 `tasks/days/status/done/progress`。
- **历史必须服务端持久化**：新增一张 `study_plan_snapshot` 快照表（只存建议快照，不存任务/完成态）；localStorage 只做旧配置兼容，不作为历史存储。
- **对话生成式 UI 与页面共用同一张卡**：`study_plan.advise` 返回 `advice/trace/graph`，`AgentToolResult` 按输出契约渲染。

> 上一轮“零新增计划表”针对的是“计划任务表”；本轮用户明确要求历史 CRUD，因此只新增**一张建议快照表**，不新增任务表、完成表、每日计划表。这是对旧约束的最小修订。

### 0.3 需要用户拍板的实现偏好

| # | 决策 | 推荐 | 备选 | 影响 |
| --- | --- | --- | --- | --- |
| D3 | workspace 旧航线面板 | **降级为一张“打开学习计划”小卡** | 完全移除 | 不影响知识百科编辑，但不再出现第二份计划 |
| D4 | 建议文案由谁写 | **LLM 在锁定事实上写解释，失败回退模板** | 纯规则模板 | LLM 有温度，但必须受事实约束 |
| D5 | 图谱默认显示层 | **默认 topic + bank，资料/笔记/图片/网页按需展开** | 默认全部展开 | 默认图更干净，避免一上来几百个节点 |

## 1. 现状诊断

### 1.1 “读《导数》”任务卡的真实链路

- `StudyPlanPanel.vue:87-105` 的「今天」列表、`:124-133` 的「完整安排」列表，都是 `plan.days[].tasks[]` 的渲染结果。
- `study_plan_service.py:733-756` 返回 `days`、`progress`；任务由 `_tasks_for_stop` 等函数生成，`target.kind` 可为 `page / question / bank`。
- `StudyPlanPanel.vue:517-532` 的 `openTask()` 根据 `target` 跳转到知识页、题库或错题本；`:103-105` 还有「开始今天第一项」。
- `StudyPlanPanel.vue:200-203` 题库抽屉里还有「去练这个题库」「纳入学习计划」。
- 结论：**只要保留 `days[].tasks[]` 和 `openTask`，用户就一定会看到“被安排”的任务卡。** 本轮必须把这条链路整体下线，而不是换文案。

### 1.2 两个入口为什么割裂

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| 学习统计 `plan` tab | `StudyPlanPanel`：设置条 + 今日任务 + `StudyMapGraph` + 完整安排 | 计划是主体，图谱只是配图 |
| workspace 右侧 | `KnowledgeRoutePanel`：航线站点 + 今日任务 + 查看完整计划 | 第二份“今天做什么” |
| workspace 抽屉 | `StudyPlanDrawer`：按天任务 + 开始今日任务 | 第三份任务视图（当前未挂载但代码仍在） |
| `LearningLoopPanel` | 「今日学习任务」+ 开始按钮 | bank tab 里还有一份任务 |
| 资料诊疗室 | 学习处方 | 第三套 LLM 计划（本轮不改逻辑，仅不把它当主计划） |

- `StudyPlanPanel.vue:440-455` 每次加载会 `GET /rag/study-plan` 自动生成；图谱 `GET /rag/study-graph` 是另一条请求。
- 用户读完页/做完题后，`StudyPlanPanel.vue:565-571` 只在关闭页面抽屉时重拉计划；图谱本身不会因为“选择了一个节点”而重新布局或高亮。**“选择—生成—图谱变化”这条链现在不存在。**

### 1.3 图谱能力边界

- `study_graph_service.py:353-490` 只产出 `page` 与 `bank` 两类节点；`knowledge_map_service.py` 能产出 `document / section / note / question / image`，但没有和 wiki 主题页合并。
- `study_graph_service.py:282-305` 的 bank→page 边使用 `target: "page:{id}"`，而 page 节点 `id` 是裸数字字符串（`wiki_service.py:2277-2292`）。**ID 命名不一致，旧图里这条边实际画不出来。**
- 笔记、文档、网页、图片没有进入“学习计划”的图；题库只作为独立方块，无法说明“这道题来自哪份资料/哪个主题”。
- `RagWikiPage.source_doc_ids` / `source_refs` 已经保存主题页的真实资料来源；`RagDocument.source_url` 已能标识网页导入；`ContentReference` 已能把笔记连到文档/主题页；`QuestionSource.question_id -> QuestionMain.bank_id` 已能反查题库。**这些真实关系此前没有被统一使用。**

### 1.4 计划对象与历史

- `study_plan_service.py:523-756` 是确定性、请求期重算、零计划表；`planId` 只是参数哈希。
- 没有历史记录；用户关掉页面后无法找回上一次建议。
- `study_plan` Agent 工具 `study_plan.py:81-262` 只返回 `days/tasks/progress`，没有“建议”对象，也没有可复用的动画轨迹。

### 1.5 旧组件去留矩阵

| 对象 | 结论 | 处理 |
| --- | --- | --- |
| `StudyPlanPanel.vue` | **删除/替换** | 新建 `StudyPlanWorkbench.vue`；旧文件不再挂载，验收后删除 |
| `StudyMapGraph.vue` | **删除/替换** | 新建 `StudyGraphCanvas.vue`（多类型 + 动画） |
| `StudyPlanDrawer.vue` | **保留代码、不挂载** | 历史兼容组件；不再作为计划入口 |
| `KnowledgeRoutePanel.vue` | **降级** | 只显示一张“学习建议已移至学习计划”的小卡 + 跳转 |
| `LearningLoopPanel.vue` | **降级** | 删除「今日学习任务」块与开始按钮，只留统计 |
| `ExamPlanPanel.vue` / `LegacyExamPlanPanel.vue` | **保留** | 旧考前计划只读归档，`?tab=exam` 仍可达；不生成新计划、不复制题库 |
| `KnowledgeMapPanel.vue` | **保留但降级** | 改名「资料结构」，只作为资料详情二级视图，不在计划页/主导航出现；不显示学习建议 |
| `KnowledgeGraphSvgPanel.vue` | **保留但降级** | 改名「实体关系（资料内）」，只作为资料详情二级视图，不显示计划/建议 |
| `KnowledgeWikiPanel.vue` | **保留** | 知识百科编辑器；内部 `知识图谱` 视图只服务资料结构，不改业务逻辑；如需统一命名，只改 1 行文案为「资料结构」 |

## 2. 产品形态与信息架构

### 2.1 唯一入口

学习统计页 `myStats/index.vue` 的 tab 仍为：

`学习计划（默认）/ 题库练习 / 英语练习 / 学习周报`

- `plan` tab 内只挂 `StudyPlanWorkbench.vue`。
- `?tab=exam` 仍落到旧考前计划归档，但不占导航。
- workspace 不再挂载完整计划抽屉；`KnowledgeRoutePanel` 只保留跳转小卡。
- `LearningLoopPanel` 不再显示任务，只显示统计。
- **边界说明**：知识百科页、资料地图保留为“内容层”（回答“这份资料里有什么”），不回答“先学什么”；用户可见的“学习计划”只有一个工作台，不会在两处看到两份计划。

### 2.2 工作台线框

```
┌─ 学习计划 ─────────────────────────────────────────────────────────────┐
│ [资料夹 ▾]  [目标 ▾]  [每天 30 分钟]  [范围：主题/题库/资料/笔记/图片/网页]  [生成建议] │
├──────────────────────────────────────────────┬─────────────────────────┤
│                                              │  建议                    │
│        统一图谱画布（ECharts）                │  先把导数的基础打牢…     │
│        topic / bank / document / note /      │  依据：12 主题 · 6 题库   │
│        image / web                           │  ─ 阶段 1 基础补齐        │
│                                              │    3 个主题 · 约 90 分钟  │
│  选中节点 → 聚焦/高亮 → 详情                  │  ─ 阶段 2 题库验证        │
│  生成时：节点脉冲 / 粒子发射 / 点亮 / 暗淡     │    题库 1293 · 约 40 分钟 │
│                                              │  [更基础] [时间减半]      │
│                                              │  [加入题库] [自定义调整]   │
│                                              │  [保存] [历史]           │
├──────────────────────────────────────────────┴─────────────────────────┤
│ 我的规划：v3 导数补弱 · 14 天   v2 …   v1 …                    [全部]  │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.3 三条核心交互

**（1）选一个起点**
- 点图谱节点，或点顶部「范围」里的资料/题库/笔记/网页/图片。
- 选中后：该节点居中/高亮，1 跳邻居亮起，其他节点降到 30% 左右；右侧显示节点详情，底部出现一个小按钮「以此生成建议」。

**（2）生成建议**
- 顶部点「生成建议」或节点详情点「以此生成建议」。
- 图谱进入动画：读取→遍历→思考→完成（详见第 5 章）。
- 右侧建议面板先显示骨架，再渐入建议；不出现“任务勾选”。

**（3）反复修改**
- 快捷调整：`更基础` / `更进阶` / `时间减半` / `只看错题` / `加入题库` / `换个起点`。
- 自然语言调整：输入“每天只能 20 分钟，先别管题库”，系统重算并生成新版本。
- 每次调整都保留父版本；历史里可对比/查看后继续/重命名/删除。

### 2.4 建议不是任务

`StudyAdvice` 只描述“为什么这样建议、建议先看什么、预计投入多少”，不描述“你今天必须完成什么”。用户不勾选、不打卡、不产生完成态；系统也不会因为用户没做而把建议标红或催促。

### 2.5 相对旧版的四个变化

| 旧 | 新 |
| --- | --- |
| 任务清单：读《xx》、开始、完成 | **图谱上的一条建议路径**：阶段 + 依据 + 替代方案 |
| 静态配图：图谱只是计划的背景 | **可演算的 trace**：真实遍历、点亮、发射、暗淡 |
| 一次性计划：关掉就没了 | **版本化建议**：每次调整留快照，可查看/对比 |
| 页面孤岛：对话里只能文字回复 | **对话生成式 UI**：同一张建议卡 + 同一套动画 |

### 2.6 图谱全屏与简洁模式

- 图谱卡右上角只保留两个小图标：`全屏`、`重置视图`；不放“去读/去练/开始”等实体操作按钮。
- 点击全屏：用浏览器 Fullscreen API 或 fixed 覆盖层把画布铺满视口；全屏内只保留「退出全屏」「重置视图」「生成建议」三个小按钮，右侧建议面板折叠为底部抽屉。
- 节点详情只显示标题、摘要、真实统计，底部最多一个小文字按钮「以此生成建议」；不在节点上堆操作。
- ESC 退出全屏；退出后恢复原来的缩放/选中状态。
- `prefers-reduced-motion` 下全屏动画同样降级。

## 3. 统一图谱模型与六类来源

### 3.1 节点/边 Schema

```json
{
  "id": "topic:123",
  "kind": "topic",
  "title": "导数的定义",
  "subtitle": "知识百科 · 已读 0 次",
  "groupId": "kb:640",
  "source": "wiki",
  "ref": { "pageId": 123, "bankId": 0, "docId": 0, "noteId": 0, "assetKey": "" },
  "metrics": { "degree": 3, "questionCount": 0, "weakCount": 0, "viewCount": 0 },
  "detail": { "summary": "…", "pageType": "concept" },
  "searchText": "导数 定义 极限"
}
```

```json
{
  "id": "e:wiki:12",
  "source": "topic:12",
  "target": "topic:8",
  "kind": "prerequisite",
  "label": "前置",
  "weight": 5,
  "evidence": { "table": "rag_wiki_page_link", "id": 12 }
}
```

节点 ID 统一带命名空间：`topic:`、`bank:`、`doc:`、`note:`、`image:`、`web:`、`section:`、`qgroup:`。**所有边两端必须能在节点集合里找到；找不到就不返回。**

### 3.2 六类来源适配器

| 来源 | 表/字段 | 节点 ID | 标题 | 真实边 |
| --- | --- | --- | --- | --- |
| 知识百科 | `RagWikiPage`（`id/title/summary/page_type/source_doc_ids/source_refs`） | `topic:{pageId}` | `title` | `RagWikiPageLink` → `prerequisite/related/contrast/part_of/mention` |
| 题库 | `QuestionBank`（`id/bank_name/subject`）+ `QuestionMain` + `QuestionSource` | `bank:{bankId}` | `bank_name` | `QuestionSource.question_id → QuestionMain.bank_id`；再经 `doc_id/chunk_id` 反查主题页 → `question_source` |
| 文档 | `RagDocument`（`id/file_name/raw_content/source_url/status`） | `doc:{docId}` | `file_name` | `RagWikiPage.source_doc_ids / source_refs` → `source_doc`；`ContentReference` → `reference` |
| 外部网页 | `RagDocument.source_url IS NOT NULL` | `web:{docId}` | `file_name` 或 URL 域名 | 同文档；另在详情显示原始 URL |
| 笔记 | `Note`（`note_id/title/markdown_content/content`） | `note:{noteId}` | `title` | `ContentReference`（note↔document / note↔wiki_page）→ `reference` |
| 图片 | `RagImageAsset`（按 `doc_id` 聚合；`asset_key/url/caption/ocr_text`） | `image:{docId}` | `caption` 或「N 张图」 | `doc:{docId} → image:{docId}` → `image_source` |

补充：
- `section:{docId}:{index}` 与 `qgroup:{docId}` 只在详情抽屉/聚焦时展开，默认不画，避免图太密。
- 同名 `question_source` 分两层：`bank→topic` 是真实题锚点（来自 `QuestionSource`）；`doc→qgroup` 只是题组计数，默认只在展开时显示，**不能混用两种语义**。
- **实时 `web_search` 结果不进入持久图谱**：它只能作为建议里的临时证据（带 URL），刷新后不假装是图谱节点。
- 无真实关系的节点允许独立存在；图谱会显示“暂无连接”，建议里如实说明“仅基于这份资料本身”。
- 读接口不调用 `sync_image_assets` 等写路径；图片资产直接读 `RagImageAsset`，索引为空就显示空态（避免 GET 产生副作用）。
- **网页来源边界（已确认）**：第一版“网页”= 用户已导入的 `RagDocument.source_url` 文档；实时 `web_search` 结果只作为建议里的临时证据（带 URL、可点击），不写入持久图谱。这样既覆盖“外部网站”，又不会把一次搜索结果伪装成长期知识关系。

### 3.3 图规模与布局

- 默认最多 80 个节点、160 条边；超过时按“与选中节点距离 + 学习权重”截断，并显示「还有 N 个节点」。
- 布局：topic 在内环/中环，bank 在下方弧形，document/note/image/web 在外环；选中节点时以它为中心重排 1-2 跳邻居。
- 节点大小按 degree/题量/字数做 3 档，不按随机数。
- 图数据全部 request-time 聚合，不建图库、不引入 Neo4j。

```json
      "summary": "跳过前置阅读，先用题库 1293 的 10 道薄弱题定位问题。",
      "tradeoff": "可能反复卡在概念上，适合已有基础的人。"
    }
  ],
  "risks": ["题库 1293 没有资料锚点，建议只作为练习验证，不当作知识页依据。"],
  "degraded": { "noPrerequisiteEdges": false, "noAnchoredMapping": true, "llmFallback": false },
  "generatedAt": "2026-11-08 16:30:00"
}
```

**明确禁止字段**：`tasks`、`days`、`status`、`done`、`progress`、`todayTasks`、`manualDone`。出现这些字段即视为方案回退，验收不通过。

### 4.2 事实锁定

1. 后端先算 `facts`：真实节点、真实边、题数、正确率、薄弱题、阅读记录、诊断摘要。
2. LLM 只拿到 `facts` 的紧凑摘要，输出 `title/summary/phases/suggestions/alternatives/risks`。
3. 校验：`suggestions[].nodeId` 必须在节点集合；`phases[].nodeIds` 必须存在；`evidence.edgeId` 必须存在；未知 id 直接丢弃，不补造。
4. LLM 失败/超时/JSON 不合法 → 用模板建议（同样基于 `facts`），`degraded.llmFallback=true`；页面不报错。
5. 建议文案不得出现“你今天必须……”“完成后……”“已为你安排任务”等命令式措辞。

### 4.3 调整

- 请求携带 `parentSnapshotId` + `instruction` + 可选参数（`dailyMinutes`、`horizonDays`、`bankIds`、`sourceTypes`、`seedNodeId`）。
- 快捷 chips 映射为结构化参数；自然语言由 LLM 解析为参数，但仍走同一校验。
- 每次调整生成新 `StudyAdvice` 与新快照；`parent_id` 指向上一版，历史里显示版本线。

## 5. 生成流程与动画

### 5.1 状态机

```
idle
  │ 点击「生成建议」/「以此生成建议」
  ▼
reading（约 400ms）
  · 种子节点外圈脉冲
  · 顶部状态：「正在读取知识图谱」
  ▼
traversing（每步约 550ms，最多 6 步）
  · 源节点：effectScatter 涟漪扩散（发射）
  · 边：lines.effect 粒子沿边移动 + 尾迹
  · 目标节点：scale 1.08 + 光晕，加入 visited
  · 未访问节点：opacity 0.28、去饱和
  · 非路径边：opacity 0.16
  ▼
thinking（LLM 生成中）
  · 图保持点亮状态
  · 顶部状态：「LLM 正在思考」
  · 右侧建议面板骨架 shimmer
  ▼
ready
  · 建议渐入
  · **图谱按 advice.scope / trace 自动更新**：以 seedNodeId 为中心重排，阶段涉及的节点分组高亮，未涉及节点保持暗淡
  · 点空白恢复全图；切换历史版本时按快照 graph 重绘
```

### 5.2 后端 `trace` 契约

```json
{
  "traceId": "tr:4a9e",
  "seedNodeId": "topic:12",
  "steps": [
    {
      "index": 1,
      "from": "topic:12",
      "to": "topic:8",
      "edgeId": "e:wiki:12",
      "kind": "prerequisite",
      "label": "前置",
      "reason": "先理解极限，再学导数",
      "durationMs": 550
    }
  ],
  "visitedNodeIds": ["topic:12", "topic:8", "topic:12"],
  "degraded": { "singleNode": false, "noEdges": false }
}
```

- `trace` 由真实图 BFS/航线顺序生成，**不是前端随机游走**；同一输入可复现。
- 没有真实边时 `steps=[]`，前端只播放种子节点脉冲 + 文案「这个节点暂时没有可信关联」，不伪造发射。
- 最多 6 跳；超过时截断并在建议里说明“还有 N 个关联节点未展开”。

### 5.3 视觉规范（保持现有色调）

| 元素 | 规范 |
| --- | --- |
| 主色 | `#2f5fce` |
| 卡片 | `#ffffff`，边框 `#e8edf5` |
| 正文 | `#253247`，次要 `#7d8596`，弱 `#9aa3b2` |
| 主题节点 | 白底圆 + `#2f5fce` 边；已读 `#e8f0ff`，练习中 `#e6a23c`，已掌握 `#2f9e8f` |
| 题库节点 | 白底圆角矩形 + `#b9a9ef` 边；文字 `#51428e` |
| 文档/网页 | `#8b6bb1` / `#5c8fa8` 小圆点 |
| 笔记/图片 | `#2f9e8f` / `#c47a55` 小方块 |
| 未访问 | opacity .28，轻微去饱和 |
| 已访问 | 2px 主色环 + 柔光；当前节点 1.08 缩放 |
| 按钮 | Element Plus `size="small"`，高 28px，圆角 6px，字号 12px |

### 5.4 性能与降级

- ECharts `scatter` + `effectScatter` + `lines.effect`，不新增依赖。
- 节点 ≤80、边 ≤160；**选中节点、生成完成、切换历史版本**各触发一次布局重算；逐跳动画只改变 opacity/scale/effect 数据，不逐帧重排。
- 生成完成后必须用 `advice.scope.nodeIds` + `trace` 重算布局并聚焦；如果 advice 响应没有 graph，则前端用 `seedNodeId + advice.scope` 重新请求 `GET /rag/study-map` 后再重排，确保“生成→图谱自动更新”是数据闭环，不只是变暗动画。
- `prefers-reduced-motion: reduce`：跳过 `reading/traversing`，直接显示最终高亮和建议；`thinking` 保留 300ms 文案。
- 页面不可见（`document.hidden`）时暂停动画；恢复时从当前步继续。
- 移动端画布高度 300px；右侧建议改为底部抽屉。

## 6. 历史记录与 `study_plan_snapshot`

### 6.1 表结构（唯一新增表）

```sql
CREATE TABLE study_plan_snapshot (
  id            BIGINT PRIMARY KEY,
  user_id       BIGINT NOT NULL,
  kb_id         BIGINT NOT NULL DEFAULT 0,
  title         VARCHAR(160) NOT NULL DEFAULT '',
  scope_json    JSON NOT NULL,
  advice_json   JSON NOT NULL,
  trace_json    JSON NOT NULL,
  graph_json    JSON NOT NULL,
  parent_id     BIGINT NULL,
  source        VARCHAR(16) NOT NULL DEFAULT 'page',
  pinned        SMALLINT NOT NULL DEFAULT 0,
  deleted       SMALLINT NOT NULL DEFAULT 0,
  create_time   DATETIME NOT NULL,
  update_time   DATETIME NULL
);
CREATE INDEX idx_sps_user_created ON study_plan_snapshot(user_id, deleted, create_time);
CREATE INDEX idx_sps_user_kb ON study_plan_snapshot(user_id, kb_id);
```

- 只存“建议快照”，**不存任务、不存完成态、不存每日打卡**。
- 每次成功生成/调整自动保存；每人保留 50 条，超过时删除最旧的未置顶快照。
- `graph_json` 存当次子图（≤80 节点），保证查看历史时看到当时的图，而不是被当前数据改写。
- 权限：所有查询强制 `user_id = 当前用户`；`deleted=1` 为软删除。

## 8. API 契约

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/rag/study-map` | 统一图谱：六类节点 + 真实边 + sourceStats + degraded |
| POST | `/rag/study-plan/trace` | 生成真实遍历轨迹（不发散、不调 LLM） |
| POST | `/rag/study-plan/advice` | 生成/调整建议（LLM 解释 + 模板降级），自动保存快照 |
| POST | `/rag/study-plan/history` | 另存当前建议（可选；生成时已自动保存） |
| GET | `/rag/study-plan/history` | 历史列表 |
| GET | `/rag/study-plan/history/{id}` | 历史详情（含 graph/trace/advice） |
| PATCH | `/rag/study-plan/history/{id}` | 重命名/置顶 |
| DELETE | `/rag/study-plan/history/{id}` | 软删除 |

### 8.1 `GET /rag/study-map`

查询：`kbId`、`bankIds`、`sourceTypes`（逗号分隔）、`seedNodeId`、`depth`、`limit`。

响应：
```json
{
  "nodes": [],
  "edges": [],
  "stats": {
    "topicCount": 12, "bankCount": 6, "documentCount": 8,
    "webCount": 2, "noteCount": 3, "imageCount": 5,
    "edgeCount": 65, "weakQuestionCount": 71
  },
  "sourceStats": [
    {"type": "wiki", "label": "知识百科", "count": 12},
    {"type": "bank", "label": "题库", "count": 6}
  ],
  "degraded": {
    "pagesEmpty": false, "banksEmpty": false,
    "noQuestionSource": true, "noSources": false
  }
}
```

### 8.2 `POST /rag/study-plan/trace`

请求：
```json
{
  "kbId": 640,
  "bankIds": [1293],
  "sourceTypes": ["wiki", "bank"],
  "seedNodeId": "topic:12",
  "goal": "weakness",
  "dailyMinutes": 30,
  "horizonDays": 14
}
```

响应：`{ "trace": {...}, "facts": {...}, "graph": {"nodes": [], "edges": []} }`

### 8.3 `POST /rag/study-plan/advice`

请求：`traceId + 同 trace 参数 + instruction + parentSnapshotId + save=true`。

`traceId` 是输入参数的稳定哈希；服务端用同一组输入重算 trace，不依赖内存缓存，因此刷新/重试也能得到同一条轨迹。

响应：`{ "advice": {...}, "graph": {"nodes": [], "edges": []}, "snapshotId": 123, "saved": true, "degraded": {...} }`。`graph` 是按 advice.scope 更新后的子图；前端收到后直接重排，不再只做视觉高亮。

### 8.4 错误码/降级

- `400` 参数非法（kbId/bankIds/seedNodeId 格式）。
- `404` 节点/快照不属于当前用户。
- `200 + degraded` 图数据为空、LLM 失败、无锚点等；不返回 500。
- 所有接口 `user_id` 从登录态取，不接受前端传入他人 id。

## 13. 风险与砍掉清单

### 13.1 风险

| 风险 | 处理 |
| --- | --- |
| LLM 慢/失败 | 模板建议兜底；页面不转圈超过 20s；thinking 有取消 |
| 图太大/卡顿 | 80 节点上限、按距离截断、ECharts canvas、reduced-motion |
| 无锚点题库被误连 | 只认 `QuestionSource`；没有就独立节点并提示 |
| 笔记/文档权限 | 所有查询 `user_id` 过滤；不读他人资料 |
| LLM 上下文隐私 | 只送标题/摘要/统计，不送笔记全文与原文长段落；引用按需单取 |
| 历史表膨胀 | 每人 50 条，置顶不删，软删除；`graph_json` 不存 searchText/原文 |
| 旧组件删除导致回归 | 先保留文件、只替换挂载；验收后清理 |
| 方案再次变任务化 | 验收硬性检查 `tasks/days/status/progress` 字段不存在 |

### 13.2 本轮明确不做

- 不引入 Neo4j、不建实体图数据库；`knowledge_graph_service` 的实体关系只作为可选证据，不并入主图。
- 不做实时网页搜索入图；只支持已导入网页文档，临时检索只作为建议证据。
- 不做移动端专门布局（仅保证不崩）。
- 不做任务打卡、完成率、学习 streak。
- 不复制题库、不生成 `考前计划·` 新题库。
- 不重写知识百科编辑器、不改 `KnowledgeWikiPanel` 基线。

## 16. 附录：资料诊疗室三页重构（本轮追加）

### 16.1 现状

- `DocumentClinicDialog.vue:42-83` 目前是 3 个 tab：`health`（资料体检）、`anatomy`（原文阅读）、`prescription`（学习处方）。
- 第三页 `StudyPrescriptionPanel.vue` 仍是按天任务 + checkbox + 进度 + 复诊；这正是用户要求删除的“学习处方”形态。
- `DocumentAnatomyPanel.vue` 的原文阅读没有全屏按钮；`workspace/index.vue` 的列表行没有点击打开原文阅读，只在操作列有资料诊疗室按钮。
- `workspace/index.vue:577-613` 另有一套旧的原文阅读弹窗（`kbp-anatomy-dialog`），与本轮统一入口容易混淆。

### 16.2 目标态

`资料诊疗室` 保留一个入口、三个页面：

```
01 资料体检         02 原文阅读              03 智能报告
先看问题            按章节读原文             这份资料可以哪里做得更好
（保留）             [全屏阅读]               [生成智能报告]
```

- **第一页 资料体检**：保留现有 `DocumentHealthPanel` 的评分、问题清单、章节覆盖热力；不改成任务。
- **第二页 原文阅读**：保留 `DocumentAnatomyPanel` 的目录/正文/图片/选中文字操作；工具栏新增一个小的「全屏阅读」按钮，进入全屏后只保留「退出全屏 / 搜索 / 目录」等必要控件。
- **第三页 智能报告**：删除 `StudyPrescriptionPanel` 的按天任务、checkbox、进度、复诊；改为 `DocumentSmartReportPanel`：
  - 顶部：资料名 + 体检总分 + 一句话结论。
  - **更新目标**：直接给出一句“这份资料下一步应该变成什么”，例如“把第 2 章补成讲解—练习—复习闭环”。
  - **可以做得更好的地方**：3-6 条，按 P0/P1/P2 排序，每条含问题、证据章节、建议动作。
  - **建议下一步**：整理/补题/拆章/补图等建议，不产生任务完成态。
  - 可选“导出报告”（第一版可先不做，优先把页面和生成链路跑通）。
