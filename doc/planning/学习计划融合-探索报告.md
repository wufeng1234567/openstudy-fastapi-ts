### A.2 考前计划链路逐层（证据）

- 表单：`examName / examDate / startDate / bankId / restDays / mode(balanced|sprint) / dailyMinutes`（`ExamPlanPanel.vue:8-81,391-399`），`generate()` 调 `getExamPlan`（`:523-567`）。
- 服务端三段式：`foundation → review → sprint`（`exam_plan_service.py:277-288`），比例 `MODE_RATIOS`（`:29-33`），按 `attention_count` 分 `maintenance/micro/standard/intensive` 四档收缩天数（`:441-452,220-224`）。
- 排题只来自 `diagnose()` 的逐题 items，且过滤「题目内容已不可用」占位（`exam_plan_service.py:27,375-380`）；按 `bankId`/`subjects` 过滤（`:399-439`）。
- **写库副作用**：把计划涉及的题按题干去重复制进专属题库，并把 `days[].tasks[].questionId` 改写为复制后的新 id（`:473-492,164-195`）。前端「开始刷题」按钮直接跳该 id（`ExamPlanPanel.vue:189-191,573-579`），`plan-bank-note` 展示题库名（`:151-153`）。
- 快照恢复：刷新/重进页面从 localStorage 恢复 `plan/form/createdAt/manualDone/visibleDays`，并对过期日期做可见兜底（`:365-379,458-479,589-594`）。

### A.3 学习计划链路逐层（证据）

- `GET /rag/study-plan` 参数：`kbId(必填,gt=0) / goal(weakness|foundation|explore|exam|today|sections) / examDate / horizonDays / dailyMinutes / restDays / focusPageId / docId / sectionIndexes / mode / sinceMs`（`rag.py:1196-1206`），docstring `:1210`「只读、零计划表」。
- `build_study_plan` 调 `build_learning_route(max_stops=8)`（`study_plan_service.py:481-488`），再按站点生成 `read/practice/question/review/retest` 任务（`:138-255`）；任务类型与分钟数表在 `:35-53`。
- 无真实 target 的任务不排：阅读只在 `viewCount==0` 时排（`:165-176`）；练习只在 `practice.bankId && questionIds` 时排（`:179-199`）；薄弱题最多 2 道且来自真实诊断（`:201-220`）。
- 按天装箱不拆任务、不补假任务，装不下顺延，`overloaded` 如实提示（`:258-301`）。
- 考前模式（`exam_date` 非空）：补 `retest`（`:236-254`），并把**没有 QuestionSource 页面锚点的错题**按真实 `bankId` 排成「考前薄弱题」伪站点 `pageId=0`，明示「不伪造图谱归属」（`:545-590,570`）。
- `degraded` 显式降级标志：`pagesEmpty / noPracticeData / noQuestionSource / noPrerequisiteEdges / allMastered / noBankForStop / examTooSoon / docFiltered`（`:500-508,614-625`）。
- `GET /userStats/study-plan-today` 是「统计页与知识图谱共用同一份计划的服务端入口」（`user_stats.py:531-535`）：无 `kbId` 时按 `isDefault + docCount` 排序遍历**所有**资料夹逐个 `build_study_plan(goal="today", horizon_days=7, daily_minutes=40)`（`:542-565`）。

### A.4 事实补充：项目里确实存在「第三套由 LLM 排的计划」

与 A.1 两个模块不同，`资料诊疗室 → 学习处方` 由 LLM 生成按天计划：`app/services/ai/prompts.py:84-89,180-190`（`SCENE_STUDY_PRESCRIPTION`、`STUDY_PRESCRIPTION_SYSTEM_PROMPT`），端点 `POST /rag/workspace/documents/{doc_id}/prescription/generate`（`rag.py:936`），`AGENT_MATERIAL_CLINIC_RULES` 说明其「用户可勾选任务、可复诊」（`app/services/ai/prompts.py:871-876`）。这是全项目唯一用 LLM 排计划的链路，且**不在**本次两个模块内；它使「今天该做什么」的来源进一步增多（见 B.1）。

**结论**：严格意义上「今天该做什么」的主计划是 **2 套**（#1 活计划今日任务、#2 考前计划当天任务），彼此没有仲裁、没有互斥、没有共享完成态；加上「旧今日处方」回退（#1 的 fallback）、周报建议、诊断最该练、跨页面重复视图，用户在不同 tab/页面最多可遇到 **5～7 处互相独立或半独立的行动清单**。`user_stats.py:531-535` 声称「不再生成第二套今日处方」，但该断言只对 `bank` tab 内部成立，`exam` tab 仍是第二套。

### B.2 同一道题 / 同一主题页的完成判定是否一致

**不一致，至少三套口径**：

1. 活计划：题目任务看 `user_practice_log.create_time >= sinceMs`；页面任务看 `rag_wiki_page_learning.lastViewTime/lastActivityTime`；**前端勾选不算**（`study_plan_service.py:11-12,304-326,446-450`）。`sinceMs` 缺省为今天 00:00（`:478`）。
2. 考前计划：题目任务看 `planCreatedAt` 之后该题的 `attempts` 次数（且要求「第 N 次出现要有 N 次作答」，`ExamPlanPanel.vue:302-317`），非题目任务看 `manualDone`（`:316,434-442`），后端 `practice-progress` 明确「概念/模拟卷类任务无法从流水推断，由用户手动勾选」（`user_stats.py:779-781`）。注意题目 id 已被替换成复制题库里的新 id（`exam_plan_service.py:487-492`），因此该计数只对新题 id 成立。
3. workspace 图谱站点状态：`updateMapNodeLearning` 在前端按 `viewCount / practiceCount / accuracy / level` **本地推断** `stop.status = done/current/next/review`（`KnowledgeWikiPanel.vue:1759-1809`，尤其 `:1800-1808`），与服务端 `_apply_progress` 的 `done/current/blocked/next`（`study_plan_service.py:329-388`）不是同一套枚举、也不是同一事实源。`KnowledgeRoutePanel.vue:110-118` 又用 `learning.level` 翻译 `statusText`，三种语义叠在一张卡上。

**同一道题**：在活计划里「计划生成后做过一次」即 done；在考前计划里要「按出现次序累计 N 次」才 done；在 workspace 站点里由「该站所有任务是否 done」间接决定（`study_plan_service.py:368-378`）。**同一主题页**：活计划看 `rag_wiki_page_learning` 的时间戳；workspace 看 `viewCount` 与前端推断的 `masteryScore/level`；考前计划**完全没有页面概念**。

### B.4 死胡同 / 无响应入口

1. **workspace 计划抽屉里的 `question` 类任务点不动**：`StudyPlanDrawer.vue:54,69` 把任务 `emit('open-task')` 给 `KnowledgeWikiPanel.onPlanTask`（`KnowledgeWikiPanel.vue:174`），而该函数只处理 `target.kind==='bank'` 与 `target.pageId`（`:1001-1016`），**没有 `questionId` 分支**。活计划确实会生成 `kind:'question'` 任务（`study_plan_service.py:201-220`），其中「考前薄弱题」伪站点 `pageId=0`、只有 `questionId/bankId`（`:566-590`）。对比统计页 `index.vue:817-837` 的 `onOpenPlanTask` **有** `target.questionId` 分支（跳错题本）。同一份任务在统计页可点、在 workspace 抽屉里无跳转。
2. **考前计划任务点击不定位到题**：`ExamPlanPanel.openTask(_task)` 忽略入参，一律 `openPracticeBank()` 跳整个专属题库（`:569-579`），无法打开当天那道题。

### C.2 页面节点、prerequisite 边、学习态、QuestionSource 反查、题库映射的真实能力

1. **页面节点**：`RagWikiPage`（`wiki.py:38-78`）字段含 `page_type / aliases / summary / content_md / sections[].sourceChunkIds / source_refs / source_doc_ids / source_chunk_ids / entity_ids / status(draft|ready|stale|failed) / version`；`get_wiki_graph()` 返回 `nodes[]{pageId,title,pageType,degree,summary,status,learning}` 与 `edges[]{source,target,type,weight}`、`stats`（`wiki_service.py:2244-2255`；契约见 `doc/planning/知航-星图体验审计与重做方案.md:446`）。`build_learning_route` 只取 `status in [ready, stale]`（`learning_route_service.py:749-759`）。

3. **学习态**：`RagWikiPageLearning` 只存 `view_count / last_view_time`（`wiki.py:106-126`，docstring `:109-110` 明写「练习正确率不在这里复制」）。`level(unread/reading/practicing/mastered) / masteryScore / accuracy / practiceCount` 由 `build_learning_snapshot()` 实时算（`wiki_service.py:73`），经 `_wiki_learning_map()` 批量产出（`:1107-1195`），**不落库、不存掌握度字段**。阅读回流：`openPage()` → `recordWikiPageView()` → `updateMapNodeLearning()`（`KnowledgeWikiPanel.vue:1811-1841`）。

5. **题库映射**：`_wiki_practice_bank()`（`wiki_service.py:1198-1261`）用 `QuestionSource.doc_id IN` **或** `chunk_id IN`（`:1214-1236`）找题，`JOIN QuestionMain/QuestionBank` 过滤 `status='0'`，按题库分组取题数最多者，返回 `bankId/bankName/questionCount/questionIds`（`:1253-1260`）。`questionIds` 被活计划用于完成判定（`study_plan_service.py:179-199,304-317`）。`_task_for_stop` 在有同源题库时给 `practice` 任务，否则给 `ask-agent`「生成练习」（`learning_route_service.py:695-716`）。

## D. 题库侧：用户题库如何与图谱发生真实关联？LLM 能查什么？

### D.1 唯一真实桥梁

```
资料(doc/chunk) ──RagWikiPage.source_doc_ids/source_chunk_ids──> 主题页(图谱节点)
        ▲
        │ QuestionSource(question_id, doc_id, chunk_id, quote, offset)
        │
   QuestionMain(题) ──UserPracticeLog──> 作答/诊断 ──_load_diagnosis_page_signals──> 页面级 weakCount
                    └──_wiki_practice_bank──> 该页同源题库 bankId + questionIds
```

写入侧：`question_manage.py:264-282` 暴露 `source_doc_id / source_quote / source_chunk_id`，`:1350-1383` 的 `_source_params` 归一为 `docId/quote/chunkId/startOffset/endOffset`，`:752,904` 传给 `qws.create_question(source=...)`；`question_write_service.py:272-356` 的 `attach_question_source` 校验文档归属、写入 `QuestionSource`（`:344-356`），且「source 为空 / 只有 docId 没有 quote 也没有 offset 就不写」（`:286,322-323`）。即 **LLM 出题时是可以建立锚点的**，但依赖模型按 schema 传 `sourceDocId + sourceQuote`；`question_manage.py:250-260` 的 `questions[].sourceQuote` 是描述性要求，不是强制字段。

#### G.3.1 补充：旧考前计划「复制题库」的累积污染（代码事实，未连库核实条数）

- **命名与复用规则**：`_create_plan_bank` 以 `考前计划·{exam_name}·{source_bank_name}` 拼题库名（截断 100 字，`exam_plan_service.py:116`），只对 `user_id + bank_name` **精确同名**才复用已有题库（`:117-124`）；否则 `db.add(QuestionBank(...))` 新建并 `flush()`（`:133-144`）。
