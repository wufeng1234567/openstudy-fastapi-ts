# OpenStudy 资料空间 · 产品设计文档

> 版本：v0.1 讨论稿  
> 日期：2026-10-28  
> 范围：知识库系统改造 / 资料上传入口 / 单文档解剖 / 资产复用 / 自动归位  
> 状态：只讨论产品方案，不包含代码实现  
> 核心结论：**不做“文件夹式知识库”，做“文档解剖 → 资产复用 → 自动归位”的资料空间。**

---

## 0. 一页结论

### 0.1 产品定位

> **OpenStudy：把一份资料，拆成可复用的学习资产。**

不是“又一个文件管理器”，也不是“又一个 RAG 问答框”。

用户上传一份自己都看不懂的 Word/PDF/图片，系统先做三件事：

1. **看懂**：拆出标题、正文、公式、表格、图片；
2. **归位**：自动命名、自动分类、自动进入默认资料库；
3. **复用**：把图片/公式/表格插入题目、笔记、讲义，并记录“被用在哪里”。

### 0.2 两个上传入口

| 入口 | 位置 | 默认行为 | 用户成本 |
|---|---|---|---|
| **智能体页面 · 自动收集** | 对话输入框：回形针、拖拽、粘贴图片 | 消息发送时自动存入“我的资料 · 收件箱”，后台解析整理 | 0 步，不打断对话 |
| **资料空间 · 手动上传** | “我的资料”页面：上传按钮、整页拖拽、批量选择 | 默认“智能整理”，也可选“仅保存” | 选文件即可，不需要先选知识库/分类 |

两个入口最终进入**同一套资料模型、同一套解析与整理流水线、同一个默认资料库**，不是两套系统。

### 0.3 演示主线

> **一份烂文档 → 解剖出资产 → 一张图进入题目/笔记 → 自动归位。**

视频不演 RAG 问答，不演长链路，不演模型自由生成。

## 1. 背景与问题

### 1.1 用户真实场景

用户手里经常是这些东西：

- `新建 Microsoft Word 文档 (3).docx`
- `扫描件001.pdf`
- `IMG_2043.jpg`
- `期末 (1).pdf`
- `概率论 (2).docx`

他们的问题不是“没有资料”，而是：

1. **不知道这是什么**：文件名没有信息，打开也未必看得懂；
2. **不知道该放哪**：讲义、试卷、笔记、错题混在一起；
3. **不知道怎么用**：图片、公式、表格散落在文档里，想用到题目/笔记里要重新找、重新截；
4. **整理一次又乱了**：手动建文件夹、改名、归类不可持续。

### 1.2 现有基础

当前系统已经具备一些关键底座，不能重复造：

| 能力 | 现状 |
|---|---|
| 默认知识库 | 每个用户已有 `is_workspace=1` 的默认知识库，上传默认落这里 |
| 文档解析 | `file_parser` 已能抽正文、表格、图片、OMML/LaTeX 公式 |
| 文档图片 | `rag_document.image_map` 已保存文档内图片的 `/profile/...` URL |
| 结构树 | `outline_tree_service` 已能从 Markdown 标题、中文序号、数字序号还原章节树 |
| 文档编排 | `doc_compose_model.Block` 已有 heading/level/paragraph/table/image 等结构 |
| 题目/笔记 | 已有题目管理、笔记管理，题目解析和笔记正文都能存图片 URL |
| 对话附件 | `chat_upload_file` / `chat_upload_image` 已持久化聊天附件 |

### 1.3 真正的缺口

不是“没有知识库”，而是：

- 没有一个**统一的资料视图**把文档、图片、知识库聚合起来；
- 没有**单文档解剖页**让用户看清一份文件里有什么；
- 没有**图片/公式/表格的资产层**和“被用在哪里”的账本；
- 聊天附件和资料空间是两套入口，但没有统一到“同一份资料”；
- 整理动作停留在“改名/移动”，没有落到“复用”。

## 2. 术语

为了避免讨论漂移，先统一叫法：

| 术语 | 含义 |
|---|---|
| **我的资料** | 面向用户的页面名称，所有资料的统一入口 |
| **资料空间** | 产品概念：文档、图片、资产、去向的集合 |
| **资料 / Material** | 用户上传的一份原始文件（Word/PDF/图片） |
| **资产 / Asset** | 从资料中拆出来的图片、公式、表格、页面等内容单元 |
| **知识库** | 后端存储/RAG 容器；用户主界面不强调这个词 |
| **整理** | 解析、识别、命名、打 facet、归位、建立来源关系 |
| **归位** | 把资料放进默认资料库/书架，而不是让用户先选知识库 |
| **facet** | 系统自动推导的分类面：学科、类型、公式数、图片数、表格数等 |
| **用途账本 / asset_usage** | 某张图片/某个资产被哪些题目、笔记、文档使用过 |

## 3. 两个上传入口（本文档重点）

### 3.0 入口总览

| 入口 | 当前页面/路由 | 用户动作 | 默认结果 |
|---|---|---|---|
| 智能体页面 · 自动收集 | `/front/agent/chat` 对话输入框 | 回形针 / 拖拽 / 粘贴图片 | 消息发送时自动进入「我的资料 · 收件箱」，后台整理 |
| 资料空间 · 手动上传 | `/front/workspace`（现知识库页改造为「我的资料」） | 上传按钮 / 整页拖拽 / 批量选择 | 默认「智能整理」，也可「仅保存」 |
| 从题目/笔记选用资料 | 题目编辑器、笔记编辑器 | 选择已有资料/图片 | 这是“选用”，不是第三个上传入口，不产生新资料 |

**MVP 只做前两个上传入口。**  
第三个入口只做“从已有资产中选择”，避免入口分散。

### 3.1 入口 A：智能体页面 · 自动收集

#### 3.1.1 用户动作

在智能体对话页，用户可以通过三种方式带文件：

1. 点输入框左侧的回形针；
2. 从资源管理器把文件拖进对话页；
3. 直接粘贴截图/图片。

现有 `ChatFileUploader` 已支持图片、Word、PDF、Markdown、TXT 等类型。

#### 3.1.2 默认行为：自动收集，但不打断

用户**不需要先选知识库，也不需要选择分类**。

消息发送时：

1. 附件照常随消息进入当前对话；
2. 系统自动把附件保存为一份**资料记录**；
3. 资料进入「我的资料 → 收件箱」，状态为 `已收集 / 待整理`；
4. 后台开始解析、提取图片/公式/表格、推断类型和 facet；
5. 对话页面只出现一条很轻的提示：
   `已存入我的资料 · 整理中`；
6. 不弹窗、不要求确认、不要求命名。

如果用户只是临时用一下，可以在附件卡片上点：

- `仅本次使用`：本次对话可用，但不进入资料库；
- `移出我的资料`：删除刚收集的资料记录，不影响本次对话；
- `查看资料`：跳到资料详情。

#### 3.1.3 为什么默认自动收集

- 用户不需要理解“知识库”；
- 用户在对话里传过的资料，往往后面还会再用；
- 如果每次都要问“是否保存”，就是打扰；
- 文件已经在 `chat_upload_file` 持久化了，自动收集只是把它挂到统一资料视图上。

#### 3.1.4 自动收集的边界

- **消息发送时才正式收集**：用户只是选了文件又删掉，不产生资料记录；
- **同一份文件只存一份**：按内容 hash 去重，已有资料直接建立对话关联；
- **低置信度不阻塞**：分类不准时进入 `待确认`，用户可无视；
- **删除对话不默认删除资料**：避免用户误删；资料详情里显示“来自某次对话”，可手动清理；
- **用户关闭自动收集**：设置里提供开关，默认开启；关闭后聊天附件只做当轮/会话使用。

#### 3.1.5 对智能体的价值

- 当前轮：Agent 可以直接读取附件正文/图片；
- 后续轮：Agent 通过 `chat_file_manage` 按 fileId 取回历史文件；
- 后续新对话：Agent 可以通过资料空间/工作空间找到这份资料；
- 图片：Agent 可以把图片 URL 插入题目解析、笔记、文档编排。

#### 3.1.6 时序

```text
用户选文件 / 拖入 / 粘贴
        ↓
发送消息
        ↓
对话附件落盘（chat_upload_file / chat_upload_image）
        ↓
创建资料记录（origin=chat, conversation_id, message_id）
        ↓
进入「我的资料 / 收件箱」——后台解析
        ↓
生成 facet / 资产 / 推荐名称
        ↓
高置信度：自动归位
低置信度：待确认（不弹窗，只在卡片上显示小点）
```

---

### 3.2 入口 B：资料空间 · 手动上传

#### 3.2.1 用户动作

用户从侧边栏进入「我的资料」，有三种上传方式：

1. 点页面顶部「上传资料」；
2. 把文件/文件夹拖到整页任意位置；
3. 在空状态页点「把资料拖进来」。

#### 3.2.2 上传面板

上传面板不需要选知识库，只给两个模式：

| 模式 | 行为 | 适用 |
|---|---|---|
| **智能整理（默认）** | 解析 + 抽资产 + 推断 facet + 建议名称 + 自动归位 | 大多数用户 |
| **仅保存** | 只保存原文件，不解析、不分类，状态 `未整理` | 用户暂时不想处理 |

可选开关（默认开启）：

- `自动命名`：只对 `新建文档`、`扫描件001` 这类无意义名称生效；
- `自动归位`：进入默认资料库；
- `重复文件`：跳过 / 保留副本（默认跳过并建立关联）。

**不要求用户选学科、类型、知识库。**  
这些由系统推断，用户想改再改。

#### 3.2.3 批量上传

- 支持多选、整页拖拽；
- 右下角出现整理托盘：
  `正在整理 8 个文件…`
- 用户可以直接离开页面，后台继续；
- 完成后一条轻提示：
  `8 个文件已整理，1 个需要确认`
- 点开托盘看「整理报告」：
  - 成功 N
  - 重复 N
  - 无法解析 N
  - 待确认 N

#### 3.2.4 智能整理具体做什么

1. 计算文件 hash，发现重复；
2. 解析正文、标题、表格、图片；
3. 生成 facet：
   - 学科：数学/英语/…
   - 类型：讲义/试卷/笔记/教材
   - 内容：公式数/图片数/表格数/字数
4. 推断标题，生成建议名称；
5. 生成资产（图片、公式、表格）；
6. 归入默认资料库；
7. 生成来源信息：来自哪个文件、第几页/第几个内容块、图几；
8. 低置信度进入 `待确认`。

**不要让 LLM 自由改写正文。**  
整理只做解析、归类、命名、建关系；正文不改。

#### 3.2.5 手动修改

在资料详情/书架卡片上，用户可以：

- 双击改名；
- 修改学科/类型 facet；
- 拖到另一个书架；
- 把孤立图片关联到某份文档；
- 合并重复资料；
- 删除/恢复原名；
- 撤销最近一次整理动作。

第一版只做：改名、改 facet、移动、撤销。  
拆分/合并/版本对比放 P1。

### 3.3 两个入口如何汇合

```text
智能体附件 ─┐
            ├─→ 资料记录（Material）─→ 统一解析/整理流水线 ─→ 我的资料
资料空间上传 ┘
```

统一规则：

| 规则 | 说明 |
|---|---|
| 同一份文件 | 按 hash 去重，保留多个来源（对话/手动） |
| 同一套解析 | 不允许聊天附件和资料空间各自解析一套 |
| 同一个默认库 | 都进入默认资料库，不自动新建知识库 |
| 同一个详情页 | 从对话卡片和书架卡片打开的是同一个解剖页 |
| 同一个用途账本 | 图片被题目/笔记引用时统一记录 |

## 4. 信息架构

### 4.1 页面结构

```text
我的资料
├─ 全部资料（默认）
│  ├─ 书架视图（文档卡片）
│  ├─ 图片墙（图片资产）
│  └─ 待整理 / 收件箱
├─ 资料详情 / 单文档解剖
├─ 图片详情抽屉
├─ 整理托盘 / 整理报告
└─ 专题资料夹（可选，仍属于“我的资料”）
```

### 4.2 顶层导航

- **知识库的迭代升级就是「我的资料」**：不是在旁边新增一个入口，也不是把知识库降级、隐藏或塞进高级设置；
- 用户侧所有可见文案统一使用 **「我的资料」**；单个容器在文案里叫 **「资料夹」**，不再出现「知识库」这个词；
- 原「知识库」页面、侧栏入口、对话页入口、设置里的知识库 tab，全部改名为「我的资料」；
- 现有专题库不删除、不降级，作为“我的资料”里的资料夹保留；
- 从智能体页面点「查看资料」也进入这里；
- 不新增第三个“上传入口”。

> 工程边界：`rag_knowledge_base`、`knowledge_base_manage`、`knowledge_search` 等内部表名/接口名/工具名保持不变，避免破坏既有数据和调用链；本次只统一用户可见文案与页面语义。

### 4.3 首页布局

```text
┌──────────────────────────────────────────────────────┐
│ 我的资料       12 文档 · 38 图片 · 3 待确认          │
│ [上传资料]  [全部] [文档] [图片] [待整理]   [搜索]  │
├──────────────────────────────────────────────────────┤
│ 自动 facet：数学 5 · 理科 8 · 含公式 7 · 含图 15     │
├──────────────────────────────────────────────────────┤
│  书架视图                                            │
│  ┌────────┐ ┌────────┐ ┌────────┐                   │
│  │ 文档卡 │ │ 文档卡 │ │ 文档卡 │                   │
│  └────────┘ └────────┘ └────────┘                   │
```

## 5. 单文档解剖页（核心页面）

### 5.1 入口

- 点击书架中的文档卡；
- 从智能体消息卡点「查看资料」；
- 从图片详情点「查看原文档」。

### 5.2 页面布局

```text
┌────────────────────────────────────────────────────────────┐
│ ← 返回   概率论-第3章-联合分布-讲义    [归位] [导出]      │
│ 96 内容块 · 13 图 · N 公式 · 3 表 · 13,000 字              │
├──────────────┬──────────────────────────┬──────────────────┤
│ 资料结构      │ 原文 / 页面预览           │ 资产轨            │
│              │                          │                  │
│ 第一章        │  [正文块]                 │ [图1] [图2] ...   │
│  1.1 ...      │  [表格]                   │ 来自本文档·图2    │
│  1.2 ...      │  [公式]                   │ [公式卡]          │
│              │                          │ [表格卡]          │
├──────────────┴──────────────────────────┴──────────────────┤
│ [插入题目] [加入笔记] [查看原页] [下载原文件]              │
└────────────────────────────────────────────────────────────┘
```

### 5.3 数据来源

| 区域 | 数据来源 | 注意事项 |
|---|---|---|
| 资料结构 | `outline_tree_service`（标题识别） | 没有标题就显示“无章节”，不要伪造 |
| 内容块 | `file_parser.blocks` | 只有 text/table/image，没有 heading |
| 图片 | `rag_document.image_map` / `ChatUploadImage` | 使用 `/profile/...` URL，不传 base64 |
| 公式 | 正文中的 LaTeX/OMML 统计 | 数字必须真实统计 |
| 表格 | `blocks` 里的 table 块 | 用 headers/rows 渲染，不靠字符串猜 |

### 5.4 统计数字的口径

只允许展示真实可得的数据：

- `内容块数` = `blocks.length`
- `文本字数` = `textContent.length`
- `表格数` = blocks 中 `type=table`
- `图片数` = `image_map` 或 asset 数
- `标题数` = `outline_tree_service.totalHeadings`（如果接口返回）
- `公式数` = 正文公式统计（需定义准确口径）

**不要写：**
- “段落 187”（没有真实段落计数）
- “标题 24”（除非 `outline_tree_service` 真的返回 24）
- DOCX 的“第 3 页”（DOCX 没有页）

### 5.5 资产卡

每张图片/公式/表格卡包含：

- 缩略图/预览
- 类型：图片 / 公式 / 表格
- 来源：
  - PDF：`第 3 页 · 图 2`
  - DOCX：`图 3` / `内容块 12`
  - 独立图片：`孤立图片 · 未关联`
- 状态：`未使用 / 已用于题目 / 已用于笔记`
- 操作：
  - `查看原页`
  - `插入题目`
  - `加入笔记`
  - `复制 URL`（高级）

### 5.6 动作

- **插入题目**：选择目标题库/题目，写入图片 URL，同时写一条 `asset_usage`；
- **加入笔记**：选择笔记，图片进入正文，同时写 `asset_usage`；
- **导出**：复用现有文档编排，导出 Word/PDF；
- **归位**：把资料放入默认资料库，并保存名称/facet。

## 6. 图片资产与用途账本

### 6.1 图片的两种来源

| 来源 | 判定 | 展示 |
|---|---|---|
| 文档内嵌图片 | `material_asset.material_id` 有值 | `来自《概率论》· 图 2` |
| 独立图片 | `material_id` 为空 | `孤立图片`；P1 支持手动关联 |
| 生成图片 | 未来 AI 生成/截图 | 后续扩展 |

### 6.2 用途账本

新增 `asset_usage` 记录：

| 字段 | 说明 |
|---|---|
| `asset_id` | 资产 ID |
| `target_type` | question / note / document |
| `target_id` | 目标 ID |
| `created_at` | 使用时间 |
| `deleted` | 软删除 |

写入点：

- `question_manage`：图片插入题干/选项/解析时；
- `note_manage`：图片插入笔记时；
- `document_compose`：图片进入生成文档时。

**不要用 `LIKE '%/profile/...%'` 扫题目正文。**  
题目正文和 options 是 Text/JSON，反查会全表扫描且不可靠。写入时记账才是正确做法。

### 6.3 用户看到什么

图片卡/图片详情显示：

- `被 1 道题使用`
- `被 1 篇笔记使用`
- 点击可跳到对应题目/笔记。

这是“资产化”最直接的证据，也是视频里最值得拍的一秒。

## 7. 我的资料：书架 / 图片墙 / 待整理

### 7.1 书架视图（默认）

- 文档卡片：封面/文件图标、标题、学科、类型、字数、图数；
- 自动 facet 徽章：`含公式 7` `含图 13` `含表 3`；
- 状态：`已整理 / 待确认 / 仅图片 / 无法解析`；
- 支持按学科、类型、时间分组；
- 点击卡片进入单文档解剖。

### 7.2 图片墙

- 瀑布流；
- 筛选：全部 / 文档内 / 孤立 / 待关联；
- 每张图显示来源角标；
- 点开右侧抽屉：来源、原文档、用途、插入题目/笔记。

### 7.3 待整理

- 所有 `未整理 / 待确认 / 无法解析` 的资料；
- 用户可批量“智能整理”；
- 不需要弹窗，不阻塞。

### 7.4 关系图

**第一版不做跨文档关系图。**

只保留单文档解剖内的“资产小图/资产轨”：文档 → 图片/表格/公式。  
跨文档关系图放 P2，原因是：

- 节点少时稀疏、不好看；
- 节点多时是毛线团；
- 用户真正的问题是“这张图用在哪”，不是“看一张全局二分图”。

## 8. 自动、静默、手动

### 8.1 状态机

```text
已上传 → 解析中 → 已识别 → 待确认 / 已归位
                         └→ 失败
```

| 状态 | 用户看到 | 系统行为 |
|---|---|---|
| 已上传 | 卡片占位 | 落盘、hash |
| 解析中 | 进度点 | 提取文本/表格/图片/公式 |
| 已识别 | facet + 建议名 | 生成资产、推荐归位 |
| 待确认 | 小圆点 | 低置信度，不阻塞 |
| 已归位 | 正常卡片 | 进入默认资料库 |
| 失败 | 错误说明 | 保留原文件，可重试 |

### 8.2 不打扰原则

- 不弹窗；
- 不强制选分类；
- 不要求先建知识库；
- 低置信度不追问，只放“待确认”；
- 用户可以永远不整理，资料仍然可用；
- 完成提示只出现一次，可忽略。

### 8.3 自动命名

只对无意义名称生效：

- `新建文档(3).docx`
- `扫描件001.pdf`
- `IMG_2043.jpg`

建议格式：

`学科-主题-类型`

例：

`数学-概率论-联合分布-讲义`

原名保留在详情页，随时“恢复原名”。

### 8.4 手动操作

MVP 只做：

- 改名；
- 改学科/类型 facet；
- 移动资料；
- 撤销最近一次整理；
- 删除/恢复。

后续再做：合并、拆分、版本对比、批量归类。

## 9. 数据模型（概念）

### 9.1 Material（资料）

| 字段 | 说明 |
|---|---|
| id | 资料 ID |
| user_id | 归属用户 |
| origin | chat / manual / import |
| conversation_id | 来自对话时记录 |
| message_id | 来源消息 |
| chat_file_id | 对应 chat_upload_file |
| kb_id | 归属默认/专题库 |
| original_name | 原始文件名 |
| display_name | 展示名 |
| file_type/file_size | 类型/大小 |
| hash | 去重 |
| status | 状态 |
| created_at | 时间 |

### 9.2 Asset（资产）

| 字段 | 说明 |
|---|---|
| id | 资产 ID |
| material_id | 所属资料；独立图片为空 |
| asset_type | image / formula / table / page |
| page_no | PDF 页码；DOCX 为空 |
| block_index | 内容块序号 |
| asset_index | 文档内第几张图/第几个表 |
| url | `/profile/...` |
| text | 公式源码/表格文本（可选） |
| meta | 尺寸、bbox、来源等 JSON |

### 9.3 AssetUsage（用途）

`asset_id + target_type + target_id`，写入时记账，查询时按 asset_id 聚合。

### 9.4 Facet（自动分类）

`material_id + key + value + confidence + source`：

- key: subject / type / topic / formula_count / image_count / table_count
- source: rule / model / user

### 9.5 与现有表的映射

- 文档：`rag_document` → Material（一对一或包装）
- 文档内图片：`rag_document.image_map` → Asset
- 聊天附件：`chat_upload_file` / `chat_upload_image` → Material/Asset
- 题目/笔记：只存 asset URL + AssetUsage，不复制图片

## 11. 边界与异常

| 场景 | 处理 |
|---|---|
| 重复文件 | hash 去重，保留来源关联 |
| 不支持格式 | 原文件保存，状态“无法解析” |
| 扫描 PDF | 先按页保存图片；无文本就标“仅图片”，不假装解析成功 |
| 独立图片 | 作为资产保存，标“孤立”；P1 再做关联 |
| 超大文件 | 限制大小，后台处理，失败可重试 |
| 删除对话 | 默认不删除资料；资料详情显示来源 |
| 删除资料 | 软删除；资产/用途标记失效，不破坏已引用内容 |
| 权限 | 所有查询/写入按 user_id 隔离 |
| 解析失败 | 保留原文件，不丢数据；可重试 |
| 并发上传 | 按 hash/用户加幂等，避免重复记录 |

## 12. 30 秒视频脚本

> 原则：不依赖 LLM 实时输出；每个数字都是解析器真实统计；不演 RAG。

| 秒 | 画面 | 字幕 |
|---|---|---|
| 0–3 | 一份真实、命名很烂的 DOCX/PDF | “这份资料，学生自己都没看完” |
| 3–7 | 拖入 → 左右分屏：左边原文件，右边解剖面板生长 | “不是预览，是拆解” |
| 7–12 | 展示真实统计：`96 内容块 · 13 图 · N 公式 · 3 表`；图片轨滚动 | “它先看懂这份文件” |
| 12–17 | 点一张图：`来自《概率论》· 图 3`；点“插入题目” | “每张图都知道自己从哪来” |
| 17–22 | 图片进入第 4 题解析；卡片出现“已用于 1 道题” | “更知道它去了哪里” |
| 22–26 | 跳到笔记/题目，图片在正文里 | “图片不是附件，是资产” |
| 26–30 | 归位到书架，自动 facet；收尾 | “把你的资料，变成资产” |

### 12.1 演示文件建议

- 用真实 DOCX（如现有 96 内容块、13 张图的概率论资料）；
- 不用 `标题 24 / 段落 187` 这种无法从当前解析器稳定拿到的数字；
- DOCX 不写页码，写“图 3 / 内容块 12”；
- 如果要页码，另做 PDF 样本，且接受 PDF 公式解析可能不如 DOCX；
- 所有数字由脚本统计后写死到视频里，不要凭感觉。

### 12.2 不做

- 不出现对话气泡；
- 不出现流式回答/spinner；
- 不出现 RAG 问答；
- 不出现全局关系图；
- 不演未实现的拖拽（用“插入题目”按钮）。

## 13. MVP 范围与优先级

### P0（必须做，决定能否演示）

1. 智能体附件自动收集到“我的资料 · 收件箱”；
2. 资料空间手动上传 + 智能整理/仅保存；
3. 默认资料库聚合 + 资料卡片；
4. 单文档解剖页：内容块、图片轨、真实统计；
5. 图片“插入题目/加入笔记” + `asset_usage` 记录；
6. 归位/改名/改 facet/撤销。

### P1（有时间再做）

- 图片墙跨文档筛选；
- 独立图片上传；
- PDF 页码；
- 重复文件分组/版本；
- 批量整理。

### P2（后续路线）

- 跨文档关系图；
- 扫描件 OCR；
- 多模态检索；
- 自动学习计划。

### P0 验收标准

- 从对话上传一份文件，不额外操作，能在“我的资料”看到；
- 从资料空间上传一份文件，能选择“智能整理/仅保存”；
- 同一文件重复上传不产生重复卡片；
- 解剖页显示真实内容块/图片/公式/表格数字；
- 图片插入题目后，图片卡显示“已用于 1 道题”；
- 归位后书架可见，改名/改 facet 可撤销；
- 全流程不依赖 LLM 实时生成内容。

## 14. 风险与必须避开的坑

1. **不要把 `is_workspace` 当创新**：默认知识库已经上线，PPT 里只当底座。
2. **不要伪造 DOCX 页码**：DOCX 没有页概念；只能写图号/内容块。
3. **不要伪造标题/段落数字**：标题数用 `outline_tree_service` 的真实 `totalHeadings`；没有就写“内容块”。
4. **不要说“多模态 RAG”**：当前是图片抽取 + 文本向量 + `【图N】` 弱关联，不是图片向量检索。
5. **不要做全局关系图**：演示噱头，日常无用。
6. **不要做完整审批流**：后台状态 + 轻提示足够。
7. **不要用 LIKE 反查图片用途**：写入时记 `asset_usage`。
8. **不要重复解析**：聊天附件和资料空间必须共用同一套解析/资产层。

- 文档整理只保留「智能整理」（原深度整理）：分阶段生成结构、图片关联、重复/噪声和无关短文剔除建议；

- 删除资料时级联清理该资料的整理计划与旧版整理日志，避免出现指向已删除资料的幽灵记录；整理记录支持逐条删除，删除记录不回退已应用的文档变更；
- 整理记录时间统一按 Asia/Shanghai 展示，避免数据库 UTC 时间直接显示成凌晨；
- 整理支持反复执行；每次以当前文档状态为新的 before，对比上次整理后的状态生成新的差异；
- 「整理记录」展示真实整理计划历史：时间、文档、模式、变更数、状态、查看对比和回退；旧版 `material_organize_log` 记录也会兼容展示；
- 整理先预览再应用；Diff 使用双栏行级差异（红色删除、绿色新增、灰色未变），图片关联按「图N → 题目」展示；所有 AI 生成的变更默认不勾选，需用户逐项确认后才应用；
- 剔除建议直接展示被隐藏的原文片段并默认不勾选；用户只想清理垃圾时，可以只勾选建议、不勾选图片关联等 AI 变更；
- 图片层深整理：无关图片生成带缩略图的剔除建议（点击可放大查看），有明确“第N题”指向但位置错误的图片生成搬运 Diff；应用后真实移动 `【图N】` 标记并重新建立索引；
- 剔除采用 `excluded_ranges` 软剔除，不物理删除原文；可回退并重新建立检索索引；
- 题库类资料在资料结构里按题型整理（单选题/填空题/简答题等，带题数），可点击跳到对应题号；
- 资料支持二次编辑：使用 Tiptap 富文本编辑器，支持标题、加粗、列表、表格、链接和插入图片；保存后重新解析；
- 编辑器以 Markdown 作为存储格式、HTML 作为富文本编辑态并通过 Turndown 双向转换，兼容 Word 文档的继续编辑；
- 支持导出 Markdown（`.md`）和 Word（`.docx`），图片资产尽量随 Word 导出；未保存的编辑内容也可以直接导出；

### 智能整理预览（2026-10-29）

- 只支持单文档：`POST /rag/workspace/organize/preview`，`mode=deep`（智能整理）
- 智能整理分阶段生成结构、图片关联、重复/噪声建议；不再提供快速整理模式
- `MaterialOrganizePlan` 保存预览计划；`apply` 前校验 `baseRevision`，避免预览后文档变化被覆盖
- Diff 双栏行级展示，表格类变更按指标展开为红色删除 / 绿色新增，图片关联和剔除建议均展示具体内容，不显示 Markdown 源
- 剔除采用 `rag_document.excluded_ranges` 软剔除，原始 `raw_content` 和文件不物理删除；可回退并重新分块
- LLM 只允许输出结构化 ops；`material_organize_contract.py` 校验块锁、白名单操作和禁止删除规则
- 单文档解剖正文改用 `LatexRenderer` 渲染数学公式、Markdown 表格和图片资产，并增加「正文与图片」全屏观看；统计图/图表按文档图片资产展示；
- DOCX OMML 转换补上 `m:acc` 上划线/帽线等结构，修复 `P(ĀB̄)` 被解析成 `$A$$B$` 的问题；
- 智能体页发布消息时，文档附件会 fire-and-forget 上传到默认资料夹（不影响本轮对话）。

### 仍需后续打磨

- 自动分类目前是规则命中，不是语义模型；边界样本需要用户手动改 facet；
- 图片自动上传到资料夹仍以 `chat_upload_image` 资产展示为主，不复制成 `rag_document`；
- 真实大规模数据下的整理报告刷新频率和虚拟滚动需要压测；
- PPT 中的自动收集状态提示与视频素材还需单独制作。
