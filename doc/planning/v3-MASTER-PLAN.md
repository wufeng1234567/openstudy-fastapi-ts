### 两处技术路线与原文不同（实测推翻了纸面方案）

1. **PDF 不走 reportlab，也不走 HTML+Edge，而是 DOCX → LibreOffice**

### 复习卷为什么不是"让 AI 生成"

复习卷的内容是**确定的**：哪几道题、什么档位、哪天复习，全部来自
`diagnose()` 的确定性算法。让 AI 再创作一遍只会引入两个问题：
同一个用户两次生成结果不同、以及多几秒延迟。

所以这条路径**完全不经过大模型**，`diagnose → 取题 → 渲染 → 返回二进制流`。

结构：
```
卷首  掌握度分档表（真表格）+ 学科情况表（真表格）
正文  按优先级排的题目（题干复用题库导出的渲染器 → 公式/表格/图片都对）
      选择题不给答案，简答题留 3 行作答空间
卷尾  未来七天复习计划表（真表格）
附页  答案与解析（单独起页，方便只打印正文时裁掉）
```

### 结构树：为什么不认一种标题就够

实测库里 29 份文档，标题形态**有三种**，只认一种会导致大量文档画不出树：

| 形态 | 例子 | 出现在 |
|---|---|---|
| Markdown `#` | `### 3. 所有权` | 434（15 个）、448（8 个）、447（7 个） |
| 中文序号 | `一、基本概念` | 417、431（8 个）、430（7 个） |
| 数字序号 | `1. 变量的可变性` | 417（111 个）、478（36 个） |

三处容易踩错的地方（都已修，并有注释）：

1. **数字序号的层级必须是 `2 + 点数`**，不是 `1 + 点数`。
   写成 `1 +` 时 `1.` 就成了 1 级，和中文序号平级，树彻底变平。
2. **题库型文档要剔除题号**。文档 478（概率论复习题）有 36 条
   `1 ［单选题］`，全被当章节 → 平坦 36 个兄弟节点，毫无结构信息。
   判据：题型标记占比 ≥60% 时整篇剔除。现在它如实返回"无章节"。
3. **根与唯一子节点同名要去重**。文档 447/448/434 第一行就是文档标题，
   树上会多一层纯冗余的包装，让本就不宽的画布再缩一圈。

## 一、我实测到的东西（这是整份规划的地基）

### 1.1 表格：不是"没做"，是"做了一半然后烂在最后一环"

完整链条（每一环我都验证过）：

```
① AI 出题       prompts.py:790-797  提示词明确要求「必须把表格输出成 Markdown 表格」
                                    ↓ 所以模型确实会产出表格
② 落库          question_main       实测：真实题库里有 3 道题带标准 md 表格
                                    (id 1879 / 1884 / 2772，全是概率论分布律表)
                                    ↓
③ 前端展示      latex.ts:434         renderMarkdownWithLatex → 渲成真 <table>
                latex.ts:231/313     还有 normalizePipeTables + normalizeTabTables 两重兜底
                                    ↓ 屏幕上是对的
④ 导出          bank_export_service  ❌ 断了
```

**断在哪，我用真实数据证明了**：

导出了含真实表格的题库 432，翻到第 13 页，第 33 题是这样印出来的：

```
X的分布律如表2-3所示：

| X | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| P | 0.04 | 0.26 | 0.46 | 0.24 |
```

**竖线原样印在纸上。** 这就是你现在能给出去的"可打印、可提交"。

更糟的是 HTML 表格（`<table>`）的情况。我构造了一道题干含 `<table>` 的题走完整导出：

```
Document.tables = 0
段落内容: 'X\\Y01'      ← 单元格全部粘连，连竖线都没有
         '00.10.3'
         '10.20.4'
```

根因（`bank_export_service.py`）：

- `:258` `_RE_BLOCK_END` 只认 `</p>|</div>|</li>|</h1-6>|</tr>`
- `:259` `_RE_TAG = <[^>]+>` **把所有标签无差别剥掉**
- `:383` `split_blocks()` 只产出 `("text", str)` / `("image", src)` 两种块
- 全文 `add_table` / `Table(` / `cellstyles` / `repeatRows` **零命中**

### 1.2 公式：Word 是真能打，PDF 和"行内公式"是重灾区

**先说好消息**：Word 原生 OMML 是真的能跑。

| 导出 | oMath 数 | 图片 | 表格 |
|---|---|---|---|
| 题库 172（概率论） | **87** | **22**（13 张图） | 0 |
| 题库 408（高中数学） | **32** | — | 0 |

87 个原生公式对象，在 Word 里能双击编辑。**这是你真正的技术资产，比你以为的值钱。**

**坏消息有三个，都被我当场拍到了**：

**(a) `$...$` 包裹的行内公式完全没被处理**

`bank_export_service.py:301` 的注释白纸黑字写着：

> 跳过 `$...$` 内部的命令 —— **那些由调用方按行内公式统一处理**

我 grep 了整个文件：**那个"调用方"根本不存在。**

实测题库 408（10 道题含 `$` 公式）导出后：document.xml 里**残留 126 个 `$`**。

实测单题 `$\int_0^1 x^2 dx$` 导出 PDF，抽出的文本是：

```
'$\int_01 x2 dx$ 与求和 $\sum_{i=1}^n i$ 与分式 $\dfrac{a}{b}$'
```

**原文照印，一个符号都没转。**

**(b) `e^{-\lambda}` / `X^{2}` / `C_7^3` / `∫_{0}^{10}` 这类写法识别不了**

`_find_bare_latex()`（`:288`）只认「命令 + 至少一个 `{}` 组」。实测：

| 输入 | 识别出的公式片段 |
|---|---|
| `e^{-\lambda}` | `['\\lambda']` ← 只抓了命令，`^{...}` 留在正文 |
| `C_7^3=35` | **无**（全当纯文本） |
| `Y=X^{2}` | **无** |
| `∫_{0}^{10} 2A dx` | **无** |

结果就是 PDF 里印出这种东西（真实导出，20 页里 23 行）：

```
由P(X=1)=P(X=2)得λ e^{-λ} = (λ2)⁄2λ^2}{2} e^{-λ}，故λ=2
总取法C_7^3=35，恰有2件一等品的取法C_4^2 × C_3^1=6 × 3=18
由密度函数的归一性 ∫_{0}^{10} 2A dx = 20A = 1
```

**你打算拿去讲"打印不走样"的那句话，现在站在反例上。**

**(c) PDF 的公式是 Unicode 近似**

`\dfrac{a}{b}` 印成 `a⁄b`，`\overline{A}` 印成 `‾A`。模块自己在 `:154-160` 承认了：

> 可行的做法只有两种：① 图片公式；② Unicode 近似

## 三、v3 应该做什么：三个交付物

排序依据不是"哪个炫"，是 **"哪个会让评委当场发现你在吹"**。

### D1 · 把导出补齐（P0，这是修 bug 不是做功能）

**为什么排第一**：因为你现在已经在对外说"可打印、可提交"了。**只要评委点一次导出，这句话当场破产。**

三件事：

| # | 做什么 | 改造量 | 验收 |
|---|---|---|---|
| 1.1 | **Markdown 表格 → Word/PDF 真表格** | ~150 行 | `Document(p).tables ≥ 1`，行列数与源表一致 |
| 1.2 | **HTML `<table>` → 真表格** | 同 1.1（共用渲染函数） | 同一个断言 |
| 1.3 | **`$...$` 行内公式 + `e^{-x}`/`C_7^3`/`∫_{0}^{10}` 识别** | ~80 行 | 导出后 document.xml 里 `$` 残留 = 0 |

**这三件做完全部是"修 bug"，一分钱新能力都不多**——但没有它们，后面所有亮点都建在沙子上。

技术上是**确定的**（子代理已实测通过，不是估计）：

- `_add_omml` / `_add_segments` / `_add_run` 都是**段落级**参数，天生能进单元格
- `_docx_add_image` 是唯一用 `doc.add_picture()` 的，改成 `run.add_picture()` 即可进单元格（**已实测成功**）

## 五、我建议你重新考虑的 3 个判断

### 5.1 「同时讨好学生和教师」——这是个错误

三个理由：

1. **叙事会散**。你的 PPT 硬约束是 ≤10 页 / 每页 ≤150 字。
2. **初筛评的是"一句话能不能说清"**。两个群体 = 两句话 = 一句都说不清。
3. **你自己的文档已经定了**：`ITERATION-PLAN.md:140` 把「教师端」标成 **⚪ P3 更远**。

**必须二选一，我建议选教师**，一条理由：

> **学生是终点消费者，教师是分发节点。**
> 教师出卷 → 全班都要用 → 你拿到一个班的数据。
> 学生自己用 → 只有一个用户。
> **评委问"怎么推广"时，教师的答案强一个量级。**

而且：**"可编辑的导出文件"这件事，只有教师真的需要**（学生只要能看清）。你的技术强项正好命中教师。

### 5.2 「别人只能把文件变成聊天框里的文字」——这句话必须删

**它不是事实。** 文档 AI 导出格式化文件早就是基线能力。

评委只要用过任意一个同类产品，这句话当场失效，还会连带怀疑你后面所有数字。

**改成这三条（每条都能当场验证）**：

1. **公式是 Word 原生对象，不是图片** → 现场双击一下
2. **表格是真表格，不是字符画** → 现场改一个单元格
3. **内容来自你自己的 115 道错题，不是 AI 编的** → 点开看题目来源

### 5.3 「绝对亮点」——我建议你别找"一个亮点"

**真实情况**：你的亮点不是某一个功能，是**"一条能被验证的闭环"**。

竞品拆解（子代理查了 10 家，7 家没有原生文档导出能力）：

- NotebookLM：至今**没有 docx 导出**，用户靠复制粘贴

**但这不构成壁垒**——LLM + python-docx 三周就能复刻。真正的差异只在三个地方：

**三条都有，但没有一条被讲出来过。**
