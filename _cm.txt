修用户实测反馈的四个问题：公式露源码、反复报错、PDF 入口缺失、误建题库

用户原话：
  「你自己查看下 这段对话都有什么问题 首先 输出的还是带代码的文字
    而不是被渲染成对应数学符号的文字  然后他反复报错 重试
    然后他说有一个pdf下载入口 我没看到有
    然后我叫他整理一下 他以为成了 题库 自动导入了一个题库给我
    应该需要更智能更合理的提示词改造」

四条都是**根因明确**的缺陷，逐条修。

## 一、工具卡片输出 LaTeX 源码

现象：卡片摘要显示 `P(AB)=P(\overline{A}\overline{B})`，一屏反斜杠。

根因：`AgentToolResult` 的摘要是 `{{ summary }}` 插值，只输出纯文本。
而摘要里经常直接带题目原文 —— 查询/导入题库后回显题干就是这个形态。

同项目里 `AgentToolDetail`（点开「查看详情」那层）早就用
`renderMarkdownWithLatex` 渲染了，但**摘要是另一个位置**，漏了。

修法：摘要改走 `renderMarkdownWithLatex` + v-html。
安全性没问题：该函数对所有非公式文本走 `escapeHtmlText`，
公式由 KaTeX 生成（`throwOnError:false`），不会产出任意 HTML。

实测：5 个 KaTeX 节点、`\overline` 与 `$` 全部消失、卡片高度 98px 正常。

## 二、反复报错重试

现象：整理那份文档时，模型连续自我纠正 2 次，用户全程看着报错。

根因：`source='outline'` 要求 `content` 是 **JSON 字符串**。
但工具参数本身就是 JSON，模型很自然地传**对象**：
`json.loads(str({"title":...}))` 得到 `"{'title': ...}"`（单引号）→ 必定 JSONDecodeError。

要求"在 JSON 里再套一层 JSON 字符串"是反直觉的，模型写错几乎是必然。

修法：加 `_coerce_spec_content()`，四种形态全认：

    ① dict / list          → 直接接受
    ② 纯 JSON 字符串        → json.loads
    ③ ```json 围栏包裹       → 剥围栏后解析
    ④ 单引号 / 尾逗号        → ast.literal_eval 兜底

仍失败且像 Markdown 时**降级按 text 排**，不再报错 ——
用户要的是"一份好看的文档"，outline 与 text 的区别对他没意义。

顺带修了个潜在崩溃：`svc` 原本在 elif 分支里 import，
而前面新加的降级分支先用它 → `UnboundLocalError`。已提到函数顶部。

## 三、PDF 下载入口看不到

现象：模型说"PDF 已生成，可下载"，但产物卡片的下载按钮给的是 **.docx**。

根因：`files` 里 docx 总是先 append、pdf 后 append，
而工具取 `primary = files[0]` —— 恒为 docx，`format` 还硬写成 `"docx"`。

修法：按用户要的格式选主文件：
  · `format='pdf'`  → pdf 当主文件（pdf 生成失败则回退 docx 并带出原因）
  · `format='both'` → pdf 当主文件（那是"最终交付物"形态），docx 另给链接

同时补齐 `docxDownloadUrl` / `docxFileName`，前端两个按钮都有数据。

## 四、「整理一下」被当成导入题库（最影响体验的一条）

现象：用户传一份题目 docx、只说「整理一下」，
系统**自动建了一个题库**并导入 4 道题 —— 用户根本没要求，还得自己去删。

两层根因，都要修：

### ① 提示词里没有"附件 ≠ 入库"这条规则

原来只有"模糊输入要问"，没有覆盖**附件与意图的歧义**。
模型看到题目标题自然会往"题库"上想。

新增规则 13「An attachment does NOT imply "import into a bank"」，
直接给一张动词对照表：

    「整理/排版/美化」        → document_compose（重排）
    「做成 PDF/导出 Word」    → document_compose（出文件）
    「导入题库/录题/建库」    → bank_manage + question_manage（入库）
    「这两份有什么区别」      → document_compare

并明确：**「整理」单独出现就是重排，不是入库**；
入库是写操作，用户没要求就不该做。

### ② 代码里「有附件就注入建库重型规则」

`needs_doc_workflow()` 原来 `if has_attachments: return True`。
于是用户只说「整理一下」，系统却注入了整套「建库/导题/题型编码」规则，
模型顺着这堆规则读，自然把「整理」理解成「导入题库」。

改成三层判断：
  · 有**强导入动词**（导入/导题/建库/录题/入库）→ 注入
  · 有**排版类措辞**（排版/整理/导出/对比/PDF）→ 不注入
  · 只传附件不说话 → 注入（说明用户期待我们从文件里读意图）

关键是区分**名词与动词**：「题目」是名词，题目当然可以被排版，
所以决定意图的是「导入」这个动词，不是「题目」这个词。

实测 15 组措辞全对，包括最容易错的
「整理这些题目，排版成文档」（不注入）vs「把这些题目导入题库」（注入）。
